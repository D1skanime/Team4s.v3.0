# Phase 117 — UI Design Contract

> Visual and interaction contract for Phase 117: Kara-Segment — Zeit-Override je Folge +
> entdoppelte Anzeige. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** 117-RESEARCH.md ist reine Analyse (kein Code gebaut). Dieses UI-SPEC beschreibt
den Vertrag für das in 117-CONTEXT.md D-03 gelockte **Zielmodell** (vollständiges Option B — ein
geteiltes, pro Release-Version zuweisbares Kara + Per-Version-Zeit-Offset + entdoppelte Anzeige),
nicht für die heutige Per-Datensatz-Duplizierung. Konkrete Feldnamen/Endpunkte sind Sache des
Planners/Executors; dieses Dokument bindet nur das *sichtbare Verhalten* verbindlich.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Projekt nutzt eine eigene, projekteigene Primitive-Bibliothek unter `@/components/ui` (kein shadcn, kein `components.json` im Repo gefunden) |
| Preset | nicht zutreffend |
| Component library | project-owned (`frontend/src/components/ui/`), kein Radix/Base-UI-Unterbau |
| Icon library | `lucide-react` (bereits in `SegmenteTab.tsx`, `ThemeTimeline.tsx` verwendet) |
| Font | `Inter` über `--font-sans` (Fallback `"Segoe UI", system-ui, sans-serif`, `frontend/src/styles/globals.css:2`) |

**Pflicht-Constraint (CLAUDE.md, UI-Checker-Gate):** Jede in dieser Phase neu gebaute UI MUSS die
Primitives aus `@/components/ui` verwenden (`Button`, `Select`, `FormField`, `Input`, `Switch`,
`Badge`, `DisclosureIndicator`, `Table`/`TableBody`/`TableRow`/`TableCell`, `Card`,
`SectionHeader`). Handgebaute native `<select>/<input>/<button>` für einen Primitiv-Typ, den
`@/components/ui` bereits anbietet, sind verboten — auch wenn `SegmentEditPanel.tsx` /
`SegmenteTab.tsx` aktuell an mehreren Stellen native `<input>`/`<select>`/`<button>` verwenden
(vorbestehende Abweichung, nicht Teil dieser Phase). Für **alle in diesem Dokument neu
spezifizierten Elemente** (Override-Eingabe, Entdopplungs-/Zuweisungs-Indikator) gilt die
Primitive-Pflicht ohne Ausnahme; `SegmenteTab.tsx` nutzt bereits `Table`/`TableBody`/`TableHead`/
`TableRow`/`TableCell`/`TableHeaderCell` aus `@/components/ui` (`SegmenteTab.tsx:30-37`) — dieses
Muster fortsetzen.

## Surface Contracts

### Surface 1 — Admin: Per-Folge Zeit-Override-Eingabe

**Ort:** `frontend/src/app/admin/episode-versions/[versionId]/edit/SegmentEditPanel.tsx`
(Seitenpanel), aufgerufen aus `SegmenteTab.tsx`.

**Sichtbarkeitsbedingung:** Der Override-Block erscheint **nur**, wenn das gerade bearbeitete
Segment ein geteiltes/zugewiesenes Kara ist (d. h. mehr als eine Folge/Release-Version zugeordnet
hat — konkretes Feld liefert die Planungsphase, z. B. `assigned_release_version_ids.length > 1`
oder ein `is_shared`-Flag). Bei einem Segment, das nur einer einzigen Folge zugeordnet ist, bleibt
das Formular exakt wie heute (kein Override-Block, „Start"/„Ende" sind direkt die einzige Zeit).

**Layout (innerhalb des bestehenden Panels, unterhalb des bestehenden „Zeitbereich im
Video"-Blocks):**

1. Bestehender Block „Zeitbereich im Video" (Start/Ende) wird bei geteilten Kara-Segmenten
   umbenannt zu **„Basis-Zeitbereich (gilt für alle zugewiesenen Folgen)"** — visuell identisch zu
   heute (zwei `Input`-Felder in einer Reihe via `FormField`), nur der Label-/Hinweistext ändert
   sich, um klarzustellen, dass diese Zeit für den gesamten geteilten Bereich gilt.
2. Neuer Block, sichtbar nur wenn im Panel-Kontext eine konkrete Folge geöffnet ist (also aus dem
   Editor-Kontext von `episode-versions/[versionId]/edit` heraus, wo `episodeNumber` bekannt ist):
   - `Switch` (`@/components/ui`) mit `label="Zeit nur für diese Folge abweichend setzen"`,
     `checked` = ob für diese Folge bereits ein Override existiert.
   - Wenn `checked`: zwei `Input`-Felder in `FormField`-Wrappern, Labels „Start (Folge {N})" /
     „Ende (Folge {N})", vorausgefüllt mit dem aktuell wirksamen Wert für diese Folge (Override
     falls vorhanden, sonst Basis-Zeit als Startpunkt zum Anpassen).
   - `FormField`-`hint`: „Diese Zeit gilt nur für Folge {N}. Das Kara selbst bleibt unverändert und
     wird nicht neu kodiert — nur die Vorschau wird neu vorbereitet."
   - Wenn `checked` und bereits ein Override existiert: zusätzlicher `Button variant="secondary"`
     mit Label „Override entfernen" unterhalb der Felder, löst den `window.confirm`-Bestätigungstext
     aus der Copywriting-Tabelle aus und setzt bei Bestätigung `checked` zurück auf `false`.

**Validierung:** identisch zur bestehenden `validateSegmentTimes`-Logik — Start < Ende, maximal
4-Minuten-Fenster (`maxSegmentWindowSeconds = 240`), Laufzeit-Obergrenze aus
`effectiveDuration`/`playback_duration_seconds`. Fehlermeldungen erscheinen als `FormField`-`error`
direkt unter den Override-Feldern, mit denselben deutschen Strings wie im Basis-Zeit-Block (siehe
Copywriting-Tabelle).

**Explizite Bestätigung (Data-Ownership-Constraint):** Der Override wird **niemals automatisch**
übernommen. Er wird ausschließlich beim expliziten Klick auf den bestehenden „Speichern"-Button im
Panel persistiert — derselbe Button, dieselbe Bestätigungskette wie beim Basis-Zeitbereich. Kein
separater impliziter Auto-Save, kein „Übernehmen beim Verlassen des Feldes" außer der bereits
bestehenden Sekunden-Normalisierung (`onBlur`-Formatierung, unverändert übernommen).

**Primitive-Pflicht:** `Switch`, `FormField`, `Input`, `Button` aus `@/components/ui` — keine
neuen nativen `<input type="checkbox">` oder Freihand-Toggle-Buttons.

### Surface 2 — Admin: Entdopplungs-/„geteiltes Segment"-Indikator

**Ort:** `frontend/src/app/admin/episode-versions/[versionId]/edit/SegmenteTab.tsx`
(Tabellen-/Toolbar-Bereich).

**Grundregel:** Ein geteiltes Kara erscheint in der Tabelle **genau einmal** (nicht mehr einmal
pro Folge, wie heute faktisch der Fall). Die Zeile repräsentiert das Kara als Ganzes, nicht eine
einzelne Folgen-Zuordnung.

**Neue Spalte/Zelle „Zuweisung":** Zwischen der bestehenden Spalte „Episoden" und „Zeitbereich"
(oder als Ergänzung der bestehenden „Episoden"-Spalte, falls das Backend Bereich + Zuweisung im
selben Feld liefert):

- Für ein Kara, das mehreren Folgen zugewiesen ist: `Badge variant="info"` mit Text „Geteiltes
  Segment", direkt gefolgt vom bestehenden Bereichstext (`formatEpisodeRange`, z. B. „Episode
  1–12").
- Für ein Kara mit genau einer zugewiesenen Folge: keine Badge, nur der Bereichstext wie heute
  (kein optisches Rauschen für den unveränderten Standardfall).
- Wenn **mindestens eine** der zugewiesenen Folgen einen Zeit-Override hat: zusätzliches
  `Badge variant="warning"` mit Text „Zeit hier überschrieben" direkt neben dem
  „Geteiltes Segment"-Badge.

**Zuweisungsliste (Detail-Ansicht):** Ein `DisclosureIndicator` (`variant="button"`, `size="sm"`)
am Zeilenende (oder in der neuen Zuweisungszelle) öffnet/schließt eine kompakte Liste aller
zugewiesenen Folgen als `Badge`-Chips innerhalb derselben Tabellenzeile bzw. einer ausklappbaren
Unterzeile:

- Chip pro zugewiesener Folge: `Badge variant="neutral"` mit Text „Folge {N}".
- Chip für eine Folge mit aktivem Override: `Badge variant="warning"` mit Text „Folge {N} · Zeit
  angepasst" statt „Folge {N}".
- Die aktuell im Editor geöffnete Folge (`episodeNumber`-Prop) wird durch `Badge variant="info"`
  statt `variant="neutral"`/`variant="warning"` optisch hervorgehoben (Accent-Nutzung, konsistent
  mit der bestehenden `isSegmentActiveForEpisode`-Hervorhebung, `SegmenteTab.tsx:574-578`).

**Primitive-Pflicht:** `Badge`, `DisclosureIndicator` aus `@/components/ui` für alle neuen Anzeige-
Elemente dieser Surface. Die bestehende `Table`/`TableRow`/`TableCell`-Struktur bleibt unverändert
strukturell erhalten.

### Surface 3 — Öffentlich: Timeline-Entdopplung

**Ort:**
`frontend/src/app/anime/[id]/group/[groupId]/releases/[releaseVersionId]/ThemeTimeline.tsx`
(Rendering), gespeist aus `releaseDetailPageData.tsx` → Backend-Read (`loadReleaseSegments`).

**Grundregel (D-02):** Die Entdopplungs-Entscheidung passiert **serverseitig vor** der Übergabe an
`ThemeTimeline`. `ThemeTimeline` selbst bekommt bereits ein bereinigtes `PublicReleaseSegment[]`-
Array — ein Kara erscheint nur auf der Release-Detailseite der Folge, auf der sein Geltungsbereich
**beginnt**, oder auf einer Folge, wo ein **echter** Segment-Wechsel stattfindet. Eine Folge, die
nur eine Zeit-Override hat (aber inhaltlich dasselbe Kara), zeigt **keinen** eigenen Timeline-
Eintrag — Playback auf dieser Folge nutzt intern trotzdem die für diese Folge aufgelöste (ggf.
überschriebene) Zeit, ohne dass das in der sichtbaren Liste als neuer Eintrag erscheint.

**Visueller Zusatz auf der Span-Start-Folge:** Wenn das Kara über die aktuelle Folge hinaus für
weitere Folgen desselben Projekts gilt, erhält die bestehende `SegmentDetails`-Kartenansicht
(`ThemeTimeline.tsx:142-162`) eine zusätzliche Zeile unterhalb der bestehenden Zeitangabe
(`styles.timeRow`):

- `Badge variant="muted"` mit Text „Gilt auch für Folge {von}–{bis}" (nur gerendert, wenn das
  Backend eine entsprechende Spannen-Information mitliefert, z. B. ein zusätzliches Feld
  `applies_through_episode`/`shared_episode_range` am `PublicReleaseSegment`-DTO — konkretes
  Feld ist Sache der Planungsphase).
- Erscheint **nicht**, wenn das Kara nur dieser einen Folge zugeordnet ist (kein zusätzliches
  visuelles Rauschen im unveränderten Standardfall).
- Erscheint **nicht** erneut auf Folgeepisoden — genau diese eine Zeile auf der Start-Folge
  informiert den Zuschauer, warum das Kara auf den nächsten Folgen nicht wieder auftaucht.

**Kein neues interaktives Element nötig:** Play-Button, Login-Hinweis, Auswahl-Verhalten
(`SelectionSurface`, `playSegment`) bleiben unverändert. Die Entdopplung ist eine reine Lese-
/Darstellungs-Änderung, keine neue Interaktion.

**Edge Case (aus 117-RESEARCH.md „Open Questions"):** Fehlt die Vorfolge (Anime-Anfang, Lücke in
der Episodenfolge), gilt die aktuelle Folge automatisch als Span-Start — das Kara wird angezeigt,
kein Sonderfall in der UI nötig, da dies dem heutigen Verhalten für einzelne, nicht geteilte
Segmente entspricht.

**Primitive-Pflicht:** `Badge` aus `@/components/ui` für den neuen Spannen-Hinweis — `Badge` wird
bereits in `ThemeTimeline.tsx:149` (`typeBadge`) und `ThemeTimeline.tsx:381`
(`Button variant="secondary"`) verwendet, dieses Muster fortsetzen.
