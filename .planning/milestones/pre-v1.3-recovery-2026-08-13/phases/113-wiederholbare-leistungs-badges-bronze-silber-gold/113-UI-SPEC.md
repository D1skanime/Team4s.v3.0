# Phase 113 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Reuse, not redesign.** Diese Phase erfindet KEINE neue Fläche. Sie hängt drei abgeleitete
Bronze/Silber/Gold-Familien als neue Gruppe „Beiträge" in die bereits gebaute
„Auszeichnungen"-Sektion (`MemberBadgeChain.tsx`, Phase 110/112). Alle Spacing-, Typografie- und
Farb-Token sind aus `MemberBadgeChain.module.css` und `memberBadgeLabels.ts` geerbt — diese Phase
führt **keine neuen CSS-Regeln und keinen neuen visuellen Primitiv** ein. Der Contract legt nur die
genuin offenen Entscheidungen fest: Badge-Codes, deutsche Labels pro Familie+Stufe, Icon-/
Palette-Zuordnung pro Bronze/Silber/Gold, Gruppen-Header und Leer-/Fehlerverhalten.

## Spacing Scale

Kanonische Skala (Vielfache von 4). Diese Phase fügt **keine neuen Spacing-Token** hinzu — alle
Chips reihen sich in die bestehende `.chain`/`.badgeRow`/`.badgeItem`-Geometrie ein.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | `.group`-gap, `.badgeRow`-gap, Badge-Innenabstand |
| md | 16px | Default element spacing |
| lg | 24px | `.groupList`-gap zwischen Auszeichnungs-Gruppen |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions (geerbt aus `MemberBadgeChain.module.css`, NICHT neu für Phase 113):
- Chip-Abstand innerhalb einer Zeile `.chain gap: 12px`.
- Sektions-/Card-gap `14px`.
- Badge-Innenpolster `8px 11px 8px 8px` (`11px` ist Bestand).
- **Touch-Target:** `.badgeItem min-height: 44px` — bewusste Ausnahme für Fingertauglichkeit.

## Color

Farben ausschließlich über bestehende CSS-Variablen und das `data-palette`-Attribut. Die
„10%"-Akzentfläche ist die **Tier-Akzentfarbe** (`--badge-accent`) pro Chip. Kein neuer Hex-Wert.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface-card` / `--surface-card-muted` | Chip-Hintergrund, Sektionsfläche |
| Secondary (30%) | `--text-secondary` | Gruppen-Titel, Meta, gesperrter/neutraler Rahmen |
| Accent (10%) | `--badge-accent` (tier-abhängig, s. u.) | NUR Chip-Icon-Fill, Chip-Rahmen, Chip-Gradient |
| Destructive | — | keine destruktive Aktion in dieser Phase |

Accent reserved for: Badge-Icon-Fill und Chip-Rahmen/-Gradient eines **erreichten** Tier-Chips. Kein
weiteres Element nutzt die Akzentfarbe.

**Tier → Palette-Token (Pflichtzuordnung, konsistent mit `role_volume_*` Phase 112):**

| Tier | `palette` | `variant` | `--badge-accent` (bestehende CSS-Regel) |
|------|-----------|-----------|------------------------------------------|
| Bronze | `bronze` | `muted` | `color-mix(in srgb, var(--color-warning) 55%, var(--text-secondary) 45%)` |
| Silber | `silver` | `neutral` | `var(--text-secondary)` |
| Gold | `gold` | `warning` | `var(--color-warning)` |

Kein `platinum`-Tier in dieser Phase (Familien enden bei Gold).

## Copywriting Contract

Die eigentliche Copywriting-Leistung dieser Phase sind das Gruppen-Label und die 9 Chip-Labels
(Deutsch, korrekte Umlaute — CLAUDE.md-Pflicht). Es gibt **keinen CTA und keine Formularflächen**.

| Element | Copy |
|---------|------|
| Primary CTA | Keine — passive Anzeigefläche (read-only Projektion, keine Aktion) |
| Empty state heading | Keine — die Gruppe „Beiträge" wird ausgeblendet, wenn keine Familie Bronze erreicht (`buildMemberBadgeGroups` filtert leere Gruppen). Kein Platzhalter-/Locked-Chip (earned-only). |
| Empty state body | Keine (Gruppe erscheint erst ab ≥1 erreichter Familie) |
| Error state | Keine neue Fehlerfläche — Badges sind Teil des bestehenden Profil-Reads; bei Profil-Fehler greift die vorhandene Profil-Fehlerbehandlung |
| Destructive confirmation | Keine destruktive Aktion in dieser Phase |

**Schwellen (aus CONTEXT, für Label-Aussage — Zähllogik ist Backend):**
- Familie 1 „Mitgetragene Projekte": Bronze 1 / Silber 5 / Gold 15 (durchgängig mitgetragene Projekte).
- Familie 2 „Chronist": Bronze 10 / Silber 50 / Gold 150 (veröffentlichte Notiz-/Text-Beiträge).
- Familie 3 „Bildarchivar": Bronze 10 / Silber 50 / Gold 150 (beigetragene Bilder gesamt).

**Optionaler Schwellen-Hinweis (nice-to-have, nicht Pflicht):** Ein `title`/`aria`-Hinweis am Chip
darf die Schwelle nennen (z. B. „Gold: 150+ beigetragene Bilder"). Das sichtbare Label bleibt
`{Familie} · {Tierwort}`, damit die Zeile nicht überladen wird.

### Interaktions- & Anzeige-Regeln (verbindlich)

- **Nur höchste erreichte Stufe pro Familie** → pro Familie genau EINE Zeile / EIN Chip in der
  Gruppe „Beiträge" (kein B→S→G-Kettenlauf). Kein `roleCode`-Merge (das ist roles-only).
- **Earned-only, kein Locked-Chip:** Die 9 Codes stehen bewusst NICHT im
  `PUBLIC_MEMBER_BADGE_CATALOG` (Muster wie `point_milestone_*`). Sie erscheinen ausschließlich
  über den `catalogWithEarnedBadges`-Fallback, wenn erreicht — nie als graues Schloss-Chip.
- **Kein Sichtbarkeits-Toggle** (D-05): Rendern NUR in der öffentlichen `MemberBadgeChain`
  (`members/[slug]`). NICHT in `/me`-`AchievementBadgesCard` (Toggle-UI für persistierte
  `member_badges`) einblenden.
- **Live-Downgrade:** Da earned-only und read-time abgeleitet, verschwindet ein Chip automatisch,
  wenn die Backend-Stufe zurückfällt — kein UI-State nötig.
- **Gruppe leer = Gruppe verborgen:** Erreicht keine Familie Bronze, fehlt der „Beiträge"-Header
  komplett (bestehendes `.filter(rows.length > 0)`-Verhalten).
