# Phase 107.1 — UI Design Contract

> Visual and interaction contract for the release review workspace and release contribution lifecycle. Generated by gsd-ui-researcher, pending verification by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Team4s global UI system; no shadcn |
| Preset | not applicable |
| Component library | Project-owned React components in `frontend/src/components/ui` |
| Icon library | Existing project icon set only; do not introduce another library |
| Font | `Inter, "Segoe UI", system-ui, sans-serif` |

Source: `docs/frontend/ui-system.md`, `frontend/src/styles/globals.css`, and Phase 107.1 `CONTEXT.md`. Reuse `Table`, `Toolbar`, `SectionHeader`, `Button`, `Badge`, `Select`, `Input`, `Modal`, `LoadingState`, `ErrorState`, and `TableEmptyState`. Use `RichTextRenderer` for text review and the existing release-version media/original-view components for image review. No new uploader, review-editor copy, or domain-neutral component is part of this phase.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge/icon gaps and dense metadata |
| sm | 8px | Compact table-cell and filter-control gaps |
| md | 16px | Default control groups and review-detail blocks |
| lg | 24px | Section padding and toolbar-to-table gap |
| xl | 32px | Major detail-page regions |
| 2xl | 48px | Page-level separation |
| 3xl | 64px | Reserved for major shell spacing; not inside the compact queue |

Exceptions: existing `12px` project token may remain inside established global components; interactive controls are at least `44px` high (`--control-height-md`) and icon-only targets are at least `44 × 44px`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / metadata | 14px | 600 | 1.4 |
| Body / table content | 16px | 400 | 1.5 |
| Section heading | 20px | 600 | 1.2 |
| Page heading | 28px | 600 | 1.2 |

Exactly two weights are permitted: `400` and `600`. Queue rows remain body-sized; counters and statuses must not create a second oversized display hierarchy.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f6f4ef` (`--surface-canvas`) | Page background and breathing space |
| Secondary (30%) | `#ffffff` / `#fbfaf8` (`--surface-card`, `--surface-card-muted`) | Toolbar, table wrapper, review content, modal |
| Accent (10%) | `#5f84dd` (`--color-primary`) | Active `Offen` view, primary `Bestätigen` action, links, selected filter/focus affordances |
| Destructive | `#82122c` (`--button-danger-start`) | `Ablehnen` action and rejection confirmation only |

Accent reserved for: the active queue view, primary confirmation action, selected filter state, navigation links, and accessible focus indication. Status badges use existing semantic badge variants: `warning` for `In Prüfung`, `success` for `Bestätigt/Öffentlich`, `danger` for `Abgelehnt`, and `muted` for cleaned-up history. Do not encode state by color alone; every badge includes text.

## Information Architecture

### Group queue

- Canonical route: `/admin/fansubs/[groupId]/edit?tab=pruefungen`.
- Legacy `tab=vorschlaege` resolves to `tab=pruefungen` without rendering a second tab or duplicated state.
- `Prüfungen` is a secondary workspace tab. Within it, use a compact two-option view control: `Offen` (default) and `Verlauf`.
- Header: `SectionHeader` title `Prüfungen`, one-sentence description, then type counters. Counter order is `Texte`, `Bilder`, `Mitwirkungen`; `Mitwirkungen` may show zero but is not wired to a Phase-108 source here.
- Toolbar order: project/anime combobox, episode/release combobox, type select, conditional image-category select, search field, `Filter zurücksetzen`. Controls wrap to a second line on narrow tablet widths without horizontal page scrolling.
- Table columns on widths at least `1200px`: `Eingegangen`, `Projekt`, `Episode / Release`, `Typ`, `Kategorie`, `Einreicher`, `Aktion`.
- At `768–1199px`, combine `Projekt` and `Episode / Release` into one two-line context cell; hide the standalone `Kategorie` column and append the category badge in `Typ`. Never hide time, submitter, or action.
- Rows are ordered oldest first by a stable server sort; filter or view changes reset the cursor. Initial and subsequent page size is `50`.
- Use a bounded vertical list region with sticky header. Append the next cursor page when the user activates `Weitere Prüfungen laden` or reaches the guarded near-end trigger. Never render an unbounded group history into the DOM.

### Review detail

- Canonical route: `/admin/fansubs/[groupId]/reviews/[reviewId]`; this is a full read-only page, not a drawer.
- Top line: back link `Zurück zur Prüfliste`, page heading `Prüfung`, and a status badge.
- Context is a compact label/value definition grid: project/anime, episode, release/version, submitter, received/last-activity time, type, and image category where applicable.
- Main content is the dominant region. Text uses `RichTextRenderer`; images use the existing responsive preview plus `Original öffnen`. Do not render editable-looking disabled fields.
- Decision area follows the content. `Bestätigen und veröffentlichen` is the sole primary action; `Ablehnen` opens the rejection modal. There is no bulk action and no optimistic “success” before the server transaction completes.
- A link to the release-version edit route is rendered only when the API reports the user already has that edit capability. Review access itself must not cause the link to appear.
- After a successful decision, replace decision controls with a success state and the actions `Nächste offene Prüfung` and `Zurück zur Prüfliste`. If no next item exists, omit the first action.

### Submitter lifecycle on the release-version edit page

- Keep the existing notes editor and release-version media upload flow. Remove reviewer/publication selectors from submitter controls.
- After save/upload, show `In Prüfung` next to the submitter’s own item with last activity time.
- For an own rejected item, show `Abgelehnt`, the structured reason label, the reviewer’s explanation, and the actions `Bearbeiten` and `Erneut einreichen`. Resubmission reuses the same item identity; the UI must not suggest “create a new contribution”.
- For an own confirmed item, show `Bestätigt` / `Öffentlich` and no review action.
- Other people’s open submissions are absent unless the current user has the matching review capability.

## Interaction Contracts

### Filters, loading, and race safety

- Search is submitted explicitly or after a `300ms` debounce; trim whitespace. All filters are URL-backed within the `pruefungen` tab so returning from a detail page restores the working set.
- Dependent release options clear when project/anime changes. Image category is enabled only when type is `Bilder`; selecting another type clears it.
- Initial load uses a table-scoped loading state. Incremental load uses one footer row and preserves existing rows. A page-load error affects only that page and provides `Erneut versuchen`.
- Each request is keyed by group, view, filters, search, and cursor. Abort or ignore stale responses. Deduplicate appended rows by stable review ID.
- Counter updates after decisions use the authoritative response/refetch. Never decrement below zero and never let a stale request restore a decided row.

### Confirmation

- Activating `Bestätigen und veröffentlichen` disables both decision actions and shows loading on the primary button until the atomic response returns.
- Confirmation does not require a second modal for a normal reviewer because the button copy states the publication consequence.
- On transaction failure, retain the open/private detail and restore both actions. No success toast or local row removal is allowed.

### Rejection

- Rejection opens the existing global `Modal`.
- Required category select labels: `Inhaltlich falsch`, `Falscher Release-Kontext`, `Qualität unzureichend`, `Quelle oder Rechte unklar`, `Sonstiger Grund`.
- Required textarea label: `Begründung`; hint: `Beschreibe konkret, was vor der Neueinreichung geändert werden muss.` Minimum non-whitespace length is `10`, maximum `1000` characters, with remaining-character feedback near the limit.
- Modal actions: `Abbrechen` and danger action `Beitrag ablehnen`. Inline validation is announced and focus moves to the first invalid field.

### Platform-admin override

- Show a persistent warning panel directly above decision actions.
- Require a free-text `Override-Grund` of `10–1000` non-whitespace characters for either decision.
- Normal group reviewers never see override controls. The warning explicitly says that no review credit is awarded.

### Concurrent decision

- HTTP conflict results in a stable inline conflict state, not a generic error.
- Remove/disable both decision actions, show `Diese Prüfung wurde bereits von einer anderen Person entschieden.`, and offer `Aktuellen Stand laden` plus `Zurück zur Prüfliste`.
- Refreshing must reveal the authoritative history state; never retry the mutation automatically.

## Responsive and Accessibility Contract

- Full review workspace starts at `768px` CSS viewport width. Below `768px`, replace queue and detail decision UI with the dedicated larger-workspace message and a safe navigation action; do not squeeze the table, allow horizontal scrolling, or expose mutation controls.
- At `768px` and above, keyboard focus order follows view control → filters → rows/actions → load-more. Sticky headers must not obscure focused rows.
- Table has an accessible caption `Offene Prüfungen der Fansubgruppe` or `Prüfverlauf der Fansubgruppe`; sortable state is not implied because order is fixed.
- Filter controls have visible labels. Counter badges are supplementary and are not the only means of selecting a type.
- Decision success, failure, and concurrency changes use an `aria-live="polite"` status region. Validation errors use field associations; the override warning and destructive modal have accessible names.
- Image alt text identifies type, project, and episode without inventing visual content. `Original öffnen` states when it opens a new tab.
- Protected screens accept an active refresh session (`hasAccessToken || hasRefreshToken`) and let the central API client refresh. Missing access token alone must not flash logged-out, empty, or forbidden UI.

## State Matrix

| Surface/state | Required presentation | Allowed actions |
|---------------|-----------------------|-----------------|
| Queue initial loading | Table-scoped skeleton/loading state | none |
| Queue empty | `Keine offenen Prüfungen`; filter reset only when filters are active | reset filters |
| Queue incremental error | Existing rows plus footer error | retry page |
| Open review | Content, context, active decision area | confirm, reject |
| Decision pending | Content remains visible; buttons disabled; active action loads | none |
| Decision success | Success message, no mutation controls | next open, return |
| Concurrent decision | Stable conflict message, no mutation controls | refresh, return |
| Own submitted item | `In Prüfung`, last activity | normal edit flow where allowed |
| Own rejected item | category and explanation visible | edit, resubmit same item |
| Cleaned-up history | metadata/timeline only; no content, free reason, or file affordance | return |
| Unauthorized / wrong group | Existing scoped forbidden/not-found state; no leaked context | return to group workspace |
