<objective>
Fix UAT-138-C: an mehreren Stellen im Rechte-/Änderungen-Admin-UI erscheinen rohe technische
Codes (Rollencodes wie `co_leader`, Capability-Action-Codes wie
`fansub_group_page.technical_links_edit`, sowie `Benutzer #<id>` statt Anzeigenamen) direkt im
user-facing Text, ein Verstoß gegen D-33 aus `138-CONTEXT.md` ("technische Begriffe gehören nur
in erweiterte technische Details"). Alle benötigten Labels existieren bereits (RoleCapabilityMatrix
für Rollen/Capabilities, `app_users.display_name` für Akteure/Ziel-Benutzer) -- es fehlt nur die
Verdrahtung an den betroffenen Stellen.

Purpose: Admin-Oberfläche zeigt an jeder betroffenen Stelle verständliche deutsche Fachbegriffe
statt interner Codes, ohne eine zweite Label-Tabelle einzuführen oder Vertragslogik/Filterverhalten
zu verändern.

Output: Vier abgeschlossene, unabhängig committbare Fixes -- (1) Rollenlabel-Mapping im
Benutzer-in-Gruppe-Rechteeditor, (2) Rollenlabel-Mapping im geführten Entzug-Dialog, (3)
Rollen-/Capability-Label-Mapping in der übersetzten Änderungen-Liste, (4) additive
`actor_display_name`/`target_display_name`-Vertragserweiterung für echte Akteur-/Ziel-Namen in
`GET /admin/changes`.
</objective>

export function roleLabelFor(roleCode: string, matrix: RoleCapabilityMatrix | null): string {
