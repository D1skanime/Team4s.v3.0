# Quick Task 260718-2w4: Fansub-Projektseite — Releases-Liste fixen — Summary

## Ziel erreicht

Alle vier diagnostizierten Fehler in der Sektion "Releases zum Fansub" (`OlderReleasesList`) wurden behoben:

1. **Reihenfolge:** `excludeReleaseVersionId` (Filter + potenzieller Ausschluss von Folge 1) komplett entfernt; die Liste sortiert jetzt clientseitig strikt aufsteigend nach `episode_number` via `sortReleasesByEpisodeNumberAscending`, unabhaengig von der API-Antwortreihenfolge.
2. **Mobile-Layout:** Die fehleranfaellige CSS-Doppelnutzung von `.rowActions` (Desktop-Button-Zeile vs. Mobile-Wrapper via `.list > .rowActions`-Override-Kaskade) wurde durch einen strukturellen Fix ersetzt: `useIsMobileReleasesList()` (neuer Hook, `useSyncExternalStore`+`matchMedia`, exakt nach `ProjectStats.tsx`-Muster) rendert zu jedem Zeitpunkt nur EINEN DOM-Zweig — entweder `.mobileList` (neue eigenstaendige Klasse) oder `.timelinePreview` (Desktop). Die CSS-Kaskaden-Unsicherheit ist damit strukturell irrelevant statt nur kosmetisch kaschiert.
3. **Kara-Dropdown:** Bleibt ein `Accordion` mit Titel "Karas anzeigen"; funktioniert unveraendert (auf/zuklappen der Segmentliste).
4. **Ansicht-Button:** Bei Kara-Folgen liegt der Button jetzt strukturell AUSSERHALB des Accordion-Toggle-Buttons (neue Komponente `MobileKaraReleaseRow`: Header + Ansicht-Button immer sichtbar, Accordion darunter fuer die Kara-Segmentliste). `ReleaseDetails` (der Accordion-Body) enthaelt den Ansicht-Button nicht mehr — er existiert nur noch einmal im DOM.
