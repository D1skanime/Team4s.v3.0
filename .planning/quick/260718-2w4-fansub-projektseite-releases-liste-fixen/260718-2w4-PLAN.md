# Quick Task 260718-2w4: Fansub-Projektseite — Releases-Liste fixen

## Ziel

Die Sektion "Releases zum Fansub" auf der öffentlichen Fansub-Projektseite (`OlderReleasesList`, eingebettet über `ReleasesSection`) zeigt vier bereits diagnostizierte Fehler. Das eingebettete Featured-Release oben (`PublicReleaseBlock`/`projectPageData.ts`) bleibt unverändert bestehen — dieser Quick Task fixt ausschließlich die darunterliegende Liste. Reine Frontend-Änderung, kein Backend-Rebuild.

## Vorab-Befund (Root-Cause-Analyse)

1. **Reihenfolge:** `ReleasesSection.tsx` übergibt `excludeReleaseVersionId={latestRelease?.id}` an `OlderReleasesList`, das damit Folge 1 (aktuell `activityPage.items[0]` nach `sort:"release_date"`) aus der Liste herausfiltert. Der Cursor-Endpunkt (`getGroupReleaseListCursor`) unterstützt laut `CursorQueryOpts` in `frontend/src/lib/api.ts` nur `sort: "activity" | "release_date"` — es gibt keinen `episode_number`-Sortmodus. Die Liste muss deshalb clientseitig sortiert werden.
2. **Mobile-Layout kaputt:** `OlderReleasesList.module.css` verwendet die Klasse `.rowActions` für ZWEI unterschiedliche Rollen: (a) die rechtsbündige "Ansicht"-Button-Zeile innerhalb von `DesktopReleaseRow`/`.rowHeader` (Basisregel `display: flex; justify-content: flex-end;`) und (b) den äußeren Mobile-Listen-Wrapper (direktes Kind von `.list`), der eigentlich eine volle-Breite vertikale Kartenliste sein soll. Rolle (b) wird nur über den spezifischeren Selektor `.list > .rowActions { display: none }` (Default) bzw. `@media (max-width: 768px) { .list > .rowActions { display: grid; ... } }` korrigiert. Sobald diese Override-Kaskade nicht wie erwartet gewinnt (z. B. durch CSS-Modul-Ladereihenfolge zwischen `OlderReleasesList.module.css` und `ui.module.css`), erbt der Mobile-Wrapper die Basisregel `display:flex; justify-content:flex-end` — das erklärt exakt das gemeldete Bild "Karten kleben rechts, linke Hälfte leer".
3. **Kara-Dropdown:** Hängt strukturell an Punkt 2 — sobald das Layout sauber ist, muss geprüft werden, dass das Accordion weiterhin korrekt sichtbar/funktional bleibt.
4. **Ansicht-Button versteckt:** Bei Kara-Folgen liegt `MobileReleaseHeader` (inkl. "N Karas"-Badge) und der komplette `ReleaseDetails`-Body (inkl. "Ansicht"-Button, Zeilen 236-238) INNERHALB des Accordion-Items. Da `Accordion.tsx` `item.title` in den klickbaren `<button>`-Header rendert und `item.children` nur bei `isOpen` zeigt, ist "Ansicht" erst nach dem Aufklappen sichtbar. Ein `<Button>` direkt in `item.title` zu legen wäre zudem ungültiges verschachteltes `<button>`-Markup. Der Button muss daher strukturell aus dem Accordion herausgelöst werden.
