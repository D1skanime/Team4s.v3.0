<objective>
Auf der Anime-Detailseite laeuft ein Theme-Hintergrundvideo. Klickt ein Nutzer auf einen anderen Anime (Link-Navigation), schaltet sich der Ton des alten Videos im selben Moment ein (weil der bestehende window-weite `pointerdown`/`keydown`-Listener JEDEN Klick als "Nutzerinteraktion" interpretiert) und laeuft dann noch eine Zeit lang hoerbar weiter, bis die neue Seite da ist. Dieser Plan unterdrueckt die Audio-Aktivierung bei navigierenden Klicks/Tastendruecken und stoppt das laufende Video sofort (mute + pause + Entladen), sobald eine Navigation beginnt, beim Unmount und bei `pagehide`.

Purpose: Kein nachlaufender Ton beim Seitenwechsel auf der Anime-Detailseite.
Output: Erweiterte reine Logik in `themeVideoAudio.ts` (mit Tests) + verdrahtete `AnimeBackdropRotator.tsx`.
</objective>

Relevanter Ausschnitt aus `AnimeBackdropRotator.tsx` (Ist-Zustand, Zeilen ~81-98 -- der Listener der Audio-Aktivierung aus JEDEM Klick/Keydown ausloest, auch bei Navigation):

```typescript
useEffect(() => {
  if (!showThemeVideo || !activeThemeVideoUrl || !isThemeVideoMuted) return undefined

  function onUserActivation() {
    void enableThemeVideoAudio(false)
  }

  const events: Array<keyof WindowEventMap> = ['pointerdown', 'keydown']
  for (const eventName of events) {
    window.addEventListener(eventName, onUserActivation, { passive: true })
  }

  return () => {
    for (const eventName of events) {
      window.removeEventListener(eventName, onUserActivation)
    }
  }
}, [showThemeVideo, activeThemeVideoUrl, isThemeVideoMuted, enableThemeVideoAudio])
```

Link-Beispiele im Projekt, die eine Navigation zu einem anderen Anime ausloesen (next/link rendert am Ende ein natives `<a href="...">`, daher reicht `closest('a[href]')` auf dem Event-Target):
- `frontend/src/components/anime/AnimeCard.tsx`: `<Link href={detailHref} ...>` (z.B. `/anime/42`)
- `frontend/src/components/anime/AnimeRelations.tsx`: `<Link href={`/anime/${rel.anime_id}`} ...>`

`themeVideoRef` ist ein `useRef<HTMLVideoElement | null>(null)`, das direkt am `<video ref={themeVideoRef} ...>`-Element haengt (key wechselt mit `activeThemeVideoUrl`).

WICHTIGER REACT-HINWEIS fuer die Umsetzung: In einem `useEffect`-Cleanup ist `themeVideoRef.current` zum Zeitpunkt des Cleanups NICHT mehr zuverlaessig das Video-Element von diesem Render (React loest Refs beim Unmount/Key-Wechsel vor dem Ausfuehren von `useEffect`-Cleanups). Daher: das Video-Element IMMER am Anfang des Effekt-Bodies in eine lokale Konstante einfangen (`const video = themeVideoRef.current`) und diese lokale Variable sowohl in den Event-Handlern als auch im Cleanup verwenden -- NICHT erneut `themeVideoRef.current` im Cleanup lesen.

      - `eventType: 'keydown'` + `key: 'Enter'` + navigierendes Link-Target -> true
      - `eventType: 'keydown'` + `key: 'Tab'` (oder beliebig != 'Enter') + navigierendes Link-Target -> false
