<objective>
Stop an existing backend test antipattern (asserting behavior by reading a .go source file as
text and grepping for a string, instead of executing the code) from spreading further into new
phases. This plan only documents the rule and records the measured scope of existing debt — it
does not touch any test file or production code. Rewriting the 49 affected test files is separate,
future, evidence-led remediation work.

Purpose: A brand-new file from Phase 144 (admin_content_release_version_media_replace_test.go)
already copied this pattern from its neighbors today, because CLAUDE.md's existing
"closest-analog" convention (from the Frontend-UI section) implicitly encourages leaning on
existing code, and nothing currently tells engineers this particular pattern is not a valid
analog to follow. Without an explicit, discoverable rule in CLAUDE.md, every future phase that
touches these packages will keep copying it forward.

Output:
- New "### Teststil" subsection in CLAUDE.md's "## Conventions" section (third subsection, after
  Sprachqualität and Frontend-UI, still before the conventions-end marker).
- Expanded "## WR-02" section in .planning/notes/2026-09-02-altlasten-cr01-wr02.md with the real
  measured scope and a note that the prior scope claim in the file was too narrow.
</objective>

Measured finding (authoritative, already measured by the user, do not re-derive): 49 backend
test files read a .go SOURCE file as text and assert on behavior via strings.Contains, 236 such
assertions total, spread across internal/handlers, internal/repository, and internal/services.

Literal example, from backend/internal/handlers/admin_content_release_version_media_test.go
(around lines 306-309, test TestReleaseVersionMedia_InvalidCategoryRejectsUpload):

  src, err := os.ReadFile("admin_content_release_version_media.go")
  assert.True(t, strings.Contains(string(src), INVALID_CATEGORY))

The test builds a real request but discards the response; it stays green if the check is moved,
inverted, or deleted, as long as the string appears anywhere in the file, including inside a
comment.

Evidence the pattern is actively spreading: the brand-new Phase-144 file
backend/internal/handlers/admin_content_release_version_media_replace_test.go already copied it,
e.g. TestReplaceReleaseVersionMediaFileRequiresUpdatePermission (line 22) does
os.ReadFile of admin_content_release_version_media_replace.go then a chain of strings.Contains
checks (lines 27-40), again without exercising the handler via httptest.

Scope boundary, do NOT conflate with the antipattern:
- 54 other test files read .sql MIGRATION files as text, that is legitimate; the file itself IS
  the thing under test there.
- Absence checks ("identifier X must not appear anywhere in the file") are also legitimate; they
  genuinely cannot be checked via behavior/execution.
