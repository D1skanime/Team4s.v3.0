# Quick Task 260703-bc9: Fix sticky admin auth/logout state blocking leader/member E2E

## Goal

Fix the logout/auth-state bug that blocked the fresh UI-first E2E retest: after logging out as platform admin, the browser must not keep showing the admin session, and a different Keycloak user such as an invited fansub leader must be able to start login from `/login` without manual cookie or storage manipulation.

## Plan

1. Reuse the central browser auth seam in `frontend/src/lib/api.ts`; do not add page-local token, cookie, or storage handling.
2. Make explicit logout clear the local Team4s runtime session before waiting for remote Keycloak/backend revocation, so the UI immediately stops treating the previous user as active.
3. Route Keycloak logout through the existing same-origin proxy endpoint in `frontend/src/app/api/auth/keycloak/logout/route.ts`, matching the existing refresh-token proxy pattern and avoiding browser CORS/redirect dependence.
4. Add focused tests proving:
   - `logoutActiveAuthSession()` clears cookies/storage before the remote Keycloak logout promise resolves.
   - Keycloak logout uses `/api/auth/keycloak/logout` with the refresh token payload.
   - Existing token-free session snapshot behavior remains intact.
5. Run the narrow frontend auth tests plus `git diff --check`.

## Acceptance Criteria

- App logout removes access token, refresh token, display name, and runtime session metadata even if remote Keycloak logout is slow or fails.
- `/login` no longer sees the previous admin session after app logout.
- No component or page reads auth cookies/storage directly.
- No new API contract is introduced; the existing Keycloak logout proxy is reused.
- The fix is documented in `SUMMARY.md`, `.planning/STATE.md` is updated, and the quick artifacts plus code changes are committed atomically.
