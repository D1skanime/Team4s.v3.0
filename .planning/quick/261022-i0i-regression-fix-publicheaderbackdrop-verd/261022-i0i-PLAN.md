<objective>
Fix a real regression introduced by quick-261022-g17: on the release page
(`.../releases/<id>`), the shared `PublicHeaderBackdrop` now visually sits IN FRONT OF the
page's own content (the hero image/logo, breadcrumb, "Zurueck zum Fansub-Projekt" button,
and episode/version heading), instead of behind it as intended. The user's own verification
screenshots from g17 (`release-transparent-logo-1440x900.png`, `release-normal-image-1440x900.png`)
show the sharp hero image missing/obscured and the breadcrumb/nav text washed out under the
backdrop's overlay.

**Confirmed root cause (found via `git show`/`git log -p` on the named g17 commits, comparing
before/after -- not guessed):**

Before g17's Task 3 (commit `afacfd2b8`), the release page's hero backdrop was implemented as two
pseudo-elements on `.pageWithBackdrop` with **negative** `z-index`:
`.pageWithBackdrop::before { z-index: -2; ... }` and `.pageWithBackdrop::after { z-index: -1; ... }`
(see `git show afacfd2b8 -- "frontend/.../page.module.css"`, removed lines). Negative `z-index` on
a positioned descendant guarantees it paints BEHIND every non-positioned, in-flow (`position:
static`) sibling in the same stacking context (CSS2.1 Appendix E stacking order: step 2, negative
z-index descendants, paints before step 3, in-flow non-positioned descendants) -- **without**
requiring the page's own content to opt into anything.

Commit `afacfd2b8` replaced those two pseudo-elements with
`<PublicHeaderBackdrop imageUrl={atmosphereUrl} className={styles.releaseHeroBackdropTuning} />`.
The shared primitive's base rule, `frontend/src/components/public/PublicHeaderBackdrop.module.css:4-10`,
declares `position: absolute; z-index: 0;` (verified: current file, line 8, `z-index: 0;`) --
**non-negative**. Per the same CSS2.1 Appendix E ordering (step 6: positioned descendants with
`z-index: 0`/`auto` paint AFTER step 3, in-flow non-positioned descendants, regardless of DOM
order), this positioned, `z-index: 0` backdrop div now paints ON TOP of every plain, non-positioned
sibling inside `.page`'s stacking context (`.page` has `position: relative; isolation: isolate;`,
`page.module.css:1-9`). The release page's actual content -- `.pageHeaderRow` (breadcrumb + back
button, `releaseDetailPageData.tsx:107-112`) and `<ReleaseDetailHero>`'s `.hero`/`.heroSummary`/
`.heroImageShell`/`.heroImage` (`ReleaseDetailHero.tsx:27-33`, `page.module.css:88-202`) -- are ALL
plain `position: static` elements with no `z-index` of their own. That is exactly why the hero
image is obscured and the breadcrumb/button/heading look washed out: the backdrop's own
`::after` gradient overlay (bundled into the same local stacking-context unit as `.backdrop`, via
`.releaseHeroBackdropTuning.releaseHeroBackdropTuning::after`, `page.module.css:30-35`) now paints
above them.

**Why the group and project pages were NOT affected by the same change (confirmed, not assumed):**
every other one of the shared primitive's 5 other call sites already wraps its content sibling in
an explicit `position: relative; z-index: 1;` container, inside the SAME small, locally-isolated
stacking-context wrapper as the backdrop:
- Group hero: `.heroFg` (`frontend/src/app/fansubs/[slug]/page.module.css:60-62`), sibling of the
  backdrop inside `.hero` (`isolation: isolate`, line 39-40).
- Project hero: `.heroFg` (`frontend/src/app/anime/[id]/group/[groupId]/page.module.css:60-62`),
  sibling of the backdrop inside `.heroShell` (`isolation: isolate`, `HeroSection.tsx:83-85`).
- Group Projekte/Medien bands: `.sectionBand > .gridSection { position: relative; z-index: 1; }`
  (`fansubs/[slug]/page.module.css:284-287`), sibling of the backdrop inside `.sectionBand`
  (`isolation: isolate`, line 268-269).
- Project "Neuestes Release" band: `.releaseBandContent { position: relative; z-index: 1; }`
  (`sections/ProjectContentSections.module.css:119-122`), sibling of the backdrop inside
  `.sectionBand` (same shared class, same isolation).

Because these content wrappers are explicitly positioned with `z-index: 1`, ordinary numeric
z-index comparison applies (`1 > 0`), and the content always wins regardless of whether the
backdrop's own base z-index is `0` or `-1`. The release page is the ONLY one of the 6 call sites
that did not get an equivalent "lift content above backdrop" wrapper during g17's Task 3, because
its OLD implementation relied on the backdrop side carrying negative z-index, not the content side
carrying positive z-index -- an inconsistency g17's migration didn't carry forward.

**The fix is therefore a single, shared-component CSS change, not a release-page patch:** change
`PublicHeaderBackdrop.module.css`'s `.backdrop` rule from `z-index: 0;` to `z-index: -1;`. This
restores the exact pre-regression release-page behavior (backdrop always paints behind static
in-flow content, no opt-in required) while being a no-op for the group/project pages, whose content
wrappers are already at `z-index: 1` (`1 > -1` holds exactly as well as `1 > 0` did). No JSX
restructuring, no new per-page exception class, and `/anime/<id>` (`AnimeBackdropRotator`,
untouched by g17 and by this plan) is unaffected.

An alternative fix -- wrapping the release page's content in its own `position: relative; z-index:
1;` div, matching the other 5 call sites' pattern -- was considered and rejected: `.page` is
`display: grid` and several existing rules key off `.page`'s DIRECT children (`.page > section:not(.hero)`,
`page.module.css:37-45`; `.hero + section { margin-top: -24px; }`, line 105; the `gap: 32px` grid
layout itself). Wrapping all of `.page`'s children in one new div would change which elements are
direct children of `.page`, silently breaking those selectors and the grid gap behavior -- a much
larger, riskier change for the same outcome. The one-line shared-primitive fix has zero such risk.

Purpose: restore the release page's intended visual hierarchy (sharp content on top, blurred
backdrop behind) via the shared primitive used by all three pages, and extend the existing
Playwright verification so this class of regression (positioned backdrop painting above static
content) is caught automatically in future, not just by human screenshot review.

Output: one-line fix in `PublicHeaderBackdrop.module.css`, a regression-guard unit test, and an
extended `verify-public-header-backdrop.mjs` with new `elementFromPoint`-based visibility/
reachability checks across all 3 pages and both release sub-cases.
</objective>

    ```javascript
    // Stacking/reachability checks (quick-261022-i0i): proves the backdrop paints BEHIND page
    // content by checking that elementFromPoint at the head image's and key content elements' own
    // centers resolves to that element itself (or its image/container), never to the backdrop.
    for (const target of STACKING_TARGETS) {
      const targetPath = target.path ?? releasePath
      await page.setViewportSize(STACKING_CHECK_VIEWPORT)
      await page.goto(`${BASE}${targetPath}`, { waitUntil: 'networkidle' })

      const stacking = await page.evaluate(({ headImageSelectors, contentProbes }) => {
        const backdropEl = document.querySelector('[data-testid="public-header-backdrop"]')
        const findFirst = (selectors) => selectors.map((sel) => document.querySelector(sel)).find(Boolean) || null

        const headImageEl = findFirst(headImageSelectors)
        let headImage = null
        if (headImageEl) {
          const r = headImageEl.getBoundingClientRect()
          const cs = getComputedStyle(headImageEl)
          const topEl = document.elementFromPoint(r.left + r.width / 2, r.top + r.height / 2)
          const isImageOrContainer = !!topEl && (
            topEl === headImageEl
            || headImageEl.contains(topEl)
            || (headImageEl.parentElement && (topEl === headImageEl.parentElement || headImageEl.parentElement.contains(topEl)))
          )
          const isBackdrop = !!topEl && !!backdropEl && (topEl === backdropEl || backdropEl.contains(topEl))
          headImage = {
            width: r.width,
            height: r.height,
            opacity: cs.opacity,
            visible: r.width > 0 && r.height > 0 && cs.opacity === '1',
            topElementIsImageOrContainer: isImageOrContainer,
            topElementIsBackdrop: isBackdrop,
          }
        }

        const probes = contentProbes.map(({ label, selector }) => {
          const el = document.querySelector(selector)
          if (!el) return { label, selector, found: false }
          const r = el.getBoundingClientRect()
          if (r.width === 0 || r.height === 0) return { label, selector, found: true, zeroSize: true }
          const topEl = document.elementFromPoint(r.left + r.width / 2, r.top + r.height / 2)
          const reachable = !!topEl && (topEl === el || el.contains(topEl))
          const isBackdrop = !!topEl && !!backdropEl && (topEl === backdropEl || backdropEl.contains(topEl))
          return { label, selector, found: true, reachable, topElementIsBackdrop: isBackdrop }
        })

        return { headImage, probes }
      }, { headImageSelectors: target.headImageSelectors, contentProbes: target.contentProbes })

      const shotPath = `${SHOT_DIR}/stacking-${target.name}-${STACKING_CHECK_VIEWPORT.label}.png`
      await page.screenshot({ path: shotPath, fullPage: false })

      results.push({ check: 'stacking', page: target.name, path: targetPath, ...stacking, screenshot: shotPath })

      if (stacking.headImage) {
        if (!stacking.headImage.visible) {
          failures.push(`${target.name}: head image not visible (width=${stacking.headImage.width}, height=${stacking.headImage.height}, opacity=${stacking.headImage.opacity})`)
        }
        if (stacking.headImage.topElementIsBackdrop) {
          failures.push(`${target.name}: head image center is covered by the backdrop (elementFromPoint returned the backdrop, not the image)`)
        }
        if (!stacking.headImage.topElementIsImageOrContainer && !stacking.headImage.topElementIsBackdrop) {
          failures.push(`${target.name}: head image center resolved to neither the image nor the backdrop -- unexpected overlay, investigate`)
        }
      }
      for (const probe of stacking.probes) {
        if (!probe.found) continue // selector not present on this page/fixture -- informational only
        if (probe.zeroSize) continue
        if (probe.topElementIsBackdrop) {
          failures.push(`${target.name}: "${probe.label}" (${probe.selector}) is covered by the backdrop (elementFromPoint returned the backdrop)`)
        } else if (!probe.reachable) {
          failures.push(`${target.name}: "${probe.label}" (${probe.selector}) is not reachable at its own position (elementFromPoint returned an unexpected element)`)
        }
      }
    }
    ```
