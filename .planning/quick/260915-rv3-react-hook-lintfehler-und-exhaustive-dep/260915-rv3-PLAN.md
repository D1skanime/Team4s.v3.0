PATTERN A — "async IIFE" fix for react-hooks/set-state-in-effect on data-fetch effects.

Applies to: useEpisodeNeighborNavigation.ts, useReleaseVersionMedia.ts, CapabilityHistoryPanel.tsx,
GroupRolesTab.tsx, and all four inner components of AdminGroupsClient.tsx.

WHY this works (verified against node_modules/eslint-plugin-react-hooks/cjs/*.development.js in the
running container): the `set-state-in-effect` rule flags any setState call reachable SYNCHRONOUSLY in
the effect callback's own control flow (including inside plain `if` branches), but does NOT flag
setState calls made inside a nested callback that only runs later/asynchronously (a `.then()`/`.catch()`
/`.finally()` callback, or the body of an `async () => {}` function after its first `await`). The fix:
wrap the WHOLE effect body — including any early-return branches that set state synchronously — in one
`void (async () => { ... })()` call, and turn the `.then/.catch/.finally` chain into `try { await ... }
catch { ... } finally { ... }`. Every `setX(...)` call that used to run synchronously in the effect now
runs inside that async function, which is executed via a plain CallExpression the linter does not trace
into. Behavior is 100% unchanged: an async function's body still runs synchronously up to its first
`await`, so `setIsLoading(true)` etc. still fire in the exact same microtask/tick as before. The
`cancelled` guard flag and its cleanup `return () => { cancelled = true }` stay OUTSIDE the async IIFE,
unchanged.

Concrete worked example — useEpisodeNeighborNavigation.ts (full effect, replace verbatim):

          const result = computeNeighborNavigation({
            episodes: response.data.episodes,
            currentVersionId,
            groupId,
            releaseVersion,
          });
          setNavigation(result);
          setError(null);
        } catch (caughtError: unknown) {
          if (cancelled) return;
          const message =
            caughtError instanceof Error
              ? caughtError.message
              : "Nachbar-Folgen konnten nicht geladen werden.";
          setError(message);
          setNavigation(EMPTY_TARGETS);
        } finally {
          if (!cancelled) setIsLoading(false);
        }
      })();

      return () => {
        cancelled = true;
      };
    }, [animeId, currentVersionId, groupId, releaseVersion]);
