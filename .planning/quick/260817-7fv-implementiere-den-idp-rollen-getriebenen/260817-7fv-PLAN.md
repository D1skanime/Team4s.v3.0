<objective>
Implement the IdP-role-driven global admin (JIT role sync) exactly as specified in
`.planning/notes/milestone-intent-rechte-benutzerverwaltung.md`, section "NACHTRAG" /
"Phase 0". A designated Keycloak realm role (`platform_admin`, also `content_admin`) makes
a user a team4s app admin automatically at request time — no `AUTH_ADMIN_BOOTSTRAP_USER_IDS`
env var, no manual DB insert, no backend restart. Sync is bidirectional: revoking the realm
role in Keycloak removes the corresponding `app_user_global_roles` row on the next resolved
request. Only the three-value global role set (`platform_admin`/`content_admin`/`user`) is
IdP-driven; fine-grained app-DB roles are an untouched, separate hybrid layer.

Purpose: Remove the admin bootstrap chicken-and-egg problem (`EnsureAppUserForIdentity`
today assigns no role, so the only way to create the first AppUserID-based admin was
`AUTH_ADMIN_BOOTSTRAP_USER_IDS`, which lives in a different, legacy `roles`/`user_roles`
table and rarely even applies to Keycloak-provisioned app users). Prepare the ground for the
later "Full-Reset" step of the v1.4 milestone intent (first admin purely via Keycloak realm
role, no env/DB bootstrap at all).
Output: Realm config wiring realm roles into the issued JWT, JWT claim extraction, a
reconciliation function (`SyncGlobalRolesFromKeycloak`) wired into the request-scoped
identity resolver, a deprecated-but-working bootstrap fallback, and a read-only
"aus IdP" global-role display in `/admin/users`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Keycloak-issued JWT -> Go backend | `realm_access.roles` is untrusted input from a token whose signature/issuer/audience are already verified before extraction; the claim itself is still attacker-influenced if the account is compromised or misconfigured in Keycloak. |
| JIT sync -> `app_user_global_roles` | Every authenticated request now reconciles a security-relevant DB table from token content; a bug here directly changes who is an app admin. |
| Docker-persisted Keycloak realm (`keycloak_db_data`) vs. declarative `realm-team4s.json` | Live `kcadm.sh` edits and the JSON source of truth can drift until the later Full-Reset. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
