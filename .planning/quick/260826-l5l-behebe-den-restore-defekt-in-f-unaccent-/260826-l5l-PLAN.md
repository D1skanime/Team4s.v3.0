<objective>
Fix the confirmed pg_restore-breaking defect in f_unaccent, documented as Befund 1 in .planning/notes/2026-08-26-keycloak-upgrade-und-voll-reset.md: pg_dump always emits an empty search_path at the top of a dump, and 0140's f_unaccent calls the unqualified unaccent('unaccent', $1), so on restore unaccent is unresolvable, the functional GIN trigram index on anime fails, anime never gets created, and 85 dependent objects cascade-fail. Purpose: Make pg_dump/pg_restore round-trips of team4s_v2 work natively again, without the sed search_path workaround, and without changing the function's runtime performance characteristics (no SET search_path on the function itself, since that disables planner inlining).

Up migration (0152_f_unaccent_search_path_fix.up.sql): open with a header comment block explaining the bug (unqualified unaccent('unaccent', $1) combined with pg_dump's empty search_path preamble breaks restore; reference Befund 1 in .planning/notes/2026-08-26-keycloak-upgrade-und-voll-reset.md and the measured 89-error restore failure from 2026-08-26) and the fix, then a single CREATE OR REPLACE FUNCTION f_unaccent(text) statement with:
- The identical signature to 0140 (RETURNS text, LANGUAGE sql)
- The identical IMMUTABLE, PARALLEL SAFE, STRICT modifiers, so the five existing GIN trigram indexes and the two generated search_tsv columns stay valid without a rebuild (CREATE OR REPLACE FUNCTION with an unchanged signature does not invalidate dependent objects)
- Body: SELECT public.unaccent('public.unaccent'::regdictionary, $1) -- schema-qualifies both the function call and the dictionary name so resolution succeeds even when search_path is empty, which is exactly what pg_dump sets at the top of every dump
- A dedicated SQL comment stating explicitly that SET search_path = public is deliberately NOT added to the function, because a SQL function carrying a SET clause can no longer be inlined by the query planner, making every search call (the five GIN trigram indexes plus the two generated tsvector columns) more expensive; the schema-qualified body alone is sufficient to fix the restore defect without this cost

Down migration (0152_f_unaccent_search_path_fix.down.sql): open with a header comment noting this restores the original, restore-unsafe 0140 body (kept only for migration reversibility, not recommended for production use), then CREATE OR REPLACE FUNCTION f_unaccent(text) with the exact original body from 0140 line 26 -- SELECT unaccent('unaccent', $1) -- and the same signature/modifiers.

Do not touch 0140's own files. Do not touch any index, generated column, or any file other than the two listed above.
