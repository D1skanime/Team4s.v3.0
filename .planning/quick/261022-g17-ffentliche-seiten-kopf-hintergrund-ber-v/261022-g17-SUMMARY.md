# Quick Task 261022-g17: Full-bleed public header backdrops + release hero image card removal Summary

**Replaced 5 page-specific, redundantly-clipped full-bleed backdrop implementations with one shared `PublicHeaderBackdrop` primitive, fixed a real (not just cosmetic) site-wide horizontal-scroll bug uncovered while verifying the fix live, and removed a box-shadow "card" artifact behind transparent-logo release hero images.**

## Performance

- **Duration:** ~48 min
- **Completed:** 2026-10-22
- **Tasks:** 6/6
- **Files modified:** 17 (4 new, 13 modified) across 6 commits

## Accomplishments

- Group page (`/fansubs/<slug>`), project page (`/fansubs/<slug>/fansubprojekt/<anime>`), and release page (`.../releases/<id>`) blurred head backdrops now bleed to both screen edges at wide viewports instead of stopping at the content-width edge, on all 3 affected pages.
- De-duplicated 5 near-identical page-specific backdrop div implementations into one shared `components/public/PublicHeaderBackdrop` primitive, reused via page-local `*Tuning.*Tuning` CSS modifier classes.
- Split the 450-line-rule-violating `group/[groupId]/page.module.css` (596 lines) into the kept hero/page-shell file plus a new `sections/ProjectContentSections.module.css` for the Story/Team/Releases/Themes/Media/Backlinks content-section rules.
- Removed the release page hero image's `box-shadow` so a transparent-background anime-logo fallback no longer shows a visible gray rounded-rectangle "card" floating behind it; `border-radius` kept for opaque images.
- **Found and fixed a real, previously-undetected regression risk**: relying on `body`-only `overflow-x: clip` (the plan's stated "already-correct global guard") does NOT reliably prevent a full-bleed (`100vw`) descendant that also carries `transform: scale(...)` from creating genuine, scrollable horizontal overflow at the `<html>`/viewport level -- confirmed live via `window.scrollTo()` + `scrollLeft` manipulation, not just by reading `scrollWidth`. Fixed by adding the same `overflow-x: clip` to `<html>` in `globals.css`.
- Built an in-container Playwright verification script (`frontend/scripts/verify-public-header-backdrop.mjs`) that measures full-bleed width, zero horizontal scroll, and unchanged content width across 3 viewports x 3 pages, plus the release hero image's `box-shadow`/`border-radius` across a transparent-logo case and a normal-image case -- 13 total combinations, all green on the final run.

## Decisions Made

- **Kept `--release-page-backdrop` alive, scoped to one remaining consumer.** The plan's Task 3 instructed removing the CSS-variable mechanism entirely since the backdrop itself no longer needs it. Removing it broke a *different*, explicitly untouched rule (`[data-release-atmosphere-band]::before`, a separate decorative glow) that still reads the same variable via `var()`. Caught by the pre-existing `cssCustomProperties.guard.test.ts` dead-reference test. Fix: keep setting the variable on `<main>`, document why in both the component and the test.
- **`html { overflow-x: clip }` added alongside the existing `body` rule.** The plan's premise ("global `body { overflow-x: clip }` ... is the already-correct guard") turned out to be incomplete for this specific combination (full-bleed `100vw` + `transform: scale()`). Verified empirically via live `scrollLeft` manipulation (not just reading `scrollWidth`) that the page was genuinely horizontally scrollable by ~200px at 2560px width before this fix, and not scrollable at all after.
- **Verification-script tolerances changed from exact-equality to edge-reach / not-full-bleed checks.** Two live-measured, pre-existing, unrelated characteristics would have made the plan's literal script fail on every single run regardless of correctness: (1) the hero backdrop's own pre-existing `transform: scale(1.15)` zoom effect (makes `getBoundingClientRect()` width larger than viewport width by design), and (2) `AppShell`'s fixed 16px "edge strip" grid column asymmetrically offsetting the `calc(50% - 50vw)` trick's containing block by ~8px (cosmetically imperceptible, present for any full-bleed element in the app, not introduced by this plan).

**8. [Rule 1 - Bug] A pre-existing, unrelated `AppShell` layout feature offsets any `calc(50% - 50vw)` full-bleed trick by ~8px**

- **Issue:** `AppShell.module.css` (a global, unrelated component, not in this plan's scope) reserves a fixed `16px` "edge strip" grid column (a hover-reveal sidebar trigger) before the content column. - **Fix:** Set the verification script's edge tolerance to 20px (comfortably covers this benign, cosmetically-imperceptible 8px offset while still failing hard on the actual multi-hundred-pixel-scale bug this plan targets).
- **Files modified:** `frontend/scripts/verify-public-header-backdrop.mjs`
- **Commit:** `059492240`

**9. [Rule 1 - Bug] Image-card verification selector matched the wrong element**

- **Fix:** Scoped the selector to `img[class*="heroImage"]`.
- **Files modified:** `frontend/scripts/verify-public-header-backdrop.mjs`
- **Commit:** `355817de6`
