<objective>
Das Header-Badge in der Fansub-Cockpit-Releaseliste ("Keine Themes" / muted) soll auch dann gruen "Themes" anzeigen, wenn die Folge Theme-SEGMENTE hat (nicht nur hochgeladene Theme-Assets). Aktuell haengt das Badge ausschliesslich an `has_theme_assets`, das nur `release_theme_assets`-Uploads prueft — Theme-Segmente ohne Upload werden ignoriert, obwohl die aufgeklappte Ansicht sie korrekt zeigt.

Purpose: Konsistenz zwischen eingeklappter Badge-Anzeige und aufgeklappter Theme-Segment-Liste herstellen, damit Admins am eingeklappten Header schon erkennen, ob eine Folge Themes hat.

Output: Neues Backend-Feld `has_theme_segments` auf `AdminFansubReleaseSummary`, befuellt durch eine korrelierte EXISTS-Subquery in allen drei Release-Queries; Frontend kombiniert `has_theme_assets || has_theme_segments` fuer Badge-Farbe/Text.
</objective>

<diagnosis>
Ursache bereits ermittelt: `ReleaseRowDetails.tsx` (~Zeile 141) rendert das Badge ausschliesslich anhand von `release.has_theme_assets`. Das Backend berechnet dieses Feld in `admin_content_fansub_releases.go` als
`EXISTS (SELECT 1 FROM release_theme_assets rta WHERE rta.release_id = fr.id)` — das erfasst NUR hochgeladene Theme-Videos, keine Theme-Segmente. Eine Folge mit OP/ED-Segmenten aber ohne Upload zeigt daher faelschlich "Keine Themes", obwohl die aufgeklappte Liste (`releaseSegmentCards`) Segmente anzeigt.

Gewuenschtes Verhalten (Nutzer bestaetigt): Folge HAT Themes -> gruenes Badge, Text "Themes". Folge hat KEINE Themes -> wie jetzt "Keine Themes" (muted). "Themes hat" = Release-Upload ODER mindestens ein Theme-Segment, dessen Episodenbereich diese Folge abdeckt (konsistent mit der aufgeklappten Liste). Muss auch fuer eingeklappte Zeilen stimmen -> Backend muss ein neues Feld pro Release liefern.
</diagnosis>
