<objective>
Fix `PlatformAdminGate` so a token refresh (which changes `hasAccessToken` and re-runs the
resolution effect) no longer unconditionally sets `isLoading(true)` and unmounts the child tree.
Only the first resolution should show the loading fallback; once a `currentUser` has resolved
once, subsequent re-validations (triggered by token refresh) must run in the background while
children stay mounted, preserving open dialogs / in-progress form state (e.g. the upcoming
Phase 138 Impact-Preview confirmation flow).

Purpose: Prevent silent loss of admin UI state (open dialogs, half-filled forms) every time an
access token refreshes in the background.
Output: Updated `PlatformAdminGate.tsx` with a "resolved once" ref gate, plus a new regression
test in `PlatformAdminGate.test.tsx` proving children stay mounted across a token change.
</objective>

<!-- The effect currently unconditionally calls setIsLoading(true) on every re-run: -->

```typescript
useEffect(() => {
  if (!isClientInitialized) return;

  let cancelled = false;
  async function resolveAdminUser() {
    if (!hasAccessToken && !hasRefreshToken) {
      if (!cancelled) {
        setIsLoading(false);
        setCurrentUser(null);
        setErrorMessage("Anmeldung erforderlich.");
      }
      return;
    }

    setIsLoading(true);              // <-- BUG: runs on every re-run, including token refresh
    setErrorMessage(null);
    try {
      const response = await getCurrentUser();
      if (!cancelled) setCurrentUser(response.data);
    } catch (error: unknown) {
      if (!cancelled) {
        setErrorMessage(
          error instanceof Error ? error.message : "Berechtigung konnte nicht geprüft werden.",
        );
      }
    } finally {
      if (!cancelled) setIsLoading(false);
    }
  }

  void resolveAdminUser();

  return () => {
    cancelled = true;
  };
}, [hasAccessToken, hasRefreshToken, isClientInitialized]);
```
