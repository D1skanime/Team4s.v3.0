weiterhin `key={member.member_display_name}` statt einer eindeutigen id. Zwei Einträge mit gleichem
Anzeigenamen kollidieren dadurch als React-Key (falsche Wiederverwendung/fehlende Einträge).

Komplikation: `memorial` mischt Zeilen aus zwei verschiedenen Domain-Projection-Typen
(`DomainProjectionMemberRow` aus der aktuellen Mitgliederliste, `DomainProjectionHistoricalRow` aus der
historischen Liste). Beide haben ein `id`-Feld, aber die IDs stammen aus unterschiedlichen DB-Tabellen und
können numerisch kollidieren — ein reiner `id`-Key wäre also nicht sicher genug. Der Fix markiert die
Quelle an der Stelle, an der sie unzweifelhaft bekannt ist (`FansubTeamSection.tsx`, beim Zusammenbauen von
`allMemorial` aus `memorialMembers`/`memorialHistorical`), und kombiniert Quelle+id über eine pure
Hilfsfunktion zu einem eindeutigen Key.

Purpose: React-Key-Kollisionen im Memorial-Block der öffentlichen Fansub-Gruppenseite verhindern.
Output: Pure, unit-getestete Key-Funktion + verdrahteter Fix in beiden betroffenen Komponenten + Report
über weitere ähnliche Risikostellen im Code (nur gemeldet, nicht verändert).
