# Phase 128 — UI Design Contract

> Visual and interaction contract for Canonical Public Identity & Visibility Foundation. Generated by gsd-ui-researcher; pending gsd-ui-checker approval.

---

## Design Intent and Phase Boundary

Phase 128 changes identity, access, and owner-preview behavior on the authoritative public member route, `/members/{slug}`. It does not redesign the public profile. Preserve the current toolbar, `MemberProfileHero`, section order, achievement presentation, cards, and profile-owned CSS except where the owner-preview notice and privacy-safe request states require a narrow addition.

The visible delta is limited to:

1. one persistent private-owner notice immediately above the existing profile header;
2. privacy-neutral loading and unavailable states;
3. stored-slug links with no numeric or nickname-derived fallback;
4. the visibility editor vocabulary changing from `members_only` to `private`;
5. owner-only edit/visibility actions and suppression of self-correction actions.

Do not add a second member page, a reduced owner-preview composition, a new global state system, or broad responsive/CSS cleanup. Complete composition consolidation, final responsive redesign, and image/accessibility hardening remain Phases 132–133.

### Reuse Contract

- Reuse `Card`, `Button`, `LoadingState`, and `ErrorState` where their semantics fit.
- Keep the existing `MemberProfileHero` and current public-profile section composition.
- Extend the existing `OwnHiddenProfilePreview` auth-state boundary or its direct replacement; remove its `getOwnProfile` reconstruction, slugification, numeric matching, and reduced legacy grid.
- Use `useAuthSession()` and the central `getMemberProfile(slug)`/API client. Never read tokens, call Keycloak refresh directly, or add protected ad hoc `fetch`.
- Do not add a generic banner/notice primitive for this one domain-specific state. Compose it from existing primitives and keep any necessary layout style route-owned.
- Do not modify unrelated profile badge/carousel visuals or the user's dirty profile files.

## Spacing Scale

All new spacing uses the existing token scale and remains a multiple of 4.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon alignment and very tight inline separation |
| `--space-2` | 8px | Notice action gap, notice text stack, and compact inline/internal gaps |
| `--space-4` | 16px | Default state padding and space between notice and hero |
| `--space-5` | 24px | Notice/card padding when geometry permits |
| `--space-6` | 32px | Larger local composition gap only |
| `--space-7` | 48px | Existing major section break |
| `--space-8` | 64px | Existing page-level spacing |

Exceptions:

- Interactive targets remain at least the existing `--control-height-md: 44px`.
- Existing 20px `stateCard` padding may remain; do not duplicate it as a new spacing token.
- Untouched legacy profile UI may retain existing 12px gaps, but 12px is outside the new Phase 128 spacing contract and must not be introduced or reused by Phase 128 additions.
- Preserve existing profile geometry outside the narrow additions in this phase.

| Role | Size | Weight | Line Height |

## Authoritative Page Composition

For an allowed public profile, retain this DOM/visual order:

1. existing page container and breadcrumb/toolbar;
2. private-owner notice only when the authoritative access result identifies an owner preview;
3. existing profile header/`MemberProfileHero`;
4. existing profile and membership band;
5. existing projects band;
6. existing badge band;
7. existing contribution band when currently applicable.

The existing `MemberProfileHero` and its member-name region remain the page's primary focal anchor. The private-owner notice is a compact contextual preface only: it must not compete as a second hero through hero-sized typography, a dominant background, additional page-heading semantics, or comparable visual weight.

The owner preview renders the same authoritative public-profile DTO and the same visible composition as a public visitor. It must not render the current reduced `profileGrid`, substitute own-profile media/contribution cards, empty badge fallbacks, or owner-only DTO conversion.

### Private-Owner Notice

Place the notice immediately above the profile header with a 16px gap to adjacent content. It is persistent, non-dismissible, and read-only.

- Accessible wrapper: `<aside aria-label="Privater Vorschaumodus">`.
- Emphasis: `Privates Profil – nur für dich sichtbar`.
- Body: `Du siehst die vollständige Vorschau. Andere Personen können dieses Profil nicht öffnen.`
- Primary action: `Sichtbarkeit ändern` → `/me/profile?tab=visibility`.
- Secondary action: `Profil bearbeiten` → `/me/profile`.
- Use existing `Button` link variants: primary for visibility, secondary for editing.
- Both targets have a minimum height of 44px and visible focus.
- The profile editor must honor `?tab=visibility` without duplicating editor state or creating a second visibility page.

The notice must not say that admins, logged-in members, or other viewers can see the profile. Only the verified owner can.

### Toolbar Ownership

- Verified owner viewing their own profile: show edit actions; never show `Korrektur melden`.
- Other viewers of a public profile: preserve the correction affordance and do not show owner edit actions.
- Private-profile non-owner, missing slug, numeric slug, or guessed nickname slug: show neither edit nor correction actions.

## Interaction and State Matrix

| Request/viewer state | Required presentation | Forbidden presentation |
|----------------------|-----------------------|------------------------|
| Public profile, anonymous | Existing full public composition | Owner notice or owner edit actions |
| Public profile, verified owner | Existing full composition plus owner edit actions; no correction action | Duplicate profile request authority or self-correction |
| Private profile, verified owner with access token | Owner notice followed by the full existing composition | Reduced preview, editor redirect, public-cacheable response |
| Private profile, verified owner with refresh token only | Neutral profile loading state, then owner notice and full composition | Logged-out, unavailable, 404, or correction flash |
| Private profile, authenticated non-owner/admin | Neutral 404/unavailable page | Login prompt, forbidden message, private-profile wording |
| Private profile, anonymous | Same neutral 404/unavailable page | Any existence disclosure |
| Missing, numeric, or guessed nickname slug | Same neutral 404/unavailable page | Redirect to a member, numeric fallback, different copy |
| Case/encoding/edge-space equivalent | Server-side permanent redirect to stored canonical URL with no toast | Client-side correction flash or existence-dependent wording |
| Non-404 transport/server failure | Scoped generic load error | Private/missing wording or exposed error details |

Private/missing equality includes visible copy, actions, heading structure, document metadata, and absence of owner/profile detail content.

## State Contracts and Copy

### Loading

While auth initialization or refresh-only owner recovery is unresolved, show only a neutral state inside the normal profile page container:

- Title: `Profil wird geladen`
- Description: `Team4s prüft, ob dieses Profil angezeigt werden kann.`
- Use `LoadingState` inside a wrapper with `role="status"` and `aria-live="polite"`.
- Do not render breadcrumbs containing a member name, profile metadata, a login prompt, the 404 state, or any cached profile content during this gate.
- On slug change/unmount, ignore or cancel stale responses before replacing this state.

### Neutral Unavailable (HTTP 404)

Use the exact same page for missing and privacy-denied requests:

- Document title: `Profil nicht verfügbar | Team4s`
- Heading: `Profil nicht verfügbar`
- Body: `Dieses Profil ist nicht verfügbar. Prüfe den Link oder kehre zur Anime-Übersicht zurück.`
- Action: `Zur Anime-Übersicht` → `/anime`
- Set `noindex`; do not include the requested slug, nickname, visibility reason, login state, or owner hints.
- Use a neutral existing card/state treatment, never a warning/danger treatment.

### Generic Failure

A non-404 failure remains distinct and scoped:

- Heading: `Profil konnte nicht geladen werden`
- Body: `Bitte versuche es später erneut.`
- Action: `Erneut versuchen`
- Use `ErrorState`; do not expose backend messages, member existence, or auth details.

### Visibility Editor Vocabulary

Retain the existing semantic radio-card control and update only its two options:

- `Öffentlich`: `Alle können dein Profil über den kanonischen Link ansehen.`
- `Privat`: `Nur du kannst dein Profil über den kanonischen Link als Vorschau ansehen.`

Remove `Nur für Mitglieder` and all `members_only` UI copy. Keep the existing save workflow; do not introduce a destructive confirmation.

## Responsive Contract

This phase does not redesign the profile page. The new notice is mobile-first and owns its overflow locally.

- Base geometry: text and actions form one vertical stack; actions may fill the notice width; `min-width: 0` on text/action children.
- Notice spacing: 16px padding at narrow geometry, 24px when the larger composition fits.
- Reusable/extracted notice content establishes `container-type: inline-size`; use a purpose-named container such as `owner-preview-notice`.
- At a minimum inline size of 36rem (576px), place the two actions in a wrapping row aligned after the copy. Below that threshold keep them stacked.
- The 36rem transition is based on fitting approximately 220px of copy, two usable actions, and gaps; it is not a device breakpoint.
- Do not add a viewport media query for the notice. Existing page-level viewport rules remain untouched.
- Long German copy must wrap naturally; do not add `overflow-wrap: anywhere`.
- Assert no document-level horizontal overflow at narrow, immediately below/above 36rem container width, intermediate, and wide layouts.

## Accessibility and Privacy Presentation

- Keep one `h1`: the member name when a profile is allowed; `Profil nicht verfügbar` when it is not.
- The private-owner notice uses an `aside` with an accessible label and non-heading emphasis so it does not precede the page `h1` with an `h2`.
- Loading changes are announced politely once; errors use the existing scoped state component.
- Links and buttons retain visible focus and 44px targets.
- Do not use color alone to indicate private preview; the explicit notice text is mandatory.
- No skeleton or stale content may reveal the hidden member before access resolution.
- The neutral unavailable page must be indistinguishable for hidden and missing profiles in both visual output and accessible names.
- Owner/viewer-specific presentation is `private, no-store` and must never be hydrated from a shared public cache.

---

## Canonical Navigation Contract

- Every member-profile link uses the required stored slug; no `slug || member_id`, numeric URL, or nickname slugifier remains.
- Changing a nickname changes visible profile text only, never the link.
- Canonical-equivalent requests redirect server-side without an intermediate visual state.
- Numeric URLs and URLs guessed from a changed nickname show the neutral unavailable page.
- The same canonical `/members/{slug}` URL serves public view and verified private-owner preview; do not create `/preview`, `/private`, or editor-based substitutes.

---

## Verification Contract

Automated UI/contract checks must prove:

1. refresh-only owner session shows loading then the full owner preview with no unavailable/logged-out flash;
2. owner notice copy, ordering, both edit links, and correction suppression;
3. missing, private-anonymous, private-non-owner, admin-non-owner, numeric, and guessed-slug outcomes share identical neutral UI copy/actions;
4. stored slug is used by every touched profile link and no numeric fallback remains;
5. `public/private` radio labels and descriptions replace `members_only`;
6. no direct token read, bearer construction, Keycloak refresh call, or protected ad hoc `fetch` is introduced;
7. notice actions reflow at their 36rem container threshold and create no horizontal overflow.

Live-browser UAT must start from the user-visible navigation path and verify:

- anonymous public profile;
- private owner with access token;
- private owner with refresh token only;
- private non-owner and missing profile side by side;
- canonical redirect;
- narrow notice geometry;
- intermediate notice geometry;
- notice geometry immediately below and immediately above the 36rem container boundary;
- wide notice geometry;
- high browser zoom that exposes reflow, overlap, and clipping faults;
- an explicit document-level no-horizontal-overflow assertion at every tested geometry (`document.documentElement.scrollWidth <= document.documentElement.clientWidth`).

Use the shared browser route `http://127.0.0.1:3300/members/{stored-slug}`; headless tests support but do not replace live navigation/product-fit review.
