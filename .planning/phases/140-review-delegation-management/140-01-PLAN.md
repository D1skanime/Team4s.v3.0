<objective>
Build the backend HTTP boundary for Review Delegation Management: a non-locking repository
read for a target member's current delegation state (RDEL-01, the one genuinely missing
piece per 140-RESEARCH.md), and a new, dedicated `AdminReviewDelegationHandler` exposing
GET (inspect) and PUT (grant/revoke) for one (fansub group, target app user) pair. The
handler is a thin HTTP projection: all domain mutation logic (idempotency, transactional
audit, eligibility gating) already lives in `services.ReviewService.GrantDelegation`/
`RevokeDelegation` (Phase 107/137, RDEL-04 already satisfied there) and MUST NOT be
duplicated or modified here.

Purpose: close RDEL-01's actual gap (no read path for an arbitrary target's delegations
exists yet) and give RDEL-02/RDEL-04 a real, tested HTTP surface, without touching
`review_service.go` (already 448/450 lines) or `admin_effective_rights_handler.go`
(already 624 lines, over cap).

Output: `ReviewDelegationRepository.LoadDelegationSnapshot`, three new DTOs, and
`AdminReviewDelegationHandler` with full unit-test coverage (stub-based, no real Postgres
needed for the handler layer -- mirrors `admin_effective_rights_handler_test.go`'s existing
convention exactly) plus one new real-Postgres repository test using the existing
`openPhase107ReviewRepositoryPool` helper already present in
`review_delegation_repository_test.go` (no new test-fixture file needed -- this repository
test file already composes `OpenPhase107Postgres` + manual migration 0134 apply, which is
sufficient for this read method; RESEARCH.md's suggested new `phase140_postgres.go` harness
is not required because the handler layer here is stub-tested, not integration-tested).
</objective>
