# Phase 98 / Plan 05: E2E-Verifikation und UAT

## Ziel

Die Phase wird erst abgeschlossen, wenn der komplette Segmentstream von gespeicherter Quelle bis Browser-Playback nachweislich funktioniert und die Sicherheitsgrenzen halten.

## Requirements

- Viper's Creed EP01 dient als realer Referenzfall.
- Audio muss im erzeugten Clip vorhanden sein.
- ASS/Kara-Effekte muessen sichtbar eingebrannt sein, wenn Jellyfin die Spur liefert.
- Kein voller Episode-Stream ueber Segment-Parameter.
- Segmentrechte funktionieren app-user- und capability-getrieben; Rollen sind kein Runtime-Hardcode.
- Public-Backend-Flaeche vorbereitet, Public-UI nicht gebaut.

## Tasks

1. Automatisierte Checks ausfuehren.
   - Backend-Tests.
   - Frontend-Typecheck/Tests.
   - Contract-Checks.
   - Migration up/down.
   - `git diff --check`.

2. Runtime-Smoke.
   - Backend-Container neu bauen.
   - `ffmpeg -version` und `ffprobe -version` im Runtime-Kontext pruefen.
   - Segment-Render-Dir existiert und liegt unter kontrolliertem Media-Volume.

3. Realer Jellyfin-Smoke.
   - Viper's Creed EP01 Segment 0-80 Sekunden aus Release/Jellyfin-Quelle rendern.
   - Status muss von `queued/rendering` nach `ready` wechseln.
   - `ffprobe` auf Output:
     - Video vorhanden
     - Audio vorhanden
     - Dauer entspricht Segmentfenster
   - Sichtprobe im Browser: Kara/ASS ist eingebrannt oder Diagnose erklaert fehlende Spur.

4. Stream-Sicherheit pruefen.
   - Segmentstream mit gueltigem Grant abspielen.
   - Unberechtigter User bekommt keinen Grant.
   - Manipulierte Query-Parameter fuer Start/Ende verlaengern Playback nicht.
   - Direkte Episode-/Release-Stream-URL ist nicht Teil des Segment-Preview-Flows.

5. Rechte- und Auth-UAT.
   - Admin kann Segment vorbereiten/previewen.
   - Konkreter App-User mit `release_version.segments.manage` kann Segment erstellen, editieren, loeschen, vorbereiten und Fallbacks hochladen.
   - Gruppen-/Projektleitung kann oder soll ueber Rechte-Management entscheiden koennen, welche App-User diese Capability erhalten.
   - User ohne Capability kann es nicht.
   - Ein User mit passender Rolle, aber ohne App-User-Capability, darf nicht allein wegen des Rollennamens zugreifen.
   - Access-Token fehlt/ist abgelaufen, Refresh-Session ist gueltig: Next-Relay funktioniert weiterhin.

6. Upload-Fallback-UAT.
   - Bestehenden Segment-Upload verwenden.
   - Upload-Fallback wird abgespielt, ohne neue Media-Struktur.
   - Keine Fallback-Datei wird an Episode-Media oder `release_media` vorbei angehaengt.
   - Langer Upload-Fallback wird nicht automatisch als Episode-Stream missbraucht.

7. Abschlussdokumentation.
   - Befunde in Phase-Artefakt oder Audit notieren.
   - Offene Risiken fuer Worker-Skalierung/HLS/Public-UI separat festhalten.
   - Keine Phase als fertig markieren, wenn Audio, Grant-Grenze oder Segment-ID-Sicherheit nicht verifiziert sind.

## Acceptance

- E2E im Browser funktioniert fuer ein reales Segment.
- Der erzeugte Clip hat Audio.
- Server erzwingt die Segmentgrenze.
- Rechte und Refresh-Verhalten sind verifiziert.
- Keine Domain-Regel zu Media-Ownership wurde verletzt.

## Verification Commands

Die genauen Befehle muessen an die lokalen Package-Skripte angepasst werden, aber mindestens:

```powershell
git status --short
go test ./...
git diff --check
```

Zusaetzlich, wenn Services laufen:

```powershell
docker compose build backend
docker compose exec backend ffmpeg -version
docker compose exec backend ffprobe -version
```
