# Phase 98 / Plan 01: Schema, Runtime und Derived-Cache

## Ziel

Eine technische Derived-Media-Basis fuer vorbereitete Segment-Clips schaffen, ohne `media_assets`, `release_media` oder Episodenmedien falsch zu verwenden.

## Requirements

- Prepared Clips sind technische Cache-Dateien.
- Keine neue fachliche Media-Ownership-Struktur.
- Cache ist invalidierbar und reproduzierbar.
- FFmpeg/FFprobe sind in der Runtime verfuegbar.

## Tasks

1. Migration vorbereiten.
   - Vorher `git status` und vorhandene Migrationen pruefen.
   - Bei mehreren untracked Migrationen stoppen und Risiko melden.
   - Naechste freie Nummer verwenden.

2. Tabelle fuer Segment-Render-Cache einfuehren.
   - Empfohlene Tabelle: `theme_segment_render_cache`.
   - Mindestens speichern:
     - `id`
     - `theme_segment_id`
     - `playback_source_id`
     - `cache_key`
     - `source_kind`
     - `source_fingerprint`
     - `render_profile`
     - `status`
     - `output_path`
     - `mime_type`
     - `duration_seconds`
     - `video_codec`
     - `audio_codec`
     - `subtitle_stream_index`
     - `subtitle_codec`
     - `error_code`
     - `error_message`
     - `attempts`
     - `queued_at`
     - `started_at`
     - `completed_at`
     - `invalidated_at`
     - `created_at`
     - `updated_at`
   - `cache_key` eindeutig machen.
   - Foreign Keys auf Segment und Playback-Source setzen.

3. Statusmodell definieren.
   - Erlaubte Statuswerte: `queued`, `rendering`, `ready`, `failed`, `stale`.
   - `ready` braucht existierende Datei, MIME-Type und Duration.
   - `failed` braucht kurzen, nicht-geheimen Fehler.

4. Konfiguration ergaenzen.
   - `SEGMENT_RENDER_ENABLED`
   - `SEGMENT_RENDER_DIR`, Default unter `/app/media/derived/segments`
   - `SEGMENT_RENDER_MAX_SECONDS`, Default `240`
   - `SEGMENT_RENDER_FFMPEG_PATH`, Default `ffmpeg`
   - `SEGMENT_RENDER_FFPROBE_PATH`, Default `ffprobe`
   - Optional: Worker-Concurrency, Default `1`.

5. Container-Runtime vorbereiten.
   - Backend-Runtime mit `ffmpeg`/`ffprobe` ausstatten.
   - Keine Jellyfin-Schluessel in Dockerfile oder Compose hart codieren.
   - Derived-Renderpfad bleibt unter dem vorhandenen kontrollierten Media-Volume.

6. Repository-Methoden anlegen.
   - Cache nach Segment/Quelle lesen.
   - Cache-Key upserten.
   - Status sicher aktualisieren.
   - Alte Cache-Eintraege als `stale` markieren.
   - Obsolete Dateien nur ueber kontrollierte Cleanup-Logik entfernen.

## Acceptance

- Migration ist reversibel.
- Render-Cache ist klar technische Derived-Media und nicht Teil der fachlichen Upload-Media-Tabellen.
- Backend kann `ffmpeg -version` und `ffprobe -version` im Container ausfuehren.
- Repository-Tests decken Cache-Key und Statuswechsel ab.

## Verification

- Migration up/down lokal gegen Test-DB oder bestehendes Migrationsverfahren.
- `go test ./backend/...` oder passende Backend-Testpakete.
- `docker compose build backend`.
- `docker compose run --rm backend ffmpeg -version` oder gleichwertiger Check.
- `git diff --check`.
