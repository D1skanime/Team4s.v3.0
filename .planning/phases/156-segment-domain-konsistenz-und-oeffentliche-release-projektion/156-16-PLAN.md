<objective>
Close GAP-04 (Origin veraltet nach Bereichsaenderung) and GAP-05 (Neue Segmente bekommen keine
Origin) from the 2026-09-14 live UAT of Phase 156 (`156-UAT.md`). Both gaps share exactly ONE
root cause and ONE fix: `theme_segments.origin_release_version_id` is only validated at the moment
`SetThemeSegmentOrigin` sets it, never re-checked or re-derived after the assignment set itself
changes (range sync, segment creation, auto-assignment of new releases). This plan introduces a
single central "ensure valid origin" function, wires it into the three places that mutate
`theme_segment_assignments`, and ships one idempotent repair migration that applies the identical
rule to already-corrupted/missing production rows (proven live: segment 3, 4, 5).

Purpose: restore the invariant "origin is NULL or a currently-assigned release version of the
segment" everywhere, without ever overwriting an already-valid origin (Auftragspunkt 8), and
without ever auto-selecting segment-contributors (only cleanup of now-invalid selections,
Auftragspunkt from Plan 156-12).

Output: `ensureThemeSegmentOriginTx` in a new small file, three call sites wired to it, an extended
`ThemeSegmentAssignmentSyncResult`, migration 0164 (up+down) that repairs existing data, and the
full mandatory test matrix from `156-UAT.md`'s GAP-04/GAP-05 sections plus the SQL/Go rule
equivalence proof.
</objective>

SELECT tsa.release_version_id
FROM theme_segment_assignments tsa
JOIN release_versions rv ON rv.id = tsa.release_version_id
JOIN fansub_releases fr ON fr.id = rv.release_id
JOIN episodes ep ON ep.id = fr.episode_id
