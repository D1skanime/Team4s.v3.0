<objective>
Give admins a clean, validated way to set and correct a segment's `origin_release_version_id`
(P156-06), and surface the current origin through the existing segment read paths so it is visible
at all (P156-18's "Origin sauber setzen ohne unnoetige Pflichtinteraktion" -- setting it is a single
explicit call, never a blocking mandatory step in the existing create/update flow).

Purpose: Plan 156-01's migration adds the column and a deterministic backfill, but origin must
remain administratively correctable per CONTEXT.md ("keine unveraenderliche Momentaufnahme"). This
plan is the write path (with the one piece of new validation logic CONTEXT.md calls for -- "die
Ziel-Release-Version muss dem Segment tatsaechlich zugewiesen sein") plus the read-path plumbing so
`GetAnimeSegmentByID`/`ListAnimeSegments` responses actually carry the current value.
Output: a new repository file, a new admin handler + route, interface/model additions, and
integration + handler tests.
</objective>
