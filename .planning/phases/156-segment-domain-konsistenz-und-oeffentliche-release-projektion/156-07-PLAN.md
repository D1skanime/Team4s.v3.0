<objective>
Rewrite `loadReleaseSegments` to do two things at once, because they are the same code path:
(1) stop deriving segment credits from the VIEWED release's own contributors filtered by a
`strings.Contains(label, "kara")` heuristic, and instead batch-load each segment's ORIGIN release
version's current contributors, filtered by the stable `SegmentCreditRoleCodes` allow-list
(P156-07/P156-08/P156-09); (2) delete `suppressSegmentsAlreadyVisibleOnPreviousEpisode` entirely so
the release page shows every segment actually assigned to it, with range/origin labeling instead of
suppression (P156-13) -- this deliberately supersedes Phase 117's decision D-02 for this one surface,
recorded in `DECISIONS.md`.

Purpose: this is the release-page half of Workstream D/F; Plan 156-06 already did the equivalent
canonical-type work for the project page and Plan 156-05 already extended the shared contributor
loader with role codes -- this plan is where both land on the release-detail page.
Output: rewritten `loadReleaseSegments`, deleted suppression function, extended `PublicReleaseSegment`
DTO, a new `DECISIONS.md` entry, updated integration tests, and (if needed) a split sibling file to
keep `release_detail_public_repository_helpers.go` within CLAUDE.md's 450-line cap.
</objective>
