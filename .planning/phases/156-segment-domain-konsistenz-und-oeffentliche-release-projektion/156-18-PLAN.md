<objective>
Close `156-UAT.md` GAP-07 ("Segment-Mitwirkende automatisch vorauswählen (gespeichert,
abwählbar)"), confirmed by the Auftraggeber on 2026-09-14 ("Ja, auch bestehende"). Today a
newly-relevant segment (e.g. "Buddy Opening 2" on episodes 2/3, or a fresh OP for episode 11)
shows zero names on the public release page until an admin manually ticks every contributor by
hand -- correct per the 2026-09-12 rule ("keine Auswahl = keine Credits"), but needlessly
tedious for segments whose crew is already fully known from the origin release. This plan adds a
REAL, saved preselection: the first time a segment gets a valid origin, every effective
contributor of that origin holding at least one segment-relevant role
(`permissions.SegmentCreditRoleCodes`) is inserted into `theme_segment_contributors` -- exactly
as if the admin had ticked them by hand -- and a new nullable marker
(`theme_segments.contributors_initialized_at`) ensures this happens EXACTLY ONCE per segment,
never again once an admin has curated (or deliberately emptied) the selection.

This closure deliberately reuses the exact codebase philosophy established by Plans
156-12/156-16/156-17: ONE central rule, reused everywhere the underlying event ("this segment's
origin just became valid") already happens. Since Plan 156-16/CR-01, `ensureThemeSegmentOriginTx`
is called from FIVE existing write paths (range sync, `CreateAnimeSegment`'s implicit branch,
release-version auto-assignment, and -- since the CR-01 follow-up fix -- the manual
per-release assign/unassign endpoints too). This plan does not narrow GAP-07 to a hand-picked
subset of those five; it composes preselection with the SAME central function via a new wrapper
(`ensureThemeSegmentOriginAndContributorsTx`) so every one of those five write paths gets the new
behavior uniformly, plus the ONE path that does not use that function at all
(`SetThemeSegmentOrigin`, the manual origin-correction endpoint) gets it wired in directly.
`ensureThemeSegmentOriginTx` itself, and its Plan-156-16 "never auto-insert a contributor" tests,
are left byte-identical -- the new insertion behavior lives entirely in a new, separate file.

Purpose: eliminate needless admin ticking for segments whose crew is already fully known, without
ever compromising the "no selection = no credits" invariant, without ever re-preselecting over an
admin's deliberate curation (including a deliberately emptied selection), and without touching the
public projection code path at all (it already reads only the saved selection).

Output: migration 0165 (schema column + one-time idempotent live backfill, SQL/Go-proven
equivalent to the Go rule), `theme_segment_contributor_preselection.go` (the new central rule),
five call-site swaps plus two direct wiring additions, and a short, optional German hint in the
admin "Mitwirkende am Segment" UI.

**Migration 0165 SQL skeleton** (mirrors `public_effective_contributors.go`'s exact
`release_version_groups`+`anime_contributions` override-precedence join, minus display-only
columns, per the same "membership only" reduction Plan 156-16's migration 0164 already applied to

```sql
ALTER TABLE theme_segments
    ADD COLUMN IF NOT EXISTS contributors_initialized_at TIMESTAMPTZ NULL;

-- RAISE NOTICE counting block (style: Migration 0161/0164) counting: (a) segments with a valid
-- origin, NULL marker, and NO existing theme_segment_contributors rows (to be preselected+marked);
-- (b) segments with a valid origin, NULL marker, and an EXISTING selection (marked only,
-- untouched selection); (c) segments with NULL origin and NULL marker (stay untouched).

WITH targets AS (
    SELECT ts.id AS theme_segment_id, ts.origin_release_version_id AS release_version_id
    FROM theme_segments ts
    WHERE ts.origin_release_version_id IS NOT NULL
      AND ts.contributors_initialized_at IS NULL
      AND NOT EXISTS (SELECT 1 FROM theme_segment_contributors tsc WHERE tsc.theme_segment_id = ts.id)
),
release_context AS (
    SELECT t.theme_segment_id, t.release_version_id, e.anime_id
    FROM targets t
    JOIN release_versions rv ON rv.id = t.release_version_id
    JOIN fansub_releases fr ON fr.id = rv.release_id
    JOIN episodes e ON e.id = fr.episode_id
),
candidate AS (
    SELECT
        rc.theme_segment_id, rc.release_version_id, ac.id AS contribution_id,
        ac.fansub_group_id, ac.member_id,
        COALESCE(ac.release_version_id = rc.release_version_id, false) AS is_override,
        (COALESCE(ac.is_public_on_anime_page = true, false) AND COALESCE(v.name, 'public') = 'public') AS is_public,
        COALESCE(ARRAY_AGG(DISTINCT acr.role_code) FILTER (WHERE acr.role_code IS NOT NULL), ARRAY[]::text[]) AS role_codes
    FROM release_context rc
    JOIN release_version_groups rvg ON rvg.release_version_id = rc.release_version_id
    JOIN anime_contributions ac
      ON ac.fansub_group_id = rvg.fansub_group_id
     AND (ac.release_version_id = rc.release_version_id OR (ac.release_version_id IS NULL AND ac.anime_id = rc.anime_id))
    LEFT JOIN anime_contribution_roles acr ON acr.anime_contribution_id = ac.id
    LEFT JOIN visibilities v ON v.id = ac.visibility_id
    GROUP BY rc.theme_segment_id, rc.release_version_id, ac.id, ac.fansub_group_id, ac.member_id, ac.release_version_id, v.name, ac.is_public_on_anime_page
),
group_override AS (
    SELECT theme_segment_id, release_version_id, fansub_group_id, bool_or(is_override) AS has_override
    FROM candidate GROUP BY theme_segment_id, release_version_id, fansub_group_id
),
effective AS (
    SELECT DISTINCT c.theme_segment_id, c.member_id
    FROM candidate c
    JOIN group_override go ON go.theme_segment_id = c.theme_segment_id AND go.release_version_id = c.release_version_id AND go.fansub_group_id = c.fansub_group_id
    WHERE c.is_override = go.has_override
      AND c.is_public
      AND c.role_codes && ARRAY['translator','timer','karaoke_fx','typesetter','editor','quality_checker']::text[]
)
INSERT INTO theme_segment_contributors (theme_segment_id, member_id)
SELECT theme_segment_id, member_id FROM effective
ON CONFLICT (theme_segment_id, member_id) DO NOTHING;

UPDATE theme_segments
SET contributors_initialized_at = NOW()
WHERE origin_release_version_id IS NOT NULL AND contributors_initialized_at IS NULL;
```
The final bare `UPDATE` covers BOTH group (a) (just preselected above) and group (b) (already had
a selection) in one statement -- idempotent by construction: on a second run, `targets` matches
nothing (every origin-having segment already has a non-NULL marker), so the INSERT and UPDATE both
affect zero rows. The hardcoded role array MUST be proven equal to
`permissions.SegmentCreditRoleCodes`'s current elements by this plan's mandatory equivalence test,
not asserted by comment alone.
