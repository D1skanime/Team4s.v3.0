<objective>
Close `156-UAT.md` GAP-06 ("Segment-Credits mit Segment-Beschriftung"), confirmed by the
Auftraggeber on 2026-09-14. Today the public release-detail page's segment credits show the
unchanged release role (e.g. "Qc · Übersetzung" on segment "op"), but `156-USER-REQUEST.md`
Punkt 11/12 always required a segment-specific German label derived from stable role codes.
Only the role **filter** (`permissions.SegmentCreditRoleCodes`) was implemented so far (Plans
156-07/156-08/156-09/156-12); the **label** never followed. This plan adds the confirmed
Rollen-Code -> Segment-Beschriftung mapping at one central location, projects it through the
existing segment-credit pipeline as a new, additive `SegmentRoleLabel` field, and renders it in
place of the release role -- ONLY inside segment participant display. The normal "An diesem
Release beteiligt" contributor list, the project-member page, and the admin candidate list
"Mitwirkende am Segment" are explicitly out of scope and must stay byte-identical in behavior.

This gap closure directly extends P156-08 (stable-role-code derivation, no label-substring
heuristic, no parallel mapping world) and P156-09 (segmentrelevante Rollen an genau einer
zentralen Stelle definiert, Frontend erhaelt fertig projizierte Credits). No new REQ-ID is
introduced; this plan is tagged with the closest-matching existing requirement IDs.

Purpose: deliver the segment-specific labeling the original order actually asked for, keep the
role-filter list and its label paired at one file so they can never drift apart (a test proves
coverage in both directions), and do so without touching the DB, without touching which
participants appear, and without regressing any other consumer of `PublicReleaseContributor`.

Output: `backend/internal/permissions/segment_credit_roles.go` (new, small, dedicated file --
`permissions.go` must end this plan strictly shorter than its current 950 lines), an additive
`SegmentRoleLabel` field on the shared `PublicReleaseContributor` DTO wired only through the
segment-credit projection path, matching `openapi.yaml`/TS contract updates, and the one-line
frontend rendering swap in `ThemeTimelineSegmentDetails.tsx`.
