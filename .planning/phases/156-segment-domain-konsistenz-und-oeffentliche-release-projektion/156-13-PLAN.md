<objective>
Make the explicit Segment-Contributor selection (Plan 156-12's table) actually control what the
public release page shows, and give admins a way to read/write that selection. Today's projection
(`applySegmentOriginCredits`) shows every role-relevant Origin contributor unconditionally; this
plan changes it to show ONLY the explicitly selected subset, still filtered by
`permissions.SegmentCreditRoleCodes`, still with zero N+1, and fixes the two existing tests whose
old "encoder/QC never appear" assumption is now factually wrong.

Purpose: This is the behavioral core of GAP-01 -- "Origin has QC A/B/C, segment selected only QC
B, only QC B appears publicly" only becomes true once this plan lands.

Output: Updated `applySegmentOriginCredits`, extended query-budget regression test, corrected
`Test5`/`TestSegmentCreditRoleFilter`, a full A-J-plus-K regression matrix (Case K added per the
2026-09-12 UAT Nachtrag: inherited anime-default contributor later overridden/removed at release
level), new admin GET/PUT `.../contributors` endpoints, and a documented confirmation of the
project page's out-of-scope status for this gap.
</objective>

func (r *ReleaseDetailPublicRepository) applySegmentOriginCredits(ctx context.Context, items []PublicReleaseSegment, origins []*int64) error {
	// ... loads contributorsByOrigin via ONE bundled loadPublicEffectiveContributors call ...
	for i := range items {
		originID := origins[i]
		if originID == nil { items[i].Participants = make([]PublicReleaseContributor, 0); continue }
		filtered := make([]PublicReleaseContributor, 0)

			if hasAnySegmentRelevantRole(contributor.RoleCodes, segmentRelevantRoles) {

			}

	}
	return nil
}
