<objective>
Replace the project page's two parallel-truth problems in one function: `attachReleaseTimelineSegments`
today (a) derives segment presence from a raw `start_episode`/`end_episode` range comparison instead
of the canonical `theme_segment_assignments` table, and (b) classifies segment type via a SQL
`CASE ... LIKE '%op%'` heuristic that is a second, independent decision from the same heuristic
`ThemeTimeline.tsx` makes on the frontend (Plan 156-08 removes that side).

Purpose: P156-10/P156-11/P156-12 require the project timeline to read the same canonical assignment
truth as the release page, show a shared segment only once (at first occurrence, project-wide), and
never confuse a member/credit/timing change with a genuine new segment. This plan is the single
backend source of both the assignment-based derivation and the canonical type, reused by Plan 156-07
for the release page.
Output: a new shared `CanonicalSegmentType` helper, a rewritten `attachReleaseTimelineSegments`, an
extended `ReleaseTimelineSegment` DTO, and its first-ever dedicated test file.
</objective>
