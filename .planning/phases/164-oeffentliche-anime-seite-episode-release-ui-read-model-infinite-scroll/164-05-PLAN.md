<objective>
Replace FansubVersionBrowser's current forward-only "Weitere Episoden laden" button + unbounded merge-all
state (D-27..D-39, REQ-164-27..39) with a hand-rolled, bidirectional, bounded-window infinite scroll: a
bottom sentinel auto-loads the next cursor page, a top sentinel auto-restores evicted earlier pages, the
mounted DOM window never exceeds 3 pages, evicted pages become measured-height spacers (no scroll jump),
and a small page-data cache (distinct from the DOM window) avoids re-fetching pages the user briefly
scrolled away from. No virtualization library is added — 164-RESEARCH.md's dependency audit already proves
none is installed and none is needed at this DOM-node scale.

Purpose: This is the phase's structurally riskiest new code (164-PATTERNS.md's "No Analog Found" section
confirms no existing precedent for the spacer/eviction technique) — isolating it into its own hook file
keeps FansubVersionBrowser.tsx's orchestration role thin and testable independent of the visual work already
completed in plan 164-04.

Output: `useWindowedEpisodePages.ts` (the bounded windowing engine + its own unit tests), FansubVersionBrowser.tsx
wired to use it (replacing `dataState`/`loadMoreState`/`loadMore`), and the previously-nonexistent
`FansubVersionBrowser.windowing.test.tsx` proving eviction, restoration, expanded-state stability, and the
directional loading/error/end-of-list UI states.
</objective>

<interfaces>
Existing single-flight abort pattern to extend, not replace (FansubVersionBrowser.tsx lines 161-271,
already read in full during planning): `requestRef = useRef<AbortController | null>(null)`; every fetch
aborts the previous controller, assigns a new one, and checks `requestRef.current === controller` before
committing state. `loadNext`/`loadPrevious` in the new hook must share this same single-flight discipline
(a filter switch aborts any in-flight page load; only the latest request may ever commit state) — do not
create a second independent AbortController owner.

Existing bottom-sentinel precedent to extend (OlderReleasesList.tsx lines 55-63, already read in full):
`new IntersectionObserver(callback, { rootMargin: '200px' })` observing a bottom trigger div. This hook adds
a symmetric top sentinel with the same rootMargin for `loadPrevious`.

Existing cursor/pagination contract (unchanged, Phase 163): `pagination: { has_more: boolean, next_cursor:
string | null, row_limit: number }` per page response. There is no `previous_cursor` field — going backward
means either serving a page already held in this hook's own cache (the common case, since the user only
just scrolled past it) or, if genuinely evicted from the cache too, re-issuing the exact same request that
originally produced that page (this hook must retain each cached page's own request parameters: cursor used
to fetch it, and the resulting episodes/pagination), never inventing a synthetic "reverse cursor".

Existing filter-change reset call site (FansubVersionBrowser.tsx `switchTo`, lines 190-220) already discards
`dataState` completely on every group switch — this hook's `resetForFilter(slug)` method must be called from
`switchTo` in place of the current `setDataState({...})` call, performing the equivalent full reset (empty
cache, empty DOM window, fresh page-1 load) so D-40's "keine Vermischung alter/neuer Resultate" is preserved
without FansubVersionBrowser needing its own parallel reset logic.

Existing `expandedEpisodes: Record<number, true>` state (FansubVersionBrowser.tsx line 134, unchanged by
this plan) is keyed by `episode.episode_id` already — 164-RESEARCH.md Pitfall 4 confirms this is already
safe; this hook must never prune or rekey it, only the rendered page list changes.

LoadingState (extended in plan 164-04 with `compact`), ErrorState, EmptyState (`variant="inline"`) are the
only UI primitives needed for D-36/D-37/D-38 per 164-UI-SPEC.md's "Zustands-Primitive-Zuordnung" — no new
component.
