<objective>
Close GAP-11 (backend half) from `164-UAT.md`: the Canon/Filler and Episodentyp display names must
come from the database, not from two independently hand-maintained (and already-diverging) hardcoded
frontend label maps.

Purpose: The 2026-09-18 live UAT confirmed the admin's own suspicion -- "ich hoffe das wurde nicht
hardcodet sondern kommt aus der DB". `episode_filler_types`/`episode_types` currently only carry a
stable code (`name`); this plan adds a real display-label column to both, backfilled with today's
already-shipped admin labels (the exact strings the Auftraggeber approved 2026-09-18), and exposes
them through the already-existing public read-model JOIN plus one new lean admin lookup endpoint.

Output: Migration 0169 (additive), `publicEpisodeQuery` now emits `filler_type_label`/
`episode_type_label`, and a new `GET /api/v1/admin/episode-classification-options` endpoint the admin
frontend will consume in a later plan (164-13). This plan does NOT touch the frontend hardcoded maps
themselves (`episodeClassification.ts`, `episodePreviewFormat.ts`) -- those are wave-3 consumption
plans that depend on this one.
</objective>
