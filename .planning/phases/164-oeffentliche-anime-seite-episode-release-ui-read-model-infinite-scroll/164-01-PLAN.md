<objective>
Extend the Phase-163 public episode read-model (`publicEpisodeQuery` / `ListPublicGroupedByAnimeID`) so a
single page response carries every field the new episode/release UI needs — filler/episode classification,
container/video codec, and has_images/has_notes/has_karaoke — without adding a single extra query per
episode, release, or group (D-21..D-26, REQ-164-03/04/08/21/22/23/24/25/26).

Purpose: This is the data foundation every later frontend plan in this phase depends on. Per D-43, the
episode-open interaction must cost 0 extra requests — that is only possible if every field the expanded
release preview needs is already in the page-1 response this plan produces.

Output: Extended `PublicEpisodeVersion`/`PublicGroupedEpisode` Go DTOs, extended `publicEpisodeQuery` SQL,
a new small `episode_version_public_flags.go` batched-EXISTS resolver, and updated integration tests that
assert the new, exact per-request query count (3 unfiltered / 4 filtered).
</objective>
