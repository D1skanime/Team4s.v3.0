<objective>
Close the admin-frontend half of GAP-11 from `164-UAT.md`: the Canon/Filler and Episodentyp select
dropdowns in the episode editor must read their option labels from the database (via the new
164-10 endpoint), not from the hardcoded `EPISODE_FILLER_TYPE_OPTIONS`/`EPISODE_TYPE_OPTIONS` arrays
in `episodeClassification.ts` -- those arrays are the exact source the 2026-09-18 migration backfill
copied its label values from, and must now be deleted in favor of the DB.

Purpose: 164-10 shipped a new admin-gated `GET /api/v1/admin/episode-classification-options`
endpoint and the DB columns it reads from; nothing in the admin UI consumes it yet. This plan is the
DB-sourcing half of "Admin und öffentliche Seite lesen die Anzeigenamen aus derselben Quelle"
(164-UAT.md GAP-11) that does not overlap with 164-12's public-page consumption (different files,
independent concern).

Output: `EpisodeClassificationFields.tsx` fetches the options list once (module-level memoized, so
mounting it per-episode-row on a list page never issues more than one network request), and the
hardcoded option/label arrays are deleted from `episodeClassification.ts` (the `EpisodeFillerType`/
`EpisodeType` string-literal types and `EpisodeClassification` interface stay -- only the label
arrays are removed).
</objective>

queries, but the same "don't repeat cheap-to-cache reads" principle applies here for UX/network
cost).
