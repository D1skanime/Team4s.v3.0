<objective>
Replace FansubVersionBrowser's opaque white episode cards and pill/badge/play-button release rows with the
glass, classification-tinted, group-first, text-based release preview specified in 164-UI-SPEC.md (D-01
through D-20, D-48 visual rows 1-19/24-25). This is a pure presentational restyle against the already-
fetched `episodes`/`pagination` props FansubVersionBrowser already receives today, before any infinite-
scroll/windowing engine work (plan 164-05) touches the same file again.

Purpose: Extracts two new presentational components (EpisodeGlassCard, ReleasePreviewRow) and one pure
formatting module out of FansubVersionBrowser.tsx to keep every touched file under CLAUDE.md's 450-line cap
once windowing state is added in the next wave, and to let this plan be reviewed/tested purely on markup
and formatting correctness without any state-machine complexity.

Depends on plan 164-01 (not just 164-02's contract shapes) because this plan renders filler_type,
episode_type, container, video_codec, and has_images/has_notes/has_karaoke — fields whose runtime
correctness (correct values, correct COALESCE fallbacks, correct batched-flag resolution) is only proven by
164-01's actual query/DTO implementation and its integration tests; 164-02 alone only fixes the contract
shape (OpenAPI/TypeScript types), not whether the values arriving at render time are actually correct.

Output: EpisodeGlassCard.tsx/.module.css, ReleasePreviewRow.tsx/.module.css, episodePreviewFormat.ts (pure
helpers + unit tests), FansubVersionBrowser.tsx wired to use both new components in place of its current
inline JSX, LoadingState.tsx's additive `compact` prop, and updated/extended component tests proving the
D-48 visual test matrix's structural claims (tint class per classification, label text, logo/fallback,
date presence/absence, extras presence/absence, Coop rendering, button href correctness).
