Close the remaining request-behavior gates for this phase: filter changes must fully cooperate with the
Wave-3 windowing engine (D-40/41/42, REQ-164-40/41/42), episode expansion must remain a zero-request
client-side toggle now that the windowing engine could theoretically introduce new fetch paths (D-43,
REQ-164-43), the Coop "Zum Release" link's group-selection rule must be pinned down and tested explicitly
(RESEARCH.md Assumption A2), and back/forward navigation from the already-live release-detail page must
restore filter and approximate scroll position using existing browser/Next.js mechanisms only (D-44,
REQ-164-44).

Purpose: This is the phase's race-condition and cross-cutting-correctness closing plan for the frontend —
it proves the windowing engine (164-05) and the visual layer (164-04) genuinely cooperate with the existing
Phase-163 filter mechanism rather than merely coexisting.

Output: Hardened `switchTo`/`resetForFilter` wiring in `FansubVersionBrowser.tsx`, a `resolveCoopLinkGroupId`
helper with unit tests, a bounded scroll-position-hint mechanism for back/forward, and a new
`FansubVersionBrowser.filterSwitch.test.tsx` proving rapid-switch race safety and zero-request expansion.
</objective>
