<objective>
Establish the interface-first foundation for Phase 139's backend work: the new grouped/paginated
Go DTOs every later backend plan (contributions, media, F-01 rights-summary) builds against, and a
disposable per-phase Postgres test harness that can seed real `anime_contributions` /
`release_crew_snapshots` / `episodes` / `release_version_media` rows. No handler or repository
behavior changes here — this plan only adds new, additive Go types and test infrastructure so
Wave 2+ plans have a locked contract to implement against instead of improvising DTO shapes mid-task
(interface-first ordering, per `<task_breakdown>`).

Purpose: prevent the "scavenger hunt" anti-pattern where each of the four downstream backend plans
(139-03 contributions, 139-04 media, 139-05 rights-summary, 139-06 gate) invents its own envelope/
field names, causing drift between what the SQL produces and what the frontend types (139-02) expect.

Output: `backend/internal/models/admin_users.go` gains new struct definitions (existing DTOs
untouched — `AdminUserContributionsResult`/`AdminUserMediaResult`/`AdminContributionItem`/
`AdminMediaItemSummary` stay exactly as-is, since `AdminUserOverview.TotalContributionsCount` and
other existing consumers must not regress, per RESEARCH.md Pitfall 2). `backend/internal/testsupport/
phase139_postgres.go` is a new file mirroring `phase137_postgres.go`'s guard/cleanup conventions but
using the full real migration chain instead of hand-assembled stand-in tables.
</objective>
