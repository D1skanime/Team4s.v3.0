<objective>
Implement the one genuinely novel piece of SQL logic in Phase 139 (per RESEARCH.md Pattern 4 and
Open Question 2): server-side contribution grouping by Anime+Project, standard-equivalent range
collapse over `episodes.sort_index`, and semantic override-vs-project-standard diffing — replacing
`ListUserContributions`'s current unbounded flat fetch. This is a dedicated TDD plan because the
range-collapse/override-diff logic has zero existing SQL precedent in this codebase (the only
reference is `AnimeGroupCard.tsx`'s client-side `buildEpisodeRanges`, explicitly flagged in
CONTEXT.md as visual reference only) and is exactly the kind of defined-I/O business logic TDD
heuristics target.

Purpose: close UADM-02/UADM-03/UADM-04 with real, provably-correct grouping and override detection
— not a cosmetic pagination wrapper around the existing flat query.

Output: a rewritten `ListUserContributions` returning `models.AdminUserContributionsPage`, a new
sibling query file holding the grouping/diff SQL, filter/pagination parsing wired into the
`GetUserContributions` handler, and an integration test suite (RED then GREEN) proving every D02-D10
truth against `testsupport.OpenPhase139Postgres`.
</objective>

<!-- Existing query this plan REPLACES (admin_users_tab_repository.go:149-253, ListUserContributions) -->
Current unbounded flat JOIN chain: anime_contributions -> fansub_groups/anime -> hist_fansub_group_members
  -> anime_contribution_roles -> release_versions -> fansub_releases -> episodes, filtered only by
  `WHERE COALESCE(ac.member_id, hfgm.member_id) = $1`, zero grouping/pagination/filters. This JOIN
  chain already reaches every table needed; extend it, do not start from scratch.

<!-- F-03 root cause this plan's override-diff logic must compensate for
     (release_crew_snapshot_repository.go, ReplaceInTx) -->
ReplaceInTx unconditionally writes snapshot_mode='independent' on ANY save through
PUT /admin/release-versions/:versionId/contributions/effective, regardless of whether the saved
crew set actually differs from the project standard. A non-null release_version_id or
snapshot_mode='independent' is NEVER sufficient proof of a real override (D04) — the diff must be
computed at READ time by comparing (member_id, role_codes set) between the release-version's
anime_contributions rows (release_version_id = X) and the project standard's rows
(release_version_id IS NULL, same anime_id+fansub_group_id).

<!-- Pagination/count pattern to reuse, unchanged (member_claims_list_repository.go) -->
