<objective>
Close F-01's more consequential half: `UserOverviewTab.tsx` (the tab every admin sees by default,
`DEFAULT_DETAIL_TAB = 'overview'`) has the identical eager `Promise.all(getEffectiveRights per
group)` fan-out as the Rights tab, but — unlike the Rights tab, which can reasonably defer to
per-group on-select — the Overview tab must render every group's compact summary simultaneously on
mount (Phase 138 D-05). This requires a genuinely new, batched backend endpoint, not a frontend-only
fix. This plan builds that endpoint with real O(1)-SQL-round-trip batching, reusing Phase 137's
existing pure precedence evaluator with zero semantic change (D21).

Purpose: UADM-06 is not honestly satisfied until BOTH fan-out locations are closed. The external
review package covered only the Rights tab; RESEARCH.md's F-01 correction and the mandatory findings
in the planning context both require this endpoint.

Output: a new `GET /admin/users/:userId/rights-summary` endpoint backed by genuine batch-loading
(existing `GetUserGroupMemberships` now paginated for roles+status, a new
`LoadCurrentOverridesForGroups` query for overrides, a new batched review-grant query for
specialized grants) feeding the existing unexported `evaluateGroupRights` precedence engine via a
new small exported façade — zero new precedence logic, full D21 compliance.
</objective>
