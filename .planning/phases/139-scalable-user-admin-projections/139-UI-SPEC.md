# Phase 139 — UI Design Contract

> Visual and interaction contract for the Contributions tab, Media tab, and Rights/Overview tab
> scale fixes on the existing admin user-detail surface (`frontend/src/app/admin/users/...`).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker. Binding sources: `139-CONTEXT.md`,
> `139-DISCUSS.md` (D01–D27), `139-RESEARCH.md`. The external draft at
> `external-review/ext-139-ui-spec.md` was read and critically evaluated — see "Divergences from
> the External Draft" at the end of this document for every place this contract changes or adds to
> that draft, and why.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not applicable) |
| Preset | not applicable |
| Component library | Team4s in-house `@/components/ui` (no shadcn/Radix/Base UI dependency) |
| Icon library | `lucide-react` |
| Font | Inter (`--font-sans`, `frontend/src/styles/globals.css`) |

**Why the shadcn gate is skipped, not just declined:** `components.json` does not exist anywhere
in the repo, and this is a mature brownfield codebase (138 completed phases) with its own complete,
CLAUDE.md-mandated primitive library at `frontend/src/components/ui/` (`Button`, `Select`,
`FormField`, `Modal`, `Input`, `Textarea`, `Tabs`, `Drawer`, `Card`, `Table`, `Pagination`, `Badge`,
`Switch`, `DatePicker`, `Toolbar`, `SectionHeader`, `EmptyState`, `ErrorState`, `LoadingState`,
`Accordion`, `DisclosureIndicator`, `ActivationStatusIndicator`, …, showcased at `/dev/ui-system`).
CLAUDE.md is explicit and binding: no hand-built native `<select>/<input>/<textarea>/<button>` and
no bespoke markup for a primitive type `@/components/ui` already provides — "local file consistency
does NOT justify deviating from the global design system." Introducing shadcn now would create a
second, competing component system in direct violation of that rule and of `REQUIREMENTS.md`'s
"Zweite Capability-Registry oder paralleles Permission-System" / no-parallel-systems posture that
governs the whole v1.4 milestone. **Decision: `@/components/ui` is this phase's design system.**
Every component named below already exists; Phase 139 adds zero new primitives.

## Spacing Scale

Phase 139 reuses the existing global token scale as-is (`frontend/src/styles/globals.css`) — no new
spacing values are introduced.

| Token | Value | Usage in Phase 139 |
|-------|-------|---------------------|
| `--space-1` | 4px | Icon/badge internal gaps, role-chip row gaps |
| `--space-2` | 8px | Compact inline gaps (meta line separators, chip rows) |
| `--space-4` | 16px | Tab root padding (`padding: var(--space-4)`, existing convention); gap between stacked project/release blocks |
| `--space-5` | 24px | Gap between the toolbar and the first result block; gap above the `SectionHeader` purpose banner |
| `--space-6` | 32px | Not used by this phase's new UI (reserved for larger page-level breaks elsewhere) |
| `--space-7`–`--space-9` | 48/64/80px | Not used by this phase |

Exceptions: none. Every spacing value Phase 139's new markup introduces or sets is a standard
8-point-scale step (4/8/16/24px) — no non-standard step is declared or used by this phase's own CSS.
The `Card` (`nestedFlat`) primitive's own internal padding (`14px 14px 12px`, hard-coded in the
pre-existing `frontend/src/components/ui/ui.module.css`, predating Phase 139 and reused byte-identical
by both the existing `AnimeGroupCard.tsx` and this phase's new project/release blocks) is untouched,
unmodified primitive CSS — not a `--space` token, and not a value Phase 139 sets or overrides. It sits
outside this table's scope for the same reason the Typography contract below excludes pre-existing
primitive type sizes: this table governs only spacing values Phase 139's new bespoke markup actually
introduces, not inherited primitive internals.

## Typography

Phase 139 introduces one **locked, new-component-scoped** contract (exactly 3 sizes, exactly 2
weights) for the new grouped-card/toolbar UI it builds. This does not retrofit the rest of
`ui.module.css`'s pre-existing, more varied inline-style sizes — it is the contract new Phase-139
markup must follow.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 12px | 700 | 1.3 | Filter field labels (`FormField label`), meta lines ("Hochgeladen: …", "Episode 5 · Version 1"), badge text |
| Body | 14px | 400 | 1.5 | Range/status row text, role-chip labels, `SectionHeader` description (tab purpose banner), `EmptyState`/`ErrorState` body |
| Heading | 16px | 700 | 1.25 | Anime title and project/group name inside each grouped Card block |

Only 2 weights are used across the whole new surface: **400 (regular body text)** and **700
(labels, headings, badge text)** — no 500/600 weights are introduced. Where existing shared
primitives (`SectionHeader`, `EmptyState`, `ErrorState`, `Badge`) already carry their own locked
`ui.module.css` sizes, those are reused unchanged rather than overridden — this table governs only
the new bespoke markup (grouped-card headers, range rows, toolbar labels, meta lines) that Phase 139
adds inside `.module.css` files, not the primitives themselves.

## Color

Reuses existing global tokens (`frontend/src/styles/globals.css`) — no new colors are introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg-primary)` (`#f9f9f9`) | Page/tab background |
| Secondary (30%) | `var(--bg-card)` / `var(--color-white)` (`#ffffff`) | Toolbar surface, every grouped `Card` (`nestedFlat`) block |
| Accent (10%) | `var(--color-primary)` (`#5f84dd`) | See reserved list below — the ONLY accent color in this phase's new UI |
| Destructive | `var(--color-error)` (`#dc3545`) | Declared for contract completeness; **not used** by any Phase 139 UI — this phase introduces zero destructive actions (see Copywriting Contract) |

**Accent (`--color-primary`) reserved for, explicitly, and nothing else:**
- The `Button variant="primary"` styling on the single canonical workspace-launch action per block
  ("Release-Medien öffnen"; "Projekt öffnen" where a contribution block links to exactly one
  project).
- The active/current page indicator inside the existing `Pagination` primitive (unchanged,
  primitive-owned styling).
- Inherited link color (`a { color: inherit }`, global — not overridden by this phase).

**Accent is explicitly NOT used for:** status badges (see below), section/card backgrounds, filter
controls, or any "this is important" visual signal outside the three uses above. This prevents the
10% accent from silently creeping into every interactive element, which the design-quality gate
checks for.

**Status badges use their own existing semantic `Badge` variants, not the accent color:**
- `Badge variant="muted"` — "Entspricht Projektstandard" (standard-equivalent range; no real
  deviation).
- `Badge variant="warning"` — "Abweichung vom Projektstandard" (a real, semantically-diffed
  override per D04/D05 — amber `--color-warning`, not accent blue, not destructive red).
- `Badge variant="neutral"` — role chips, media-type chips, project/group name chips.
- `Badge variant="danger"` — reserved for `ErrorState`'s existing icon treatment only; not used as
  a status badge anywhere in this phase's new grouped-card content.

**Focus states** reuse the existing global `:focus-visible` rule (`outline: 2px solid
var(--focus-outline)`, an existing amber/orange token, `globals.css:215-218`) unchanged. Phase 139
does not define a new focus color — this is a deliberate reuse, not an omission.

## Component Inventory — Contributions Tab

**Primary visual anchor:** the anime title inside each grouped `Card` (Heading 16/700, per

lands on per block, ahead of badges, chips, and action buttons.

|---|---|

| Filter bar | `Toolbar` (`leading=` filter cluster, `trailing=` reset `Button` + count `Badge`) |
| Anime filter | `FormField label="Anime"` wrapping `Select`, options populated from the response's bounded `filter_options.animes` (scoped to this one user's contribution history — see "Filter Data Contract" below), not a free-text ID field |
| Projekt/Gruppe filter | `FormField label="Projekt/Gruppe"` wrapping `Select`, options from `filter_options.groups` |
| Beitragsrolle/-typ filter | `FormField label="Beitragsrolle"` wrapping `Select`, options from the existing `useRoleCatalog('anime_contribution')` hook (unchanged source) |
| Nur-Abweichungen toggle | `Switch` label "Nur Abweichungen" (D10) |
| Zeitraum filter | Two `FormField`s ("Von"/"Bis") each wrapping `DatePicker` |
| Reset | `Button variant="ghost"` "Filter zurücksetzen" |
| One project block (pagination unit, D08) | `Card variant="nestedFlat"` |
| Block header | Anime title (Heading 16/700) + `Badge variant="neutral"` project/group name |
| Project standard row (D03, always visible, never accordion-gated) | Plain text row (Label style) + role chips (`Badge variant="neutral"` with `ROLE_CATALOG_CHIP_CLASS`, reusing `AnimeGroupCard.tsx`'s exact chip pattern) |
| Standard-equivalent range row (D06) | One compact row: range label (Body) + `Badge variant="muted"` "Entspricht Projektstandard" |
| Real-deviation row (D04/D05/D06) | One row: range label (Body) + `Badge variant="warning"` "Abweichung vom Projektstandard" + an inline delta line directly beneath it (member/role diff text, Body 14px, **always visible, never behind a click** — see rationale in Divergences) |
| Pagination (project blocks) | `Pagination`, bottom of tab |
| Loading / Error / Empty | `LoadingState` / `ErrorState` (+ retry action) / `EmptyState` (two variants: no-data vs. filtered-to-zero, per Copywriting Contract) |

**Filter Data Contract (informs the planner's endpoint shape, not decided here):** because every
list on this tab is already scoped to exactly one `userId`, the set of anime/groups/roles the
filters need is inherently small and user-bounded — the recommended shape is for the same paginated
list response to carry a `filter_options` object (distinct anime `{id,title}` and group `{id,name}`
pairs the user has ever contributed to), computed server-side in the same query family, so the
filter `Select`s never need a second unbounded search endpoint or a blind numeric-ID `Input` (unlike
the cross-user Claims/Änderungen admin lists, which are unbounded and use plain ID inputs for that
reason — that precedent does not fit here).

## Informational-vs-Actionable Pattern (UADM-07)

One reusable, locked convention — not a new component, not per-tab bespoke text:

**Tab-level posture is stated exactly once, via the existing `SectionHeader`'s `description` prop**,
using one of exactly two copy templates:

- **Informational tabs** (Contributions, Media): `"Informativ — {one-line explanation of what this
  tab shows}. Änderungen erfolgen in {Zielort}."`
- **Actionable tabs** (Rights): `"Aktionsfähig — {one-line explanation of what can be changed here
  directly}."`

**Per-item/per-block actionability is communicated by the action `Button`'s own specific-verb label**
— never a bare "Öffnen", never a separate badge/pill next to read-only content. Every workspace-launch
button uses one of exactly three locked labels, all reused from existing shipped precedent:
"Release-Medien öffnen" (D16), "Projekt öffnen" (`AnimeGroupCard.tsx`), "Gruppe bearbeiten"
(`GroupSection.tsx`).

**Why no new badge/label primitive is introduced:** a floating "read-only" or "actionable" badge
next to every row would be redundant noise once the tab-level posture is already stated once at the
top, and would itself violate the "no bespoke markup for a primitive type already provided" rule if
built as anything other than the existing `Badge`. The design decision is: **state posture once per
tab (SectionHeader), signal per-action specificity through button copy, never repeat a badge on every
row.**

## Responsive / Narrow-Width Behavior (UADM-08, D26)

Desktop-first base styles; graceful degradation via **CSS container queries**, not the admin area's
existing `useIsMobile()`/`matchMedia('(max-width: 759px)')` JS-breakpoint convention. This is a
**deliberate, binding deviation from that D-32 (Phase 138) precedent, scoped only to this phase's
new components** — `139-DISCUSS.md` D26 explicitly mandates CSS/container-query-based degradation,
overriding D-32 for this surface only. Existing `useIsMobile()` call sites elsewhere in `admin/`
(`RoleHoldersTable.tsx`, `ClaimsClient.tsx`, `RoleCapabilityImpactPreviewModal.tsx`, `RolesClient.tsx`)
are explicitly **not** touched or converted by this phase.

Concrete rules:

- Each tab's root list container gets a named CSS container: `container-type: inline-size;
  container-name: admin-user-projection;` (mirrors the existing `@container member-badge-carousel`
  / `@container owner-preview-notice` precedent already shipped in this codebase, proving the syntax
  works without a new dependency).
- **`@container admin-user-projection (max-width: 760px)`**: Toolbar filter fields (`FormField`
  instances) stack to a single full-width column instead of a horizontal row; the reset `Button` and
  count `Badge` move below the filter stack. (760px chosen to visually match the existing 759px value
  used elsewhere in `admin/`, even though the *mechanism* here is a container query, not
  `matchMedia`.)
- **`@container admin-user-projection (max-width: 600px)`**: each grouped `Card` block's header row
  (title + badges) wraps from a single horizontal line to a wrapped/stacked layout; role-chip rows
  wrap freely (`flex-wrap: wrap`); Media-tab thumbnails shrink from 96×96 to 64×64.
- No `Table` primitive is used anywhere in the new Contributions/Media UI — the grouped-card layout
  replaces the current flat `Table`, which structurally removes the "wide mandatory data table"
  overflow risk the draft warned about (no wide table exists to overflow).
- Every header/meta row that combines text + badges uses `flex-wrap: wrap` and `min-width: 0` on its
  flex children — the single most common source of unexpected horizontal overflow in this codebase's
  own CSS history (per `139-RESEARCH.md`'s citation of prior overflow-gate fixes elsewhere).
- `Pagination`'s buttons are native, already-focusable `Button` instances — no new keyboard work is
  required as long as the primitive is reused unmodified.
- All filter controls (`Select`, `Input`/`DatePicker`, `Switch`, `Button`) are native-focusable
  `@/components/ui` primitives; no custom overlay/dropdown may be hand-rolled for any of them (would
  both violate CLAUDE.md's primitive mandate and risk a keyboard trap).
- No page-level horizontal overflow at any supported width is the hard gate (D26) — verified the same
  way Phase 133 verified it (`capturePageMetrics()`/`pageOverflow`/`bodyOverflow` deltas), reused not
  reinvented.

## Explicit Non-Goals (D15/D18/D19/D27 — planner must not scope-creep into these)

- **No new media editor.** The single "Release-Medien öffnen" link-out is the only interaction Media
  blocks offer; no inline edit, upload, delete, or reorder control is added here (D15).
- **No deep storage/technical diagnostics anywhere in these tabs**: no physical file path, no storage
  ID, no derivative-file inventory, no image-size/format analysis, no missing-file health indicator
  (D18). That is explicitly reserved for a later, separate Metabase/reporting idea (D27) — Phase 139
  must not build any version of that dashboard, not even a small one.
- **No `Berechtigung aktiv/fehlt` badge or any badge derived from parsing `owner_context`** — deleted
  outright, not replaced with an equivalent (D19).
- **No raw `release_version:<id>` string ever shown as visible domain context** — always resolved to
  "Anime · Projekt · Episode · Version" text (D19-adjacent rule already stated in `139-CONTEXT.md`).
- **No redesign of Guided Revoke/Grant flows, provenance UX, role-assignment impact modal, or any
  Phase-138-owned rights semantics.** Phase 139 touches only `UserGroupRightsTab.tsx`'s initial-load
  orchestration (D21).
- **No client-side regrouping, filtering, or range-collapsing.** Every filter control writes to a
  server-side query parameter and triggers a refetch; the current `UserMediaTab.tsx`
  `groupByReleaseVersion()` function is deleted, not extended (D23).
- **No Claims/Änderungen/role-capability-matrix redesign** — out of this phase's roadmap scope
  entirely (`139-CONTEXT.md`).

## Divergences from the External Draft

The draft at `external-review/ext-139-ui-spec.md` was read in full and used as one input. This
contract diverges from it in the following specific, load-bearing ways:

1. **Component mapping added.** The draft describes copy and an ASCII projection structure but names
   zero `@/components/ui` primitives. Every structural element in this contract is mapped to a
   specific existing primitive so the plan/executor can build directly against CLAUDE.md's
   primitive-only mandate; nothing in the draft's structure was rejected, it was made buildable.
2. **Deviation delta stays always-visible, never click-gated.** The draft's projection example shows
   the deviation's "[effective user roles / delta explanation]" as a bracketed placeholder without
   specifying disclosure behavior. This contract locks it as **always inline, never behind an extra
   click/accordion** — D06 requires real deviations to "remain individually visible," and gating the
   explanation behind disclosure would undercut that even if the row itself is visible.
3. **Filter inputs locked as `Select`, not free-text/ID `Input`.** The draft lists filter names
   ("Anime filter", "Gruppe/Projekt filter", …) without specifying widget type. This contract locks
   them as `Select` dropdowns fed by a same-payload, user-scoped `filter_options` block — a
   deliberately different choice from the unrelated cross-user Claims/Änderungen admin lists' plain
   numeric-ID `Input` pattern, justified because this data is inherently bounded to one user.
4. **Overview tab's batched rights summary added.** The draft's "Rights scale" section only discusses
   `UserGroupRightsTab.tsx`. `139-RESEARCH.md`'s F-01 finding is explicit that `UserOverviewTab.tsx`
   (the tab admins see by default) has the byte-identical fan-out at a different line, and UADM-06
   requires fixing both. This contract adds the Overview-tab component inventory the draft omitted —
   leaving it out would have left UADM-06 half-solved on the surface admins actually land on first.
5. **Concrete container-query breakpoints and the D26-vs-D-32 deviation are named explicitly.** The
   draft's "Narrow layout" section states behavior qualitatively ("filters wrap/stack") without
   naming a mechanism or values. This contract locks 760px/600px container-query breakpoints and
   explicitly flags that this deviates from the codebase's dominant JS-`matchMedia` admin convention
   — `139-RESEARCH.md` Pitfall 4 called this out as a likely inconsistency risk if left unstated.
6. **Copy standardized for internal consistency.** The draft's Contributions header says "Bearbeitung
   erfolgt in …" while its Media header says "Änderungen erfolgen in …" — two different verbs for the
   same underlying "action happens elsewhere" idea. This contract locks "Änderungen erfolgen in …"
   for both, and additionally locks the "Release-Medien öffnen" copy as the one CTA string (matching
   D16 exactly, replacing the currently-shipped "Arbeitsfläche öffnen" string, which the draft did not
   flag as needing to change).
7. **Non-goals section added.** The draft states rules inline per section but never assembles them
   into one explicit "do not build this" list for the planner. This contract adds that list verbatim
