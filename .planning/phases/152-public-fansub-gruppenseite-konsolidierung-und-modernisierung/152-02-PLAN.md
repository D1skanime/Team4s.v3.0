<objective>
Close the Tiptap link-mark contract drift between the frontend editor and the backend validator (D1),
and tighten two under-constrained sanitizer rules (D2). This is its own independent strand
(critical_sequencing_constraint #5), unrelated to the History/badge migration or the query-budget work.

Purpose: `@tiptap/starter-kit` v3 registers the `link` extension (with `autolink`) by default;
`RichTextEditor.tsx` never disables it. Typing a bare URL therefore silently produces a `link` mark
that `TipTapService.ValidateJSON`'s `allowedTipTapMarks` allowlist (which correctly has no `link`
entry) rejects with HTTP 400 at save time — a real, code-confirmed-but-not-yet-live-reproduced defect
per `152-CONTEXT.md`. D1 requires reproducing the defect as a backend test FIRST (no live UI/admin
login needed), then fixing it on the frontend (the side that actually drifted).
Output: A backend pinning test proving today's correct backend-deny behavior; a frontend fix
(`link: false`) that stops the frontend from ever producing what the backend already rejects; two
sanitizer hardenings (`class` regex on span/td/th, `h1` removal) with rejection tests.
</objective>
