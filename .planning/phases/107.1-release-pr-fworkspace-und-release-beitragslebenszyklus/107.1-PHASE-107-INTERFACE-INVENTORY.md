## Review Service and Transaction Boundary

Primary implementation: `backend/internal/services/review_service.go`.

- Constructor: `services.NewReviewService(starter PointTxStarter, adapters map[string]ReviewTargetAdapter) *ReviewService`
- Delegation methods: `(*ReviewService).GrantDelegation` and `(*ReviewService).RevokeDelegation`
- Decision method: `(*ReviewService).Decide`
- Decision commands and targets: `ReviewDecisionCommand`, `ReviewTargetRef`, `ReviewTarget`, `ReviewDecision`
- Stable decision constants: `ReviewDecisionConfirm`, `ReviewDecisionReject`

`ReviewService` owns the transaction lifecycle through the landed `services.PointTxStarter` interface (`Begin(context.Context) (pgx.Tx, error)`). Repositories and adapters receive the same transaction through `repository.DBTX`, defined in `backend/internal/repository/audit_logs.go` with `Exec` and `QueryRow`. Source adapters must not begin, commit, or roll back a second transaction.

## Adapter Interface and Registry

The exact adapter contract is:

```go
type ReviewTargetAdapter interface {
    LoadForDecision(context.Context, repository.DBTX, ReviewTargetRef) (ReviewTarget, error)
    ApplyDecision(context.Context, repository.DBTX, ReviewTarget, ReviewDecision) error
}
```

The registry is the constructor-provided `map[string]ReviewTargetAdapter`. `NewReviewService` copies the map, and `resolveAdapter` performs exact canonical `ReviewTargetRef.SourceType` lookup. There is no separate global registry type. Phase 107.1 release-note and release-version-media adapters must register distinct stable source types in this existing map.
