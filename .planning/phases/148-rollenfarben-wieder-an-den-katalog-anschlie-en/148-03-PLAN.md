<objective>
Connect the dead `--role-accent` variable in the role-progress badge card (rendered by
`MemberBadgeChain.tsx`'s `roles` carousel branch, styled by `RoleBadgeCard.module.css`) to the
catalog seam, per CONTEXT decision #1 (remove the dead per-code selectors) — this is one of the ten
CSS modules named in ROADMAP's Ausgangsbefund and one of the UI-SPEC's accent-reserved-for
surfaces (item 4). `RoleBadgeCard.stages.module.css` and `RoleBadgeCard.status.module.css` already
only *consume* `var(--role-accent)` with no dead self-assignment, so they need no edit; their
contrast proof already lives in Plan 148-02's extended accessibility test.
`LayeredBadgeArtwork.module.css` is explicitly out of scope and must not be touched (it
intentionally hardcodes its own `--role-accent: #17a7a5`).

Purpose: today `.roleBadgeRow[data-role-code="fansub_lead"] { --role-accent:
var(--role-accent-fansub-lead); }` (and eleven sibling rules) reference tokens that do not exist
anywhere in the repo, so the role-progress card's color is dead for every role. This plan removes
those twelve dead rules and instead lets the card pick up `--role-accent` the same way every other
restored surface does: via a `data-color-key` attribute feeding the `[data-color-key]` derivation
added in Plan 148-02.

Output: `RoleBadgeCard.module.css` with its twelve dead per-code selectors removed;
`MemberBadgeChain.tsx`'s role-card `<Card>` element additionally carries
`data-color-key={presentationForRole(contributionRoles, row.key).colorKey}`; a new behavior test
proving a role with `icon_key: 'other'` (e.g. `fansub_lead`) still renders its own catalog hex via
`data-color-key`, thanks to Plan 148-01's `presentationForRole` decoupling.
</objective>
