<objective>
Remove `FansubAppMembersOverview.tsx`'s own `getRoleClassName()`/`colorClassMap` — a third, broken
color mapping keyed by category-name strings (`'leadership'`, `'creative'`, ...) that
`presentationForRole().colorKey` has not returned since commit `84a38c0f` (it now returns a bounded
hex or `'neutral'`), so this map always falls through to `styles.fansubEditRoleDefault` today (per
ROADMAP Ausgangsbefund) — and instead color those role badges via the same
`ROLE_CATALOG_CHIP_CLASS` + `data-color-key` seam the six working admin surfaces already use
(CONTEXT decision #4). Separately, remove the single dead `--role-accent: var(--role-accent-default)`
self-assignment from the `FansubEdit.module.css` role-toggle selector
(`.fansubEditMemberRoleToggle`, rendered by the *different*, already-correctly-wired
`FansubAppMemberEditorPanel.tsx`), per UI-SPEC's reserved-for list item 6.

Purpose (scope note): `FansubEdit.module.css` also defines a separate `.fansubEditRoleBadge`/
`.fansubEditRoleOption*`/`.fansubEditRoleLead...Default` class family (current lines ~550-630) that
*also* references dead `--role-accent-<code>` tokens, but this family is used only by
`FansubAppMemberAddModal.tsx` and `GroupMembersHistTable.tsx` via their own, independently-correct
role-code-keyed `getRoleClassName()` functions — neither file is named by any CONTEXT decision, and
UI-SPEC's accent-reserved-for list does not include this class family for FansubEdit.module.css
(only the role-toggle and historical-role label are listed). This plan intentionally leaves that
class family untouched and records it as an out-of-scope finding (see Deviations in the SUMMARY),
consistent with the phase's locked scope boundary.

Output: `FansubAppMembersOverview.tsx` with `getRoleClassName`/`colorClassMap` removed, its three
role-badge call sites (member roles, invitation roles desktop, invitation roles mobile) using
`ROLE_CATALOG_CHIP_CLASS` + `data-color-key`; `FansubEdit.module.css`'s role-toggle with its one
dead self-assignment removed; a new behavior test proving the member-role badge now carries the
correct `data-color-key`.
</objective>
