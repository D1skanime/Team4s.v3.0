<objective>
Fix D-03b (Klasse C, 185-CONTEXT.md): the 9-test Phase-134 verification matrix
(TestPhase134MatrixAnonymousPublicProfile, MissingProfile, HiddenProfileIsIndistinguishableFromMissing,
OwnerPreviewOfHiddenProfile, RefreshOnlyOwnerAccess, SparseProfileMatchesManifest,
DenseProfileMatchesManifest, ErrorMalformedSlugDoesNotPanic, PaginationHonestAcrossPages) hard-codes
the Linux host's LAN IP (192.168.235.196) for both the backend base URL and the Keycloak base URL.
Inside a test-runner container attached to the Compose network, that host IP is not reachable,
producing "connection refused". Per D-03, make both addresses environment-configurable (so a
Docker-network-internal address can be supplied when running inside the test-runner container)
while keeping the current host-IP values as fallback defaults so existing manual/local runs are
unaffected.

Purpose: Let the 9-test Phase-134 matrix run inside scripts/test-backend.sh's containerized test
runner without needing host-network access, without breaking any existing manual invocation.
Output: The two base-URL constants become env-overridable vars; provision-phase134-matrix-db.sh
documents/exposes the matching override so both sides can be pointed at the same address.
</objective>
