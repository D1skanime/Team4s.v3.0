<objective>
Close L-02 (RQUE-02's confirmed gap): add the two-signal self-exclusion predicate to
`releaseReviewQueuePredicates` (used by both `List` and `Counts`) so an actor's own
submissions never appear in, or inflate the counters of, their own actionable queue. Add the
new `view=own` scope value (Pattern 2) so "Wartet auf Fremdprüfung" has a real backend data
source with inverted polarity and a capability bypass (D10), reusing the existing
`View`-scoped opaque cursor mechanism unchanged. Correct `List`'s sort direction to match D15
(newest-first, descending) -- confirmed by direct code reading to be ascending today, a real
pre-existing violation of a locked CONTEXT.md decision, not just an untested assumption. Prove
RDEL-05's already-structurally-correct immediacy end to end with a real-Postgres regression
test, add an explicit RQUE-06 regression guard, and give the Counts response an
`allowed_types` field so the frontend's later D10 filter-gating work (Plan 141-06) has an
honest, capability-derived signal to gate on instead of inferring "allowed" from a nonzero
count.

Purpose: this is the core data-correctness work of the phase -- until this plan lands, an
actor's own pending submissions are indistinguishable from others' work in the queue and
counters, directly violating D01/D06, and the queue sorts the wrong direction, violating D15.
`Detail`/`Next`'s equivalent self-exclusion gap (Pitfall 2/3, D04) is deliberately deferred to
Plan 141-03, which depends on this plan's new `ActorAppUserID`/`ActorMemberIDs` fields and
predicate function.

Output: extended `releaseReviewQueuePredicates`, a new `own` view value, corrected
descending sort order, a new handler dependency resolving the actor's verified member IDs
once per request, a new `allowed_types` field on the Counts response, and five new
real-Postgres regression tests.
</objective>
