<objective>
Close UAT-05, the exact mirror-image defect of UAT-02 for media instead of notes: today
`has_own_media`'s EXISTS subquery in `anime_contributions_member_project_repository.go` (lines
150-156) has no join to `release_version_media_review_lifecycle` and applies no `review_state`
filter, unlike its sibling `has_own_notes` subquery (already fixed by plan 143-17) which excludes
`review_state = 'rejected'`. A member whose only contribution to a release is a rejected image
upload still gets `has_own_media=true`, so `isDone()` (`has_own_notes || has_own_media`, unchanged)
returns true and the release shows a false-positive green "Erledigt" — worse than UAT-02's original
bug, since rejected media actively claims the work is finished, and rejected media rows persist
until a 90-day async cleanup job (`backend/internal/services/release_review_cleanup.go`).

This plan does for media exactly what plans 143-17 (backend/contract) and 143-18 (frontend
badge/button) did for notes, in one combined plan: fix the `has_own_media` exclusion, add a new
`has_own_rejected_media` signal through the repository/contract/TS-type chain, and unify the
frontend's `hasOwnArtifacts`/`needsRework` logic to treat a rejected note and rejected media
identically — a release needing rework because of either (or both) artifact types shows exactly one
"Überarbeitung nötig" state, never a precedence puzzle between artifact types.

Purpose: close the exact bug class UAT-02 fixed for notes, for the sibling artifact type (media),
so "Erledigt" never lies about unfinished, rejected work regardless of which artifact triggered it.
Output: repository EXISTS-subquery fix + new subquery + struct field (with proving tests), new
required boolean property in openapi.yaml/contributions.ts, and unified frontend badge/button logic
in page.tsx with regression tests covering the rejected-media-only and both-rejected cases (in a
new sibling test file, since page.test.tsx is already over this codebase's 450-line file cap).
</objective>
