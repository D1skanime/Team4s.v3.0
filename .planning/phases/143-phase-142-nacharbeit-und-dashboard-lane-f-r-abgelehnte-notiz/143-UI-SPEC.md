# Phase 143 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Only Success Criteria 6 and 7 have a UI surface (per the phase brief). Criteria 1-5 are
backend/test remediation with zero visual surface and are out of scope for this document.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — project runs its own hand-built design system under `@/components/ui`, not shadcn. `components.json` does not exist anywhere in the repo. Per `CLAUDE.md` ("Frontend-UI (globales Design-System)"), every user-facing surface MUST use these primitives (`Button`, `Select`, `FormField`, `Modal`, `Input`, `Textarea`, `Tabs`, `Drawer`, `Card`, `Table`, `Badge`, `EmptyState`, `SectionHeader`, …); native `<select>/<input>/<textarea>/<button>` are forbidden wherever a primitive already covers that type. Given this is a mature, actively-enforced in-house system spanning 142 prior phases, the shadcn init prompt was skipped rather than asked — introducing shadcn now would contradict the locked project convention this exact phase is enforcing (ESLint `no-restricted-syntax` -> `error`). |
| Preset | not applicable |
| Component library | custom internal (`frontend/src/components/ui/`), zero external headless/UI library dependency |
| Icon library | `lucide-react` (already used in `AttentionSection.tsx` via `ArrowRight`) |
| Font | `Inter, "Segoe UI", system-ui, sans-serif` (`--font-sans`, `frontend/src/styles/globals.css`) |

Reference/showcase route: `/dev/ui-system` (`frontend/src/app/dev/ui-system/page.tsx`).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (this phase) | No new visible-text CTA button. The interaction is the existing icon-only "open workspace" row affordance (trailing `ArrowRight`, `aria-hidden`) already used by every other Attention-lane item — the new rejected-notes lane follows the identical pattern, not a new button. |
| New dashboard lane — group badge | `Abgelehnt` (Badge `variant="danger"`) — deliberately distinct from the existing `Offen` (`variant="warning"`, used for review-queue items awaiting *someone else's* decision) and `Neu` (`variant="info"`, new assignments). "Abgelehnt" signals this is the user's *own* content that was declined and needs *their* revision — a different semantic than "pending review". |
| New dashboard lane — episode label | `Folge {N}` if `episode_number` is present, else `Release-Version` — reuses the exact fallback string and logic already shipped in `attentionHelpers.ts`'s `presentAttentionContribution` (`Folge ${episode} · ${roleDetail}` pattern), do not invent a new fallback string. |
| New dashboard lane — note title fallback | `Ohne Titel` if the note has an empty/null title — matches the existing `anime_title ?? "Ohne Titel"` fallback convention already used in `attentionHelpers.ts` and `AttentionSection.tsx`. |
| New dashboard lane — row accessible name | `Folge {N} · {Notiztitel} überarbeiten öffnen` as the row `<Link>`'s `aria-label`, since the visible content is the episode chip + title only (no visible verb) and the row shares one link with several sibling rows in the same group card — an explicit `aria-label` disambiguates them for assistive tech (none of the other 3 lanes need this because each of *their* cards has exactly one link). |
| Empty state (shared, unchanged) | Heading: `Nichts Neues im Moment`. Body: `Du hast in den letzten 14 Tagen keine neuen Projekt- oder Release-Zuweisungen erhalten.` — this exact copy is NOT changed by adding the new lane; it must simply also gate on the new lane's data being empty (see Interaction Contract below). Do not add a lane-specific empty state — the whole section already has one shared empty state. |
| Error state (retrofit target, unchanged) | `AnimeProjectTimelineSection.tsx`: `Projektzeitraum konnte nicht geladen werden.` / `Projektzeitraum konnte nicht gespeichert werden.` — copy stays byte-identical; only the inline `style={{ color: 'var(--color-error)' }}` moves into a CSS Module class. |
| Destructive actions this phase | None. Criterion 6 is a pure structural retrofit (no new delete/reject action). Criterion 7 only adds a read/navigate lane; the actual "revise a rejected note" write action already exists on the workspace notes tab from prior phases and is out of this phase's scope. |

| Gesamtdauer | native `<input>` with `onBlur` parse | `<FormField label="Gesamtdauer" htmlFor="duration-seconds" hint="Akzeptiert m:ss, hh:mm:ss, rohe Sekunden sowie Kurzformen wie 2m oder 1m30s. ## Criterion 7 — New Dashboard Lane: Rejected Own Notes

### Where it lives

Inside the existing `AttentionSection.tsx` / `AttentionSection.module.css`, as a **new array of `<li>`
entries appended to the same shared `<ul className={styles.list}>`** that already renders
`pendingGroupMediaReviews`, `pendingReleaseReviews`, `pendingClaims`, and `contributionProjects`. It is
**not** a new sub-section with its own `SectionHeader` — "Braucht deine Aufmerksamkeit" remains the one
heading for all five lanes, matching the existing pattern exactly.

**Locked render order** (top to bottom in the list) — default placement chosen since no upstream
artifact fixes this order; flag for confirmation during planning if this reads wrong once seen live:

1. `pendingGroupMediaReviews` (unchanged)
2. `pendingReleaseReviews` (unchanged)
3. `pendingClaims` (unchanged)
4. **`pendingOwnNoteRevisions`** (new) — grouped by needing *your own* revision, placed after the
   review-others lanes and before new-assignment lanes since it is the most time-sensitive personal
   action (a rejection is stronger than a fresh assignment)
5. `contributionProjects` (unchanged)

### Data shape (frontend consumption contract)

Mirrors the existing `OwnDashboardPending*` naming convention in `frontend/src/types/dashboard.ts`. Field
names below are the UI's consumption contract; the planner/executor own the exact Go DTO but must keep
these fields and this shape (grouped, not flat) since the rendering below depends on it:

```ts
export interface OwnDashboardPendingOwnNoteRevisionItem {
  release_version_id: number;
  episode_number: string | null;
  note_title: string;
}

export interface OwnDashboardPendingOwnNoteRevisionGroup {
  anime_id: number;
  anime_title: string;
  fansub_group_id: number;
  fansub_group_name: string;
  items: OwnDashboardPendingOwnNoteRevisionItem[];
}
```

Added to `OwnDashboardData` as `pending_own_note_revisions: OwnDashboardPendingOwnNoteRevisionGroup[]`
(new `AttentionSection` prop: `pendingOwnNoteRevisions`, defaulted to `[]` exactly like the other three
optional lane props).

Source data per `143-CONTEXT.md` Kriterium 7: `ReleaseVersionNotesRepository.ListReleaseVersionNotesForMember`
already returns `ReviewState`; only `review_state = 'rejected'` rows qualify (never `tombstoned`, which
is already excluded upstream because the cleanup repository soft-deletes tombstoned notes). This phase's
Kriterium-3 repository aggregation is the reuse target — no new handler-level SQL per the phase brief.

### Markup and interaction contract

Unlike the other three lanes, **the group card itself is not a single `<Link>`** — a rejected-notes
group can contain rows pointing at *different* release versions/episodes, so each row is its own link.
This is a deliberate, necessary deviation from the "whole card = one `Link`" pattern used by the other
three lanes; do not force it back into a single-link card, and do not turn the other three lanes into
multi-link cards either — keep both patterns as-is, each fits its own data shape.

```tsx
{pendingOwnNoteRevisions.map((group) => (
  <li key={`own-note-revision-${group.anime_id}-${group.fansub_group_id}`}>
    <Card variant="default" className={styles.itemCard}>
      <div className={styles.noteGroupHeader}>
        <span className={styles.itemTitle}>
          <strong>{group.anime_title}</strong>
          <span> · {group.fansub_group_name}</span>
        </span>
        <Badge variant="danger">Abgelehnt</Badge>
      </div>
      <ul className={styles.noteRevisionList}>
        {group.items.map((item) => {
          const episode = item.episode_number ? `Folge ${item.episode_number}` : "Release-Version";
          const title = item.note_title || "Ohne Titel";
          return (
            <li key={item.release_version_id}>
              <Link
                className={styles.noteRevisionRow}
                href={`/me/releases/${item.release_version_id}/workspace?tab=notes`}
                aria-label={`${episode} · ${title} überarbeiten öffnen`}
              >
                <span className={styles.noteRevisionEpisode}>{episode}</span>
                <span className={styles.noteRevisionTitle}>{title}</span>
                <span className={styles.itemAction}>
                  <ArrowRight size={15} aria-hidden="true" />
                </span>
              </Link>
            </li>
          );
        })}
      </ul>
    </Card>
  </li>
))}
```

### States

| State | Behavior |
|-------|----------|
| Loading | Handled entirely by the parent `/me/dashboard` page's single `LoadingState` — no per-lane loading state, matching the existing three lanes. |
