<objective>
Close the backend/contract half of UAT-02: today, `has_own_notes` correctly excludes a rejected note
(fixed by plan 143-11), but that means the information "this release has a rejected note needing
rework" no longer exists anywhere in the DTO — a release with only a rejected note is
indistinguishable from a release nobody ever touched. This plan adds the missing third signal,
`has_own_rejected_notes`, end to end through the repository, Go struct (which is also this handler's
JSON response body — no separate DTO layer exists), OpenAPI contract, and TypeScript type, WITHOUT
yet changing any frontend rendering (that is plan 143-18's job, which depends on this one).

Purpose: give the frontend a real, tested signal to distinguish "Offen" (never touched) from
"Überarbeitung nötig" (rejected, needs rework) without touching `has_own_notes`'s already-correct,
locked Kriterium-5 semantics.
Output: one new EXISTS subquery + struct field in the repository (with 3 new proving tests), one new
required boolean property in both `openapi.yaml` and `contributions.ts`, and the one existing TS test
fixture factory that constructs `MeProjectReleaseVersion` literals updated so `tsc --noEmit` stays
clean before plan 143-18 lands any rendering change.
</objective>

EXISTS (
    SELECT 1
    FROM release_version_notes rvn
    LEFT JOIN release_version_note_review_lifecycle lifecycle
      ON lifecycle.release_version_note_id = rvn.id

      AND rvn.member_id = $1
      AND rvn.deleted_at IS NULL
      AND (lifecycle.review_state IS NULL OR lifecycle.review_state <> 'rejected')
