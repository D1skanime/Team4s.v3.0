<objective>
Wire the existing Create-page controller to support the Discovery hand-off end to end: auto-adopt a
Jellyfin candidate from a `?jellyfin_id=` query param (reusing the existing, unmodified
`handleJellyfinCandidateAdopt` pipeline, D-08), prefill (never auto-run) the AniSearch search field with the
Jellyfin series name (D-09), branch the post-create redirect between the untouched manual path and the new
assisted path (D-10), and extract/extend the existing AniSearch conflict block into a real
"verbinden"/"neu anlegen" decision that fires at both the AniSearch-selection point (D-02) and the
save-time re-check from 165-03 (D-20).

Purpose: this is the single plan that touches the Create page's central state (`useAdminAnimeCreateController.ts`)
for every Discovery-related concern, avoiding a same-wave file conflict that would occur if this work were
split across two plans. `useAdminAnimeCreateController.ts` is already 1451 lines — over CLAUDE.md's
450-line limit before this plan touches it — so the auto-adopt-once + AniSearch-prefill logic (D-08/D-09)
is built as a new sibling hook file (`useCreatePageDiscoveryHandoff.ts`) that needs zero changes to the
controller itself (it only consumes values/callbacks the controller already exposes); only the D-20
second-trigger 409-handling and the redirect if/else — both of which must live at the existing
`handleCreateSubmit` POST call site — remain as minimal additive edits inside the controller file.
(D-11's other two target pages — the episodes overview and edit pages — are wired in the separate,
dedicated 165-12 plan, kept out of this plan to stay within the 2-3-task-per-plan budget.)
Output: `AniSearchDuplicateDecision.tsx` (new), `useCreatePageDiscoveryHandoff.ts` (new),
`page.tsx`/`useAdminAnimeCreateController.ts`/`createAniSearchControllerHelpers.ts`/
`CreateAniSearchIntakeCard.tsx` extended additively.
</objective>
