<objective>
Implement D-31 (165-CONTEXT.md "Nachtrag nach Live-UAT..."): the AniSearch candidate search currently
FILTERS OUT any candidate that already belongs to an existing Team4s anime
(`anime_create_enrichment.go:~1326-1330`, `filteredExistingCount++; continue`), making the GAP-06/D-30
duplicate-connect decision practically unreachable from the discovery/candidate-search flow — an admin
searching by title never even SEES the already-imported result to select it. Fix: stop filtering; instead
annotate each already-linked candidate with `existing_anime_id`/`existing_title` via the SAME single
batched DB lookup already used for this exact purpose (`ResolveAdminAnimeRelationTargetsBySources`, no
N+1), and surface a "Existiert schon als `<Titel>` (#`<id>`)" hint in the candidate list. Selecting such a
candidate needs NO new frontend branching: `handleAniSearchCandidateSelect` already calls
`loadAniSearchDraftByID` unconditionally, which already calls the backend `Enrich()` endpoint, which
already returns `mode: "redirect"` for a source that's already linked (165-13/D-02) — the
`AniSearchDuplicateDecision` UI (now D-30-compliant after 165-17/165-18) already renders automatically.

Purpose: closes the practical dead-end GAP-08 describes — today, connecting an already-imported AniSearch
entry via the discovery/candidate-search flow requires knowing its exact numeric ID and typing it into the
separate "AniSearch ID" field, since the title-search results never show it at all.
Output: candidates are never hidden; already-linked ones carry visible existing-anime metadata; selecting
one routes to the existing connect decision with zero new logic beyond the hint itself.
</objective>
