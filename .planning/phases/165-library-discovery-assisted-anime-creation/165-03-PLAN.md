<objective>
Close the race window between the AniSearch-selection-time duplicate check (existing `Enrich()`) and the
actual "Speichern" click (D-20): add a guard immediately before `h.repo.CreateAnime(...)` in the
`CreateAnime` handler that re-checks `anisearch:<id>` against `FindAnimeBySource`, and on a hit returns the
same redirect/conflict payload shape the existing `Enrich()` dedup check already returns (reusing
`models.AdminAnimeAniSearchEnrichmentRedirectResult`), instead of silently creating a duplicate anime row.
Add a way for the client to explicitly confirm "create anyway" on a repeated attempt so the same collision
does not surface a third time.

Purpose: 165-08 (frontend Create-Page Integration) renders the existing `AniSearchDuplicateDecision` block
a second time when this guard fires, per UI-SPEC Screen 3's second trigger point. This plan is the backend
half of that contract and can be built/tested independently of the frontend.
Output: `CreateAnime` extended with the D-20 guard; a `confirm_duplicate` request field that lets a second,
explicit "Als neuen Anime anlegen" click bypass the guard.
</objective>
