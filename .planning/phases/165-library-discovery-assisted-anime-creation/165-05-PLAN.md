<objective>
Build the standalone, presentational half of the Discovery hand-off UI before any state wiring happens:
the `DiscoveryEntryCard` (a new, non-destructive CTA on the existing Create page), the reusable
`DiscoveryReturnLink` (used on three different pages later), and the pure `buildAssistedCreateRedirectPath`
helper that computes where an assisted create lands (`/admin/anime/{id}/episodes?return=...` for series,
`/admin/anime/{id}/edit?return=...` for film — the D-01/D-10 film transitional rule: no film-specific UI
exists anywhere in this phase, only a redirect to the existing edit page).

Purpose: Interface-First ordering — 165-08 (Create-Page Integration) and 165-09 (Discovery List Page) both
consume `DiscoveryReturnLink`; defining it as a finished, tested component now means neither later plan has
to guess its props contract mid-implementation. `buildAssistedCreateRedirectPath` is deliberately a new
sibling function, not a modification of the existing `buildManualCreateRedirectPath` — the manual/direct
create flow must remain byte-identical per D-10/D-12 (Test J/K non-regression).
Output: two new components + one new pure helper function, each independently unit-tested.
</objective>
