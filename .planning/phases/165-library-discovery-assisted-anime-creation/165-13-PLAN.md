<objective>
Give `AnimeCreateEnrichmentService.Enrich` a way to say "yes, I know about the AniSearch-ID conflict, load the
real draft anyway" — the missing backend half of the D-23 fix. Today `Enrich` unconditionally returns the
conflict/redirect result the instant `FindAnimeBySource(ctx, "anisearch:"+id)` finds a match (`anime_create_
enrichment.go` ~line 1192-1212); there is no way for a second, explicit "Als neuen Anime anlegen" click to
actually fetch+merge the AniSearch draft — it would just hit the same conflict again. Add a `ForceNew bool`
field to `AdminAnimeAniSearchEnrichmentRequest` (`backend/internal/models/admin_content.go` ~line 132-135)
and gate the existing early return on it, so `ForceNew=true` skips straight to the normal fetch+merge path.

Purpose: 165-08 (frontend Create-Page Integration, same wave) removes the buggy `window.location.href`
auto-redirect that was hiding the AniSearch-conflict decision UI (D-23, live-reproduced with AniSearch-ID
2788 -> Naruto #4) and wires "Als neuen Anime anlegen" to resend the enrich request with `force_new: true`.
Without this plan, that button would be visible but functionally inert — it would just re-trigger the same
conflict response. This plan and 165-08 touch entirely independent files (this plan never touches frontend
code, 165-08 never touches this plan's backend files) and can execute in the same wave without coordination
beyond agreeing on the `force_new` JSON field name, which this file documents for both.
Output: `AdminAnimeAniSearchEnrichmentRequest.ForceNew`, `Enrich()`'s bypass-gated early return, three new
service-level tests proving the default path, the bypass path, and the no-op-on-no-conflict guarantee.
</objective>
