<objective>
Implement D-30 (165-CONTEXT.md "Nachtrag nach Live-UAT..."), which supersedes the "Trotzdem als neuen
Anime anlegen" part of D-02/D-20: an AniSearch ID belongs to exactly one anime
(`uq_anime_source_links_source UNIQUE(source)`, `database/migrations/0047_add_anime_source_links.up.sql:6`)
— a second anime with the SAME `anisearch:<id>` is fachlich unmöglich. The "Trotzdem als neuen Anime
anlegen" option is removed ENTIRELY (not disabled) at both trigger points: the AniSearch-selection-time
conflict (`Enrich()`'s `ForceNew` bypass, introduced in 165-13) and the save-time re-check immediately
before insert (`CreateAnime`'s `ConfirmDuplicate` bypass, introduced in 165-03). Root cause of GAP-06's
observed HTTP 500: `ForceNew`/`ConfirmDuplicate` together let a request reach the actual `INSERT INTO
anime_source_links` with an already-taken `source` value; `syncAnimeSourceLinks`'s `ON CONFLICT (anime_id,
source) DO NOTHING` target does not match the table's SEPARATE, GLOBAL `UNIQUE(source)` constraint, so
Postgres raises an unhandled unique-violation that surfaces as a generic 500.

Purpose: with both bypasses removed, there is no code path left that could reach that INSERT with a
duplicate `source` under NORMAL UI usage — but this plan ALSO hardens `syncAnimeSourceLinks` itself to
convert that specific unique-violation into a typed, cleanly-mapped HTTP 409 (defense-in-depth against any
residual race window between the save-time re-check and the actual insert, and against any future/direct
API caller), per the explicit GAP-06 requirement that saving must NEVER produce a 500 for this case.
Output: `ForceNew`/`force_new` and `ConfirmDuplicate`/`confirm_duplicate` are deleted from the Go request
models, the frontend types, the frontend controller, and the frontend UI (the "Als neuen Anime anlegen"
button); a real-Postgres-tested `syncAnimeSourceLinks` fix; a handler-level 409 mapping; a real-Postgres,
full-HTTP-chain proof that saving with an already-taken AniSearch ID returns 409, not 500, through the
actual `CreateAnime` handler (not a fake repo, not a direct function call to a repo-internal function).
</objective>
