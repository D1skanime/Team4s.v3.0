<objective>
Harden the single "Verbinden"/additive-connect code path (`connectJellyfinFolderAdditively`, shared by the
discovery-duplicate "Mit bestehendem Anime verbinden" action AND the anime-edit-page "Jellyfin-Metadaten
anwenden" resync) against four related 165-UAT.md findings from independent code review and live UAT:

- **GAP-05 (blocker):** the current `additive` decision is based on sniffing whether `anime.source`
  already starts with `"anisearch:"`. For the actual real-world case this feature exists for — an anime
  whose `anime.source` is `jellyfin:<A>` (the normal shape for anime originally created via Jellyfin
  preview/intake, not AniSearch) — connecting folder `B` takes the FORCE-WRITE path instead, silently
  overwriting `anime.source`/`anime.folder_name` with `B` and never inserting `B` into
  `anime_source_links`. The existing test
  `TestConnectJellyfinFolderAdditively_UsesForceWritePathWhenNoAniSearchSource` currently asserts this
  wrong behavior as correct.
- **GAP-13 (minor):** the `jellyfin_discovery.connected` audit event fires unconditionally on every
  successful call, including the routine edit-page metadata resync — which is not a "connect" action.
- **GAP-10 (major):** `LinkAdditionalJellyfinSource`'s `ON CONFLICT (source) DO NOTHING` silently no-ops
  when the folder already belongs to a DIFFERENT anime, yet the handler still returns 200 and writes a
  "connected" audit entry for a mutation that never happened.
- **GAP-12 (minor):** after a successful connect, the admin stays on the create draft with no navigation,
  risking the same draft hitting the (now-hardened, see 165-18) save-time AniSearch conflict again.

The fix for all four is one coherent redesign: introduce an explicit `connect` boolean signal (set only by
the discovery-duplicate "Verbinden" caller) that BOTH decides additive-vs-force-write (GAP-05) AND gates
the audit write (GAP-13) — replacing the fragile source-prefix heuristic entirely — plus an owner-aware
`LinkAdditionalJellyfinSource` that returns a typed conflict error instead of silently swallowing an
ownership mismatch (GAP-10), plus a navigate-away-on-success change in the one frontend caller that sets
`connect: true` (GAP-12).

Purpose: this is the backend/frontend counterpart to 165-18 (removes the OTHER duplicate-handling
bypass, "Trotzdem neu anlegen") — both plans replace ad-hoc, since-proven-wrong heuristics from
165-07/165-13 with explicit, intent-carrying signals.
Output: a `connect`-flag-driven `connectJellyfinFolderAdditively`; an ownership-aware
`LinkAdditionalJellyfinSource`; a corrected/renamed regression test set (fake-repo) PLUS new
`TEAM4S_PHASE165_TEST_DSN`-gated real-Postgres integration tests proving GAP-05 and GAP-10 against actual
SQL constraint behavior (the explicit lesson from this phase's original UAT failure: fake-repo-only tests
hid both bugs); a `connect: true`-sending, post-success-navigating `AniSearchDuplicateDecision`.
</objective>
