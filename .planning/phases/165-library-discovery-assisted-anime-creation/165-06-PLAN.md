<objective>
Compose the Wave-1 building blocks (165-01's snapshot cache/status resolver/cursor, 165-02's ignore
repository) into the actual `GET /admin/jellyfin/discovery` list endpoint, plus the `POST`/`DELETE`
ignore/unignore mutation endpoints with audit-log writes (D-21). This is the plan that proves D-07's ≤1
DB-query-per-page budget end to end and that the existing direct Jellyfin search endpoint remains untouched
(D-12 non-regression).

**D-24 addition (UI-SPEC Update-Durchlauf 2, card-grid correction):** the Discovery list moved from a table
to a card layout (`DiscoveryLibraryCard`, built in 165-09) whose "Typ | Bibliothek" meta-line needs a
`library_context` value per item. This is NOT a new Jellyfin capability and does NOT belong to the
per-library fetch loop in 165-01's snapshot cache (that loop only knows library GUIDs, never human-readable
names) — it is the same purely path-based `deriveJellyfinPathContexts` helper `jellyfin_intake_helpers.go`
already uses for the existing direct-search flow's `AdminJellyfinIntakeSearchItem.library_context`. Because
that helper only runs when a response item is actually built (not when the raw snapshot is fetched), this
plan — which is where `AdminJellyfinDiscoveryItem` response items get built — is the correct, minimal owner;
165-01's snapshot cache/cursor/status-resolver logic is not reopened.

**D-28/D-29 corrections (live walkthrough 2026-09-21):** `buildJellyfinIntakeTypeHint`
(`jellyfin_intake_helpers.go:203-239`), already reused by this plan for the Discovery Type-Hint column, has
a real bug live-verified against the actual Jellyfin-12 instance: its `special`-matching `case` branch only
checks the English spelling, but the live Fansubs library has a folder literally named `Spezial` (German
path segment `Anime.TV-Spezial.Sub`), whose normalized signal contains `"spezial"` but never `"special"` —
so it silently falls through to the `default: "tv"` branch instead of being suggested as `"special"`,
contradicting D-28's explicit requirement. This plan is the correct, minimal owner of the one-line additive
fix (it already reuses `jellyfin_intake_helpers.go` for Test E's "Movie sichtbar" type-hint assertion), and
adds a dedicated regression test covering all eight live Fansubs path segments. The fix is purely additive
(broadens the existing `case`'s match set, changes no other branch) so the pre-existing direct-search flow's
English-language type-hint behavior — and its own test suite — stay green. Separately, the live-measured
Fansubs `Series` count is `TotalRecordCount=2111` (RESEARCH.md §17d), not ~1500 as originally assumed — Test
F's pagination/D-07-budget assertions are extended with a ~2111-item scale fixture (D-29) to rule out O(n²)
traps in the in-memory sort/filter/seek pipeline that a 5-item fixture cannot expose.

Purpose: the read side (list) and the mutating side (ignore/unignore) belong in the same plan because both
consume the same status-priority resolver and both must write/read the same ignore-batch data consistently
within one wave — splitting them would create an artificial dependency without reducing complexity.
Output: two new handler files, a small response-shape models file (now including `library_context`), route
registration, an additive one-line bug fix in the shared type-hint helper (D-28), and a query-count guard
test proving the D-07 budget at both small and production scale (D-29).
