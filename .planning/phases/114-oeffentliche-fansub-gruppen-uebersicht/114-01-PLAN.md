<objective>
Add the smallest additive backend metric ("Anime-Projekte" / `projects_count`) that Phase 114's
public fansub-group directory needs but that `GET /api/v1/fansubs` does not yet expose. This is
the one backend touch this phase performs (per CONTEXT D-03: "kleinstmögliche additive
Ergänzung ... kein Umbau der Gruppen-Domäne").

Purpose: The existing `anime_relations_count` field on `FansubGroup` is NOT a valid substitute —
it counts all `anime_fansub_groups` rows with no `anime.status` filter, while the detail page's
"Anime-Projekte" figure (`profile.projects.length`) is filtered to `a.status <> 'disabled'`
(`listPublicFansubProjects`, `backend/internal/repository/fansub_repository.go:372-374`). Without
this fix, the new directory (Plan 114-03) would show a wrong, inflated number that visibly
disagrees with each group's own detail page.

Output: `FansubGroup.projects_count` present end-to-end (Go struct → SQL aggregate → OpenAPI
contract → TS type), backed by a regression test, and live on the rebuilt Docker backend.
</objective>
