<objective>
Add the one alias-management capability that has zero existing precedent in this codebase: moving an alias from
its current fansub group to a different one on explicit admin action (D-02, D-09). Everything else D-09 needs
(create/delete, permission gate, audit logging) already exists in `fansub_group_aliases.go` — this plan extends
that file with a `ReassignFansubAlias` handler, adds the backing `ReassignAlias` repository method, registers
the route, and — critically — checks permission against BOTH the source and destination group (the IDOR risk
RESEARCH.md's Security Domain identified: a naive implementation would only check the destination).

Purpose: unblocks Plan 08's frontend alias-management UI (which needs this endpoint to exist) and Plan 07's
import-mapping "Trotzdem umhängen" conflict action (D-02).
Output: one new repository method, one new handler + request/validation glue, one new route, one new
httptest+fake test file (the CLAUDE.md-compliant pattern, not the forbidden source-inspection one).
</objective>
