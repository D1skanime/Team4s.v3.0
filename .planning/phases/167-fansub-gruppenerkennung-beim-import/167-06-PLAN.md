<objective>
Close the actual bug D-03 targets: `resolveImportFansubSelection`'s apply-time fallback (`name :=
derefString(mapping.FansubGroupName); if name == "" { name = deriveFansubGroupName(media) }`) currently
re-derives a group name from the filename and silently creates a new `fansub_groups` row via
`upsertImportFansubGroup` whenever a mapping row was submitted with no explicit group selection. This plan
removes that fallback (an unresolved row now stays unresolved, matching Plan 05's "empty stays empty" preview
contract) and, in its place, adds D-01's alias-learning: when the admin's mapping DOES carry an explicit
existing-group selection, the row's own filename-derived kürzel is checked and — if genuinely new and unclaimed
— saved as an additional alias of that group, audited as `fansub_group_alias.learned`.

Purpose: this is the other half of "ich muss das nicht jedes Mal neu zuweisen" — once an admin resolves an
unknown kürzel once, every future import recognizes it automatically via Plan 05's batch matching.
Output: a narrowed, no-longer-auto-creating fallback in `episode_import_repository_release_helpers.go`, a new
alias-learning helper reusing Plan 02's exact-match query inside the apply transaction, an accumulator threaded
up to `EpisodeImportApplyResult`, and a minimal audit-writing addition in Plan 05's new handler file.
</objective>

func resolveImportFansubSelection(
	ctx context.Context,
	tx pgx.Tx,
	mapping models.EpisodeImportMappingRow,
	media models.EpisodeImportMediaCandidate,
) ([]resolvedImportFansubGroup, error) {
	if mapping.FansubGroups != nil {
		return resolveImportFansubSelectionFromInputs(ctx, tx, mapping.FansubGroups)
	}

	if mapping.FansubGroupID != nil && *mapping.FansubGroupID > 0 {
		group, err := lookupImportFansubGroupByID(ctx, tx, *mapping.FansubGroupID)
		if err != nil {
			return nil, err
		}
		return []resolvedImportFansubGroup{*group}, nil
	}

	name := strings.TrimSpace(derefString(mapping.FansubGroupName))
	if name == "" {
		name = deriveFansubGroupName(media)
	}
	parsedNames := parseImportFansubGroupNames(name)
	if len(parsedNames) == 0 {
		return nil, nil
	}

	selectedGroups := make([]models.SelectedFansubGroupInput, 0, len(parsedNames))
	for _, parsedName := range parsedNames {
		nextName := parsedName
		selectedGroups = append(selectedGroups, models.SelectedFansubGroupInput{Name: &nextName})
	}
	return resolveImportFansubSelectionFromInputs(ctx, tx, selectedGroups)
}

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin-submitted apply payload -> alias-learning write | `mapping.FansubGroups`/derived filename candidate are admin-influenced but the admin already had write access to reach ApplyEpisodeImport at all; the risk here is data-integrity (duplicate/incorrect aliases), not privilege escalation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-167-03 | Tampering (data integrity) | `maybeLearnFansubGroupAlias` | mitigate | The pre-insert `resolveFansubGroupMatches` check plus `ON CONFLICT (normalized_alias) DO NOTHING RETURNING id` together make the learn-write race-safe and conflict-respecting: a concurrent apply, or an alias that already belongs to a different group, can never result in a silent reassignment or a duplicate global alias, enforced by the real `UNIQUE(normalized_alias)` constraint, not just application logic. |
| T-167-04 | Repudiation | Alias auto-learn during apply | mitigate | Every learned alias is audited with `ActorAppUserID`, `EventType: "fansub_group_alias.learned"`, and a `source: "episode_import"` payload marker — an admin cannot later dispute that a given alias was system-inferred vs. manually created, since the two paths use distinct event types (`.learned` vs `.created`). |
