# 131-01 — Query-count instrumentation + current-state characterization (Wave 1)

**Requirement:** PMPF-01, PMPF-07 (instrumentation for D-07/SC1). **Depends on:** nothing (measures current behaviour).
**Goal:** A deterministic, reusable way to count the SQL queries a public profile load issues, plus a characterization test that records today's count for both seed members. This is the instrumentation the constant-query-budget gate (131-03) enforces against; it lands GREEN (records reality, asserts nothing it cannot yet meet).

**Steps**
1. Implement a `QueryTracer` (implements `TraceQueryStart`/`TraceQueryEnd`) that increments a counter per query. Attach it via the pool/conn config used in tests (`pgxpool.Config.ConnConfig.Tracer`), so one `GetPublicMemberProfileByID` call's query count is observable.
2. Characterization test: seed one member with a SMALL current-project count and record the query count for a full profile load; log it via `t.Logf`. Assert only a loose upper bound (documents today's ~1+N shape) — do NOT assert constancy yet (that is 131-03, after the batch fix).
3. Document in the test header the exact per-card seam (`loadCurrentProjects` → `loadCurrentProjectReleaseVersions`, `member_profile_projects_repository.go:109`) as the known growth source the constant-budget gate will close.
