# 131-04 — Fully tie-broken stable ordering + honest total (Wave 2)

**Requirement:** PMPF-02, PMCT-06, D-02/D-03 (SC2/SC3). **Depends on:** 131-03 (constant-budget projects path).
**Goal:** Every paginated public list has a deterministic ORDER BY that breaks ties down to a unique key, so offset pages never wobble between loads; and every `total` is computed from the SAME filtered/visible set that yields the rows (never a separately-filtered count).

**Read first:** `131-CONTEXT.md` (D-02/D-03), `backend/internal/repository/member_profile_projects_repository.go` (`loadCurrentProjects` `ORDER BY MAX(ac.updated_at) DESC, a.title ASC, fg.name ASC` L76 — NOT tie-broken; `countCurrentProjects` L122), `backend/internal/repository/member_profile_contributions_repository.go` (`loadLatestContributions` `ORDER BY occurred_at DESC, id DESC` L96 — already tie-broken; `loadPreviousContributions` `ORDER BY MAX(ac.ended_year) DESC, a.title ASC, fg.name ASC` L169 — NOT tie-broken).

**Files**

- MODIFY `backend/internal/repository/member_profile_contributions_repository.go` (previous-contributions ORDER BY + count).
- MODIFY/EXTEND the PostgreSQL tests proving page stability.

**Steps**
1. Add a trailing UNIQUE tie-breaker to every non-deterministic ORDER BY: `loadCurrentProjects` -> append `, a.id DESC` (or the grouped anime_id) after `fg.name ASC`; `loadPreviousContributions` -> append the same unique key. Keep the existing domain sort keys first; the unique key only breaks exact ties. `loadLatestContributions` already ends in `id DESC` (verify, no change).
