proves the ACTUAL SQL (the migration's row shape, the exclusion predicates, the role_kind emission)
behaves correctly against a genuinely migrated Postgres schema — pure-Go fixtures cannot catch a
typo'd column name or a forgotten `AND` clause.

test proving migration idempotency/rollback and effective-rights snapshot equivalence, and three small
repository-layer SQL/DTO changes (role_kind emission + two more picker exclusions) each proven against
the same real database.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser -> Capability Matrix API -> role_definitions | `role_kind` is now derived from a DB column an admin cannot set directly (no UI/endpoint writes `reserved`) |
| App-member-add flow -> role picker endpoint | `ListFansubGroupRoleDefinitions` output gates which role codes an admin can even see to assign |
| Public unauthenticated browser -> role catalog endpoint | `ListPublicRoleDefinitions` is reachable without auth; must not present an internal plumbing role as a real, holdable role |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-145-04 | Information Disclosure | `ListPublicRoleDefinitions` (public, unauthenticated) | mitigate | `AND NOT rd.reserved` keeps the internal pseudo-role out of the public, unauthenticated role catalog — prevents an internal admin-plumbing concept from being presented to anonymous users as a real, holdable fansub role. |
| T-145-05 | Elevation of Privilege | `ListFansubGroupRoleDefinitions` (app-member-add role picker) | mitigate | `AND NOT rd.reserved` removes the reserved role from the picker options an admin (or a scripted client replaying the picker's response) could otherwise submit through the adjacent assignment endpoint. |
| T-145-06 | Tampering | `role_kind` provenance | accept | `role_kind` is read-only, computed server-side from `role_definitions.reserved`; no endpoint in this repository accepts a client-supplied `role_kind` or `reserved` value — low risk, no mitigation beyond the existing platform-admin-gated migration/deploy pipeline is needed. |
</threat_model>
