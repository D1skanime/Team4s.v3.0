<objective>
Restructure the import apply loop's per-mapping error handling so that Plan 03's new guard errors
(`ErrGroupHasDependents`, `ErrReleaseVersionGroupsEmpty`) are caught per-row and marked as a conflict
instead of aborting the entire batch transaction -- reusing the existing, previously-unused
`EpisodeImportMappingStatusConflict` enum value and `EpisodeImportApplyResult.Conflicts` counter
(187-RESEARCH.md Pattern 3) rather than inventing new plumbing. Also resolve D-12's explicit
Prüfauftrag (investigate-and-report, not silently fix) about whether the import reliably recognizes
an existing release today.

Purpose: without this, Plan 03's guard would correctly reject a bad replace but would also abort
every OTHER unrelated mapping in the same apply call -- directly violating D-12's "nur diese Zeile
wird markiert, kein globaler Abbruch".
Output: restructured apply loop, `ConflictDetails` on the result (+ contract/type parity), a
documented D-12 Prüfauftrag finding.
</objective>
