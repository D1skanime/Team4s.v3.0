<objective>
Extract the existing internal `COUNT(DISTINCT rev.id)` query (already computed inside
`GetGroupReleases`'s offset pagination, group_repository.go:165-178) into a standalone,
independently-callable repository method and expose it via a new lightweight endpoint —
so the project page's "Releases" stat (`ProjectStats`) can be answered with exactly one small
count query instead of loading up to 100 full release rows. This is the operator-locked
resolution of RESEARCH.md's Open Question 2: the new count must NOT reuse
`group.stats.episode_count` (which undercounts episodes carrying multiple release versions).

Purpose: P155-07/P155-08 require Counts/Aggregates to come from a dedicated count query, not a
full release list; the operator explicitly rejected the cheaper `episode_count` substitute because
it silently changes the publicly-visible number for any anime with a v2/fix release.
Output: New backend repository method + test proving byte-identical old/new counts for a seeded
multi-version-episode case, new handler method + route, contract parity (OpenAPI, TS type,
api.ts). The frontend loader is NOT wired to call this yet — that is 155-04's job.
</objective>
