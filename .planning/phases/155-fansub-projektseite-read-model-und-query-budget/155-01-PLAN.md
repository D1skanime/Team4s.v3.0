<objective>
Build a narrow, server-side Project Resolver that turns `groupSlug + animeSlug` into
`{groupID, animeID, animeSlug, projects[]}` in one bounded API call backed by 1-2 small,
parameterized SQL queries — replacing the current pattern where three separate pretty routes
each load the ENTIRE public fansub profile (`GetPublicProfileBySlug`, which itself runs a fixed
~8-query set per `fansub_public_profile_query_budget_test.go`) purely to find one project's
numeric IDs. This plan produces the backend contract only; wiring it into the frontend pretty
routes and the project loader happens in later plans (155-04, 155-06).

Purpose: P155-01/P155-02 require that `groupSlug + animeSlug` resolve without a full public
profile load. Auftrag §1 explicitly forbids "vollständiges Public Fansub Profile nur zur
ID-Auflösung" and "Doppelabfrage derselben Profile Projection."
Output: New repository file, new handler file (+ `main.go` wiring), new OpenAPI path/schema, new
frontend type + `api.ts` client function. No frontend page changes yet.
</objective>
