<objective>
Rewrite `loadPublicFansubProjectPageData`'s data-fetching branches to close Workstream D (release
data paths) and Workstream E (non-rendered data) at the source, and add the integration seam the
three pretty routes (Plan 155-06) will use to skip the loader's own redundant public-profile
lookup once they have already resolved everything via the new Project Resolver (Plan 155-01).

Purpose: Auftrag §5/§6 require removing the `per_page:100` offset call (or proving it unneeded)
and removing themes/release-media fetches that have no render consumer. RESEARCH.md additionally
found that `GroupAssetShowcase`'s only real use of the `per_page:100`-sourced `releaseEpisodes`
array (an episode_number -> release lookup for episode asset cards) is ALREADY duplicated,
server-side, inside `getGroupAssets`'s response (`group_assets_handler.go`'s
`buildGroupAssetsPayload` already attaches `release_id`/`episode_id`/`title` onto each
`groupAssetsResponse.data.episodes[]` entry by calling `GetGroupReleases` itself) — so the
frontend's separate `releaseEpisodes` fetch can be removed outright, not just resized.
Output: `projectPageData.ts` no longer fetches themes, release-media, or the offset release list;
`PublicFansubProjectPageData` drops `themesData`, `releaseMediaData`, `hasThemes`, `hasMedia`,
`releaseEpisodes`, and gains `releaseVersionCount: number`; the loader accepts an optional
`precomputed` navigation param.
</objective>
