<objective>
Close GAP-01 and GAP-02 from 137-UAT.md: fix `AdminEffectiveRightsHandler.MutateOverride` so a
post-commit-only failure (target actor re-resolution or `ResolveGroupRights` re-resolution) can
never make an already-committed, successful override write look like a failed HTTP request to the
caller, and make the generic admin/security audit log consistent — written unconditionally for
every successful mutation and for the reject branches that currently write nothing at all
(target-not-active-member, unknown action, non-overridable action, missing reason).

Purpose: `MutateOverride` currently commits the override + immutable history transactionally, then
performs two more reads (`resolveTargetActor`, `ResolveGroupRights`) purely to build the response
and only THEN writes the generic audit entry. If either post-commit read fails, the handler returns
404/500 for an operation that already succeeded and permanently changed state, and the generic
audit log entry for that successful mutation is silently lost (137-REVIEW.md WR-02). Four of five
mapped rejection branches also write no audit entry at all today, leaving BOLA-style probing
attempts (foreign/inactive target, unknown action code) untraceable in the generic admin audit
trail that CLAUDE.md calls out as a project-level observability requirement.

Output: `admin_effective_rights_handler.go` where the HTTP response for a successful mutation is
built entirely from data the mutation service already returned (best-effort enrichment only adds
the computed `effective_right` snapshot, never gates the 200), the generic audit write for success
happens immediately after commit, and all reject branches UAT names are audited too.
</objective>
