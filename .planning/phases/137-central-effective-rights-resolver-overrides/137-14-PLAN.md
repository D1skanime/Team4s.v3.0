<objective>
Close GAP-08 (UAT-137-02) from `137-UAT.md`: the "Logo und Banner" branding section in
`FansubBasicInfoTab.tsx` is currently gated by `canEditMedia = canEditBroad ||
Boolean(capabilities?.can_update_group_media)`, which only `disabled`s the two `MediaUpload`
controls rather than hiding them. Because the backend
(`backend/internal/handlers/fansub_media_upload.go`) checks `permissions.ActionFansubGroupEdit`
(`fansub_group.edit`, i.e. `capabilities.can_edit_group`) for `kind = logo` and `kind = banner` —
not `can_update_group_media` — any role that has `can_update_group_media` but not `can_edit_group`
(`co_leader`, `founder`, `gfxler`, `techadmin`) sees active upload fields that unconditionally 403
on submit. The user's locked decision (137-UAT.md GAP-08) is: rights stay unchanged
(`fansub_group.edit` remains `fansub_lead`/`project_lead`-only); instead the UI must not offer an
action the user cannot perform at all — the branding section is hidden entirely, not just
disabled, for anyone who is neither Platform-Admin nor holds `can_edit_group`.

Purpose: make the Basisdaten-tab branding UI gate exactly match the backend's `fansub_group.edit`
enforcement for logo/banner uploads, so UI and enforcement cannot diverge again, without
introducing any new capability, migration, or resolver change.

Output: a new `canEditFansubBranding` helper in `fansubEditAccess.ts` (colocated with the existing
`canUseMainTab`/`hasFansubWorkspaceAccess`/`canView*`/`canManage*` capability-gating functions),
its unit tests, the wired conditional render in `FansubBasicInfoTab.tsx`, and component tests
proving the section is hidden/shown correctly.
</objective>
