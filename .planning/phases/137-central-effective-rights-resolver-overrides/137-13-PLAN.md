<objective>
Close GAP-07 (UAT-137-01) from `137-UAT.md`: `fansub_group_media.view` is seeded by migration
0109 only to `fansub_lead` and `project_lead`, while migration 0146 (Phase 136) gave `co_leader`,
`founder`, `gfxler`, and `techadmin` `fansub_group_media.upload`/`.update`/`.reorder` without the
matching `.view` grant. This makes the media tab disappear (frontend gate: `canUseMainTab`'s
`case "media"` reads only `capabilities.can_view_group_media`) and the media list 403 for these
four roles, even though they already have write access. The user's binding decision (137-UAT.md) is
a catalog-side fix: a new additive migration (next free number `0151`; `0146` and `0150` stay
untouched) that seeds `fansub_group_media.view` for exactly these four roles, idempotently, with a
matching down migration.

Purpose: extend the "who can edit can also view" semantics that `app_auth.go` already implements
for per-member overrides (`canViewGroupMediaAllowed := canViewGroupMedia.Allowed ||
hasAnyCustomMediaPermission`) to role-capability seeding, so `co_leader` (and the other three
affected roles) can actually reach the media tab/list they already have write rights to.

Output: `database/migrations/0151_fansub_group_media_view_role_defaults.{up,down}.sql`, a new
Go migration-contract/regression test file, and a new frontend regression test proving the tab
gate needs no code change once the capability is seeded.
</objective>
