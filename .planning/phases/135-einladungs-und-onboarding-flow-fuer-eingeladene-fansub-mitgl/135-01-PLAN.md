<objective>
Extend `keycloakAuth.ts`'s existing sessionStorage-based transient-auth-state mechanism with a
`returnPath` (D-04) and `loginHint` (D-01/D-08) option, and wire `/login/page.tsx` to prefer that
persisted returnPath over its URL-based `next` param after a Keycloak callback. This is the shared
foundation both accept pages (`/invitations/accept`, `/claim-invitations/accept`, built in
`135-05`/`135-06`) depend on to survive the full-page Keycloak redirect round-trip without losing
where the user needs to land afterward.

Purpose: Closes the root cause of Pitfall 1/5 from `135-RESEARCH.md` -- the fact that any query
parameter on the original `/login?...` URL is silently dropped once Keycloak redirects back to the
fixed `${origin}/login` callback URL with no query string.
Output: `keycloakAuth.ts` exports `consumeStoredReturnPath()`; `login/page.tsx` consumes it with
correct priority; `login/page.test.tsx` proves the new priority ordering.
</objective>
