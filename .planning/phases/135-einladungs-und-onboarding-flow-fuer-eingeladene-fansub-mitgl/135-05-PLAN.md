<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| URL `email` query param (publicly editable by anyone who has the link) -> `loginHint` prefill | Client-controllable, non-authoritative UX hint only. |
| `returnPath` computed from `window.location.pathname+search` at click time -> persisted via `135-01`'s sessionStorage mechanism | Same-origin write, re-validated on read. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-135-05-01 | Spoofing | `email` query param used as `loginHint` | accept | Purely a UX prefill; `FansubGroupInvitationRepository.Accept()`'s server-side `email_match` remains the sole enforcement (unchanged) -- a spoofed email param can at most mis-prefill a form field, it cannot grant group membership. |
| T-135-05-02 | Tampering | `returnPath` computed and persisted before the Keycloak redirect | mitigate | Consumed only via `135-01`'s `consumeStoredReturnPath()`, which re-validates same-origin / no-`//` / no-`/login`-prefix before use in `router.replace()`. |
| T-135-05-03 | Information Disclosure | `fansubInvitationErrorMessage`'s `email_mismatch` copy | accept | Mirrors the backend's own existing generic wording ("gehoert zu einer anderen E-Mail-Adresse") -- introduces no new account-existence oracle beyond what `Accept()` already returns today. |
</threat_model>
