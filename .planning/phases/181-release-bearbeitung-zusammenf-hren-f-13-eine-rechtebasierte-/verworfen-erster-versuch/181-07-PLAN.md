## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser (any authenticated user) -> `/releases/[versionId]/edit` | the page itself performs no server-side authorization -- all reads/writes still go through the unchanged, already-authorized `getEpisodeVersionEditorContext`/`getReleaseVersionCapabilities`/`updateEpisodeVersion` endpoints |
| `?tab=files`/`?tab=changelog` query manipulation by a non-admin | client-side only -- see mitigation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-181-11 | Elevation of Privilege | `?tab=files`/`?tab=changelog` forced via URL for a non-admin | mitigate | `buildReleaseEditorTabIds` excludes `files`/`changelog` from the `TabItem[]` array entirely for non-admins -- `Tabs`'s own `activeId` fallback (per `Tabs.tsx`) only activates an id present in `items`, so a forced `?tab=files` simply falls back to the default tab; even if rendered, `ReleaseEditorFilesTab`'s only mutating action (`handleScanFolder`/save) is still blocked server-side by the unchanged `isReleaseMetadataOnlyPatch` 403 gate. Documented RESEARCH.md Security Domain pattern, not a new risk introduced here. |
| T-181-01 (carried from Plan 01) | Elevation of Privilege | D-05 sentinel `memberID=0` surfacing through `getMyProjectDetail` into this page's navigation data | accept | This page only ever reads `previous`/`next` release-version IDs/labels from the response to build navigation links -- it never uses the sentinel or `role_codes` for any authorization decision on this page. |
| T-181-04 (carried from Plan 02) | Tampering (Open Redirect) | `return_to` -> `getSafeReturnPath` -> Zurück-Button href | accept | Unchanged, already-mitigated allowlist from Plan 02, reused verbatim here. |
</threat_model>
