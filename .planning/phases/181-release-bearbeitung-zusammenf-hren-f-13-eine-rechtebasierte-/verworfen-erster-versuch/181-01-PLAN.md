<objective>
Fix D-05: `ContributionsMeHandler.GetMyProjectDetail` (`GET /api/v1/me/projects/:animeId?fansub_group_id=:id`)
must stop returning 404 for a platform admin who has no verified `member_claims` row, mirroring the
already-established `GetOwnDashboard` ("D-09-Kontrast") graceful pattern. The real blocker is TWO-part
(per 181-RESEARCH.md Pattern 4 / Pitfall 2): the repository's `JOIN own_roles ON true` makes the whole
query return zero rows whenever `memberID` has no matching `own_roles` CTE row (true for any sentinel
`memberID=0`), so a handler-only fix would just move the 404 one level deeper. Both halves ship together.

Purpose: unblock the merged release-editor page's (later plans) project-context Vor/Zurück navigation for
platform admins without a member profile, and the page itself when loaded in that same scenario.
Output: `LEFT JOIN` repository fix + handler sentinel fix + regression tests at both layers + corrected
404 description text in both API contract files.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-181-01 | Elevation of Privilege | `contributions_me_project_handler.go` sentinel `memberID=0` | mitigate | `memberID=0` is used EXCLUSIVELY to make `GetMemberProjectDetail`'s read-only `own_roles`/role-array query degrade gracefully (empty role_codes); it never participates in any write-authorization decision -- all authorization for this endpoint remains `identity.AppUserID`-derived via `requireMeIdentity`, unchanged by this fix. Regression test `TestGetMemberProjectDetailWithSentinelMemberID` additionally proves the value is not special-cased by magic string match, just a non-matching id. |
| T-181-02 | Tampering | `animeId`/`fansub_group_id` request params | accept | Unchanged pre-existing behavior: both params are validated as positive integers (`strconv.ParseInt`, `badRequest` on failure); the repository's `WHERE a.id = $2` / `fg.id = $3` scoping is unchanged by the LEFT JOIN fix and still returns `ErrNotFound` for a genuinely non-existent combination. |
| T-181-03 | Information Disclosure | `GetMemberProjectDetail` returned `release_versions` for memberID=0 | accept | The returned release-version list is anime/fansub-group-scoped project data (title, episode numbers, dates) already readable by any platform admin through other admin endpoints; no per-member-private fields (notes bodies, uploaded media) are exposed by this query -- `has_own_notes`/`has_own_media` degrade to `false` for the sentinel, they do not leak content. |
