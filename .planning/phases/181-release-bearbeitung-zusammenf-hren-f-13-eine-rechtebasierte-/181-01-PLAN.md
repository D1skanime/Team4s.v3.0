<objective>
Retarget the 5 frontend entry points that currently navigate to `/me/releases/[id]/workspace`
so they open `/admin/episode-versions/[versionId]/edit` instead, each carrying a `return_to`
that matches where the click originated (D-02). Extend the editor's existing `return_to`
allowlist (`getSafeReturnPath` in `EpisodeVersionEditorPage.tsx`) with the two new safe
origins this introduces (`/me/dashboard`, `/me/contributions`), on top of the two patterns it
already accepts. Every retargeted link keeps precisely the visibility condition it has today —
own confirmed `anime_contribution` — per D-04's finding that gating these links behind the
group-wide capabilities used by the admin-side entry points would strand a pure contributor
without any fansub-group role.

Purpose: This is the navigation half of Phase 181's restart — it removes the second, divergent
editing surface (`/me/releases/.../workspace`) from the user-facing click paths without touching
the one surface that survives (the admin episode-version editor, D-01/D-05).
Output: 5 updated hrefs, 1 extended allowlist function, matching test updates.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser URL (`return_to` query param) → editor `backHref` | `return_to` is attacker-visible/attacker-craftable if a user is lured to a hand-built URL containing this app's own origin; the editor turns an accepted value into a same-origin navigation target. |
| Click-time link visibility (frontend) → backend authorization | Which of the 5 links render is a pure UX decision; the real access decision for the destination page is `permissions.CanForReleaseVersion` on the backend (unchanged by this plan). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-181-01 | Tampering | `getSafeReturnPath` (EpisodeVersionEditorPage.tsx) | mitigate | Task 1 adds only two exact-literal-pathname checks (`=== "/me/dashboard"`, `=== "/me/contributions"`), not a wildcard/prefix match; every other value still falls through to `return null`, which the caller already treats as "use the safe computed default" — open-redirect surface stays exactly as narrow as before this plan, now unit-tested with one explicit rejection case. |
| T-181-02 | Elevation of Privilege | The 5 retargeted `<Link>`/`<Button href>` call sites | mitigate | Task 2/3 explicitly keep each link's pre-existing visibility condition (own confirmed `anime_contribution`) and add no new capability check; per D-04's measured finding, the backend `CanForReleaseVersion` check the destination page already runs is identical for both the old and new destination, so no privilege boundary moves — only the link's label text changes, never its gating. |
| T-181-03 | (Supply chain) | n/a | accept | This plan adds zero new npm/pip/cargo dependencies; package legitimacy gate not applicable. |
</threat_model>
