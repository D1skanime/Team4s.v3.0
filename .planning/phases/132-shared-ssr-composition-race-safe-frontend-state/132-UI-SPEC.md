# Phase 132 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope note:** Phase 132 is composition/state, not pixels (see `132-CONTEXT.md` deferred
section). Responsive layout, accessibility polish, image budgets, and visual rhythm are Phase 133.
This contract governs only the interaction surfaces Phase 132 actually touches: local
loading/empty/error/hidden/missing presentations, the progressive-disclosure pattern, the
consolidated viewer/session seam's user-visible effects, and metadata copy. It reuses the
project's existing mature design tokens and `@/components/ui` primitives verbatim — it does not
invent new visual language.

oversight to fix: `.planning/ROADMAP.md` Milestone Constraints and `.planning/REQUIREMENTS.md`

project `CLAUDE.md` mandates the existing `@/components/ui` primitives for all user-facing UI.
Introducing shadcn here would violate both. Registry safety gate: not applicable.

## Spacing Scale

Declared values (project's existing `--space-*` scale in `frontend/src/styles/globals.css`, all
multiples of 4 except the documented 12px exception):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`--space-1`) | Icon gaps, inline padding |
| sm | 8px (`--space-2`) | Compact element spacing |
| — | 12px (`--space-3`) | Icon+label inline gaps (existing exception, keep as-is) |
| md | 16px (`--space-4`) | Default element spacing, section header action gaps |
| lg | 24px (`--space-5`) | Section padding |
| xl | 32px (`--space-6`) | Layout gaps |
| 2xl | 48px (`--space-7`) | Major section breaks |
| 3xl | 64px (`--space-8`) | Page-level spacing |
| — | 80px (`--space-9`) | Hero-level breaks only (existing exception) |

Exceptions: 12px (`--space-3`) and 80px (`--space-9`) are pre-existing project tokens outside the
strict 4/8/16/24/32/48/64 set; Phase 132 reuses them as-is rather than introducing a parallel
scale. New Phase-132 UI (state cards, disclosure toggles, viewer-seam driven toolbar) must use
only the tokens listed above — no ad hoc pixel values.

## Typography

Reuses the project's established type usage (confirmed via `profile.module.css`,
`page.module.css`, `ui.module.css`, `MemberStorySection.module.css`) rather than declaring a new
scale. Phase 132 introduces no new type sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / section copy | 14px | 400 | 1.5 |
| Label / state title (EmptyState, ErrorState, LoadingState `stateTitle`) | ~16px (0.98rem) | 700 | 1.3 |
| Section heading (`SectionHeader` h2/h3) | 20px | 700 | 1.2 |
| Hero display (profile name) | 32px (2rem) | 700 | 1.2 |

Weights used project-wide: 400 (regular body) and 700 (bold — buttons, headings, state titles,
badge labels). Phase 132 work (metadata copy, local state cards, disclosure toggle labels, viewer
toolbar) uses only these two weights; do not introduce 800/900 in new Phase-132 surfaces even
though isolated legacy 800/900 instances exist elsewhere in `profile.module.css` (Phase 133
concern, not touched here).

## Color

Reuses the project's existing warm-neutral token system (`frontend/src/styles/globals.css`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface-canvas` `#f6f4ef` | Page background |
| Secondary (30%) | `--surface-card` `#ffffff` / `--surface-sunken` `#f0ece5` | Cards, section panels, state cards |
| Accent (10%) | `--accent-primary` `#5f84dd` | Primary CTA fill, focus ring tint, links inside empty/loading states, "owner" affordances |
| Destructive | `--button-danger-mid` `#580c22` / `--color-error` `#dc3545` | Error-state icon/text accents only |

Accent reserved for: the primary CTA button (`buttonPrimary`), the focus ring
(`--focus-ring`, `--focus-outline`), the `LoadingState`/info state icon tint, and links/active
states inside the consolidated viewer seam (e.g. owner-preview toolbar action). Accent is never
used for plain body text, section backgrounds, or as a default border color.

Semantic state colors already exist and are reused as-is: `stateNeutral` (empty), `stateDanger`
(error), `stateInfo` (loading) in `ui.module.css` — Phase 132 must use these three existing
`EmptyState`/`ErrorState`/`LoadingState` primitives for every local section state (PMFE-04); no
new ad hoc colored state card is introduced.

## Copywriting Contract

German UI text throughout (per `CLAUDE.md` Sprachqualität — correct umlaute, no ASCII
substitutes). Values below are taken from existing established copy in this codebase
(`MemberStorySection.tsx`, `MemberCurrentProjectsSection.tsx`, `OwnHiddenProfilePreview.tsx`,
`ErrorState.tsx`) and extended consistently for the new Phase-132 surfaces.

| Element | Copy |
|---------|------|
| Primary CTA (paging continuation, e.g. current-projects / contributions) | "Weitere {Projekte/Beiträge} laden" (established pattern from `MemberCurrentProjectsSection.tsx`) |
| Progressive-disclosure expand | "Mehr lesen" |
| Progressive-disclosure collapse | "Weniger anzeigen" |
| Empty state heading (e.g. no story, no projects) | "Noch keine {Geschichte/Projekte/Beiträge} hinterlegt." |
| Empty state body | none required beyond heading, unless a next step exists (e.g. owner-only edit hint) |
| Local section load error (paging/carousel/expansion) | Title: "{Bereich} konnte nicht geladen werden" · Body: "Bitte versuche es erneut." + retry action — do NOT escalate to a whole-page error (PMFE-04, D-05) |
| Whole-page load error (page-level SSR/owner-preview failure) | Title: "Profil konnte nicht geladen werden" (established, `OwnHiddenProfilePreview.tsx` / `page.tsx`) · Action: "Erneut versuchen" |
| Retry action label | "Erneut versuchen" (established) |
| Continuation-load section error (existing exact string, reuse) | "Weitere {X} konnten nicht geladen werden. Bitte versuche es erneut." |
| Destructive actions | None introduced in Phase 132 — no delete/remove UI in scope. If the consolidated viewer seam surfaces any correction/edit entry point, it must link to the existing owner-edit surface rather than perform an inline destructive action. |

Metadata copy (D-08, PMFE-07): `generateMetadata` title/description are composed only from
publicly-permissible facts already in the DTO (fansub display name, top roles, known groups,
active years) — no private facts, no owner-only data. Hidden/noindex profiles keep the existing
neutral noindex metadata (do not reveal existence in title/description).

## Interaction Contract (Phase-132-specific, beyond the template's standard sections)

These are the concrete, testable UI behaviors this phase's design contract governs, tied to the
locked `132-CONTEXT.md` decisions:

- **Distinct state rendering (D-05, PMFE-04):** `hidden` and `missing` remain page-level and
  visually non-distinguishable from each other (existing neutral 404 → `not-found.tsx` path).
  `loading`, `empty`, and `error` render locally per section using the existing `LoadingState`,
  `EmptyState`, `ErrorState` primitives — a failed continuation fetch in one section (e.g.
  current-projects paging) must show that section's own `ErrorState`, leaving the rest of the
  page fully interactive.
- **Progressive disclosure (D-09, PMFE-08):** Long stories and large badge/achievement
  collections use the established clamp + "Mehr lesen"/"Weniger anzeigen" pattern
  (`MemberStorySection`'s `storyContentClamped`/`storyContentExpanded` + mask-image fade,
  `Accordion`/`DisclosureIndicator` for badge groups where applicable). Full content stays
  mounted in the DOM at all times — clamping is visual only (`max-height` + mask), never
  `display: none` or conditional unmount, so assistive tech and SEO see the complete content.
- **Owner/preview affordances:** Any UI surfaced by the consolidated `useMemberViewer` seam
  (e.g. an "Als Owner-Vorschau" indicator, edit entry point) uses the existing `Button` variants
  (`buttonPrimary`/`buttonSubtle`/`buttonGhost`) and existing toolbar patterns in
  `MemberProfileContent.tsx` — no new button style is introduced.
- **No layout/visual rework:** Phase 132 must not change existing spacing, breakpoints, or
  component visual styling beyond what state-consolidation and hook extraction require. Any
  visual delta belongs to Phase 133.
