<objective>
Extract the slug-keyed, cancellable, last-write-wins request pattern already proven twice in this
codebase (`useDebouncedSearch.ts`'s real `AbortController` cancellation and
`useProjectMemberCollection.ts`'s pure dedup-by-key updater) into ONE shared hook, add real
cancellation support to `getMemberProjects`, and wire the fansub-projects continuation ("Weitere
Projekte laden") onto it — replacing its current bespoke `useState`/`try`/`catch` with no
cancellation at all. Also lock the existing progressive-disclosure behavior (story clamp, badge
carousel expand) as a tested contract.

Purpose: PMFE-03 requires paging/carousel/expansion state to be slug-bound, cancellable,
deduplicated, and protected against stale responses. `getMemberProjects` currently has no
`signal` parameter (unlike `getSearch`/`getSearchSuggestions` in the same file), so no consumer
can truly cancel an in-flight continuation request today. PMFE-04 requires a failed continuation
load to show a LOCAL error, not a broken page — `MemberCurrentProjectsSection.tsx` currently
renders a bespoke `<p role="alert">` instead of the shared `ErrorState` primitive UI-SPEC
mandates. PMFE-08 is already implemented once (`MemberStorySection.tsx`'s clamp pattern,
`FocalCarousel`'s full-mount expand) — this plan formalizes it as a locked test contract rather
than re-inventing it.
Output: `useCancellableSlugState.ts` (new shared hook + test), `getMemberProjects` with a
`signal` parameter, `MemberCurrentProjectsSection.tsx` rewired onto the hook with `ErrorState`,
and extended progressive-disclosure regression tests.
</objective>

    - On failure (non-abort error), `state` becomes `{ key: requestKey, status: 'error', data:
      null, error }`; an `AbortError` (the fetch's OWN cancellation, not a stale-response case)
      must NOT set an error state.
    - Unmounting the component aborts any in-flight request (no act()/state-update-after-unmount
      warning).
    - A React 18 StrictMode double-invoke of the hook's effect (mount -> cleanup -> mount) results
      in exactly ONE settled state transition per requestKey, not a duplicated/corrupted one —
      assert this with a test that simulates the double-invoke (mount, immediately unmount via
      cleanup, remount) and checks the final state is correct and only one non-aborted fetch call
      contributed to it.
  </behavior>
