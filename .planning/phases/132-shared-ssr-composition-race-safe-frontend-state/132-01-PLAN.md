<objective>
Add a server-authoritative "known for" aggregate (top roles, known groups, active-year span) to
the public member profile DTO, computed over the member's COMPLETE approved current-project set
(not just the first embedded page), and land it in parity across the Go model, the SQL
projection, OpenAPI, and the frontend TypeScript types.

Purpose: PMFE-11 requires top roles/known groups/totals to derive from the full approved dataset
rather than the first paginated project page. Today `MemberProfileHero.tsx`'s
`deriveKnownForFromPublicProfile` computes this client-side from `current_projects`, which is
capped at 6 rows (documented max 24) — a member with more current projects, or whose top role
only appears past row 6, gets a wrong "Schwerpunkte" display. This plan closes that data-
correctness bug at its source (the backend) so a later plan can make the frontend a pure reader.
Output: `known_for` field on the public member profile response, backed by one new SQL query that
reuses `countCurrentProjects`'s exact filter set, with full Go/OpenAPI/TS contract parity.
</objective>
