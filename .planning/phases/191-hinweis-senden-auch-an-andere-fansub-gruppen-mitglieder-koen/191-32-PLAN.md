<objective>
Close D-31/D-32/D-33/D-34's backend half. Today `related_release_version_id` exists as a reserved,
never-populated column on `fansub_group_hints` (migration 0187) -- the request DTO has no field for
it, nothing validates it, the partial unique index ignores it, and no read path exposes it. This
plan: (1) adds a new migration 0189 that widens the partial unique index to also key on
`COALESCE(related_release_version_id, -1)` so two open hints to different releases of the same
project can coexist (D-32); (2) adds a new, narrowly-scoped validation
(`ensureHintReleaseContext`, D-31) that -- when a client supplies `related_release_version_id` --
confirms the release actually belongs to `related_anime_id` (via its episode) AND that
`target_fansub_group_id` participates in it (`release_version_groups`), mirroring D-23's existing
`ensureAnimeFansubProjectContextExistsInDB` pattern without reusing it verbatim (different join
shape); (3) makes the 409 conflict message text release-scoped vs. project-scoped (D-33); (4) adds
`related_release_version_id`/`related_release_label` to every read path so the three list surfaces
Plan 191-36 will touch have real data to render (D-34's backend half). Because this plan's SELECT/
JOIN/row-struct changes touch the same lines `fansub_group_hints_repository.go` already sits at 448
of 450 lines on, this plan also performs the mandatory split: `AdminHintListFilter`/`HasActiveLead`/
`ListWithoutActiveLead` move out into a new `fansub_group_hints_repository_admin.go`, a pure,
behavior-preserving extraction, before any content change lands.

Purpose: ASVS L1 data-integrity -- the server must never trust a client-asserted
(release, anime, group) triple; D-32's index change is a correctness fix (today a second correction
hint about a different release of the same project is wrongly blocked); D-33/D-34 make the already-
built release link actually visible and understandable to users and reviewers.
Output: a new migration; `ensureHintReleaseContext`; a split, under-450-line repository file;
updated contract; updated backend architecture doc; new and updated tests.
