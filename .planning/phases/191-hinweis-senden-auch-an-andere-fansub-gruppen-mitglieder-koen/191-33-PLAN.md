Backend contract this hook/type file mirrors (Plan 191-32, do not re-derive independently --
these are the literal field names/types the backend actually sends/accepts):
`CreateFansubGroupHintRequest.related_release_version_id?: number | null` (request, optional),
`FansubGroupHint.related_release_version_id: number | null` and
`FansubGroupHint.related_release_label: string | null` (response, always present, null when no

Existing release list API this hook calls, `frontend/src/lib/api/releases.ts:112-133`:
```typescript
export async function getGroupReleaseListCursor(
  animeID: number,
  groupID: number,
  opts: CursorQueryOpts = {},
): Promise<CursorPage<EpisodeReleaseSummary>>
```
`CursorQueryOpts` (`frontend/src/lib/api/history.ts:21-27`) supports `limit`/`sort`/`cursor` among
others. This hook does NOT need to follow pagination cursors -- a single `{ limit: 100, sort:
'release_date' }` call covers every realistic fansub project's release count for a dropdown; do not
build cursor-following logic here (out of scope, no project in this dataset has anywhere near 100
releases for a single group).

`EpisodeReleaseSummary` (`frontend/src/types/group.ts:34-58`), the shape each `CursorPage.data[]`
entry has: `id`, `episode_number: number`, `episode_number_label: string`, `title?: string | null`,
`version_label?: string | null` (plus fields this hook ignores). Per D-29's research, the label
format is: `Episode {episode_number_label} — {title ?? default} · {version_label}` -- when `title`
is null/empty, fall back to `Episode {episode_number_label}` as the title portion (do not render the
literal string "null"); when `version_label` is null/empty, omit the ` · {version_label}` suffix
entirely (do not render an empty trailing " · ").

`CursorPage<T>` type (`frontend/src/types/releaseDetail.ts`, re-exported via
`frontend/src/lib/api/history.ts:14`): `{ data: T[]; next_cursor: string | null; has_more: boolean
}` (read the actual type before using it if the field names above are imprecise -- do not guess if
wrong).
