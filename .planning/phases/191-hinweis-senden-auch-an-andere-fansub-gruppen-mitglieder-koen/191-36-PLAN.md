<objective>
Surface D-31/D-32's release link (Plan 191-32's backend `related_release_version_id`/
`related_release_label`, Plan 191-33's mirrored frontend types) in every place a hint is actually
read: the sender's own "An andere Gruppen" list (`MyProposalsSection.tsx`), the group-scoped
Leader review list (`FansubGroupHintsReviewSection.tsx`), and the platform-wide "ohne aktive
Leitung" list (`FansubGroupHintsAdminClient.tsx`, both its desktop table and its <760px mobile
card). Also closes D-34's explicitly-required side investigation for the UNRELATED, pre-existing
own-group `anime_contributions` path: `MeAnimeContribution` already has an `episode_number` field
(`frontend/src/types/contributions.ts:99`, from an earlier phase's per-episode contribution
feature) that `MyProposalsSection.tsx`'s `renderProposalCard` never displays -- this plan adds that
display too, confirming and implementing D-34's schema-free condition rather than silently skipping
it.

Purpose: a release link only the database and the API response know about is worthless to the
humans who actually decide/track hints -- Leaders and Plattform-Admins need to see WHICH release a
correction is about, and senders need to see what they actually submitted.
Output: release labels visible in all three fansub_group_hints surfaces and (schema-free) the
own-group proposal cards; a frontend architecture doc note for future consumers.
</objective>
