**Second-round correction (this revision):** the first version of this plan's Task 2 had the
prefilled foreign-group case still rely on the existing `loadGroupAnime` effect to resolve the
project, which (per Plan 191-15/D-10) needs `foreignGroup.slug` to call
`getPublicFansubProfileBySlug` -- exactly the network path D-10 had to fix because the sender has
no membership-gated access to the target group. Reusing it here for the main D-12 use case (a
member reporting a problem on a project of a group they do NOT belong to) would reintroduce that
same bug. The fix below avoids the network round-trip entirely for the prefill case: the project is
already known from `prefill.animeId`/`prefill.animeTitle`, so it is set directly instead of being
"found" in a freshly loaded list, and no slug is ever required.
