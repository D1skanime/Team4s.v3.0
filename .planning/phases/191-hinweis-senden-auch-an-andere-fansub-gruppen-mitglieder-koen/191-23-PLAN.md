<objective>
Wire Plan 191-22's new `GET /api/v1/me/fansub-group-hints` endpoint into `/me/contributions`
(D-18's frontend half): the sender of a correction hint to a foreign group can now actually see it
listed, with status and rejection reason, under "Eingereichte Hinweise" -- extending (not
replacing) the existing `anime_contributions` proposal list. Without touching the already-executed
plans 191-01 through 191-19.

Purpose: D-18 is a real UX gap confirmed in the fourth Live-UAT round -- a sent hint to a foreign
group is currently invisible to its own sender anywhere in the product. This plan also extracts
the existing `hintStatusLabel`/`hintStatusVariant` helpers (already built for the platform-admin
list in Plan 191-09/191-12) into one shared module, following the exact "single source, no
duplicate copy" precedent Plan 191-17 already set for `isEligibleForContributions` -- rather than
either importing across the `app/admin/...` route boundary or re-implementing the same status
mapping a second time.
Output: `/me/contributions` shows a member's own sent hints to foreign (and own) groups, correctly
counted and labeled, with a status-mapping helper shared between this list and the existing
platform-admin list.
</objective>

export function hintStatusLabel(status: FansubGroupHintStatus): string {
  switch (status) {
    case 'open': return 'Offen'
    case 'acknowledged': return 'Bestätigt'
    case 'rejected': return 'Abgelehnt'
    default: return status
  }
}
export function hintStatusVariant(status: FansubGroupHintStatus): 'warning' | 'success' | 'danger' | 'neutral' {
  switch (status) {
    case 'open': return 'warning'
    case 'acknowledged': return 'success'
    case 'rejected': return 'danger'
    default: return 'neutral'
  }
}
