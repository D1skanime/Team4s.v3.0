<objective>
Create the new `fansub_group_hints` table (migration 0187) and the Go repository that owns its
CRUD/list operations. This is the data-model foundation for Phase 191: a member can send a hint
(correction or membership-request) to ANY fansub group (D-02), the Leader-of-target-group vs.
Plattform-Admin routing split (D-01/D-07) reads from `requested_role_code`, double-hint spam is
blocked by a DB-level partial unique index (D-04(1)), and no capability/role is invented (D-06).

Purpose: give every later plan in this phase (Create-handler, Leader-review, Plattform-Admin-review)
a single, already-tested persistence layer so none of them re-derives the schema or the
conflict-mapping rules.
Output: `database/migrations/0187_fansub_group_hints.{up,down}.sql`,
`backend/internal/repository/fansub_group_hints_repository.go`, a Phase-191 Postgres test fixture,
and repository tests against a real Postgres instance (teststil rule: no handler exists yet to
test through, so this plan tests the repository directly against real SQL — httptest/Fake-Repo
tests for the handler layer land in Plan 191-03/04/05 once the handlers exist).
</objective>
