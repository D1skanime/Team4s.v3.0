<objective>
Implement the member-facing "send a hint" endpoint (`POST /api/v1/me/fansub-group-hints`) and the
daily rate-limit it needs (D-04(2): ~10/person/day), reusing the existing Redis fixed-window
limiter instead of building a new mechanism. This is the Create half of D-06's "two hint types, no
new capability" — Confirm/Reject land in Plans 191-04/191-05.

Purpose: let a member send a correction-hint or membership-request to ANY fansub group (D-02's
backend half was already proven at the repository layer in Plan 191-01; this plan proves the HTTP
layer does not reintroduce `MemberBelongsToFansub`-style ownership gating).
Output: working, tested `POST /api/v1/me/fansub-group-hints`; a reusable AppUserID-keyed rate-limit
middleware variant.
</objective>
