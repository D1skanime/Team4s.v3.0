# GSD Phase 127 – Besondere Auszeichnungen kompakt in den bestehenden Member-Header integrieren

## Ausgangslage

Die Badge-Darstellung des öffentlichen Memberprofils wurde in den vorherigen Phasen fachlich bereinigt und auf passende Präsentationsmuster umgestellt.

Bereits umgesetzt:

### Phase 121 – Rollen-Badges

- echtes `FocalCarousel` zwischen verschiedenen Rollen
- große Rollen-Hero-Darstellung
- Rank-Track für:
  - Einstieg
  - Bronze
  - Silber
  - Gold
  - Platin
- Wide-Desktop-Layout
- responsive Mobile-Darstellung
- korrigierte Badge-Geometrie
- funktionsfähiger Expanded-/„Alle anzeigen“-Modus

### Phase 123 – Anime-Projekte

- äußeres Ein-Karten-Carousel entfernt
- responsive Single-Family Achievement Stage
- Hero links / Informationen rechts auf Desktop
- gestapelte Darstellung auf Mobile
- Meilenstein-Track
- Fortschrittsanzeige

### Phase 124 – Punkte-Meilensteine

- äußeres Ein-Karten-Carousel entfernt
- Single-Family Achievement Stage
- sechs visuell unterschiedliche Stufen
- visueller Thumbnail-Track
- Vorschau früherer verdienter Stufen
- Touch-/Swipe-Verhalten auf Mobile

### Phase 125 – Beitragsbadges

- äußeres `FocalCarousel` bleibt für die drei fachlich unterschiedlichen Beitragsfamilien
- Bronze/Silber/Gold innerhalb der Familie als visuelle Stufen
- klare Trennung zwischen äußerem Familienwechsel und innerer Stufenauswahl

### Phase 126 – Mitgliedschaft

- `Gründungsmitglied` fachlich von 5/7/10 Jahren getrennt
- Membership Stage
- Gründungsmitglied bleibt eigene historische Mitgliedschaftsauszeichnung
- Gründungsmitglied kann als Hero-Vorschau betrachtet werden
- 5/7/10 Jahre bilden weiterhin ausschließlich die Dauerprogression

Damit bleiben als letzte bisherige Badge-Gruppe die **Besonderen Auszeichnungen**.

Aktuell relevant:

- `historical_leader` – Historische Leitung
- `all_rounder` – Allrounder
- `verified` – Verifiziert

Diese Badges sind keine Progressionsfamilie.

---

# 1. Ziel von Phase 127

Die besonderen Auszeichnungen sollen nicht mehr in einer eigenen großen Carousel-/Achievement-Sektion dargestellt werden.

Stattdessen sollen sie kompakt in den bereits bestehenden öffentlichen Member-Header integriert werden.

Der vorhandene Header ist bereits visuell stark und enthält unter anderem:

- großes Hintergrund-/Bannerbild
- Avatar
- Member-Typ
- Membername
- Verifiziert-Status
- Aktiv-Status
- Punkte
- Profilbeschreibung
- „Aktuell aktiv seit …“
- Schwerpunkt / Rolleninformation

Das Ziel ist deshalb ausdrücklich **keine weitere große Kartenreihe im Header**.

Die Specials sollen kompakt als Teil der Profilidentität erscheinen.

---

# 2. Bestehender Header ist verbindliche Grundlage

Der aktuelle Member-Header soll nicht neu erfunden werden.

Seine bestehende visuelle Struktur bleibt grundsätzlich erhalten.

Aktuell ungefähr:

```text
FANSUB-MEMBER

CSubs Leader   [Verifiziert] [Aktiv]

Punkte
2733

Ich bin der Leader von C-Subs ...

Aktuell aktiv seit 2002

Schwerpunkte: Übersetzung
````

Phase 127 ergänzt diesen Header um einen kleinen Bereich für besondere Auszeichnungen.

---

# 3. Zielposition im Header

Bevorzugte Position:

direkt unterhalb der bestehenden Profilinformationen, insbesondere unter:

```text
Schwerpunkte: Übersetzung
```

Beispiel:

```text
Schwerpunkte: Übersetzung

Auszeichnungen:
[ Historische Leitung ] [ Allrounder ]
```

oder:

```text
Besondere Auszeichnungen
[ Historische Leitung ] [ Allrounder ]
```

Die genaue Position anhand der aktuellen DOM-/CSS-Struktur so wählen, dass:

* der Membername dominant bleibt
* die Beschreibung nicht verdrängt wird
* der Header nicht unnötig höher wird
* die Specials wie ein Teil des Profils wirken und nicht wie eine zweite Sektion

---

# 4. Verifiziert NICHT doppelt anzeigen

Sehr wichtig:

`Verifiziert` ist im aktuellen Header bereits direkt neben dem Membernamen sichtbar.

Beispiel:

```text
CSubs Leader   [Verifiziert] [Aktiv]
```

Deshalb darf Phase 127 nicht zusätzlich eine zweite Special-Auszeichnung:

```text
[ Verifiziert ]
```

unter „Besondere Auszeichnungen“ anzeigen.

Das wäre redundant.

Regel:

* bestehender Header-Verifiziert-Status bleibt erhalten
* `verified` darf im alten Special-Badge-Pfad entfernt werden
* genau eine sichtbare Verifiziert-Darstellung im Header

---

# 5. Im neuen Special-Bereich zunächst nur eigenständige Specials

Für die aktuelle Datenlage sollen im neuen Header-Special-Bereich insbesondere dargestellt werden:

## Historische Leitung

Code:

```text
historical_leader
```

Bedeutung:

* historische Führungsrolle
* ehemaliger Fansub-Leader beziehungsweise Gründerkontext gemäß bestehender Badge-Logik

Asset:

```text
special-historical_leader-v1.png
```

---

## Allrounder

Code:

```text
all_rounder
```

Bedeutung:

* mindestens drei unterschiedliche Rollen in bestätigten Anime-Beiträgen

Aktuelle Darstellung:

* bestehendes Hexagon-/Lucide-Icon
* kein eigenes PNG-Asset

# 6. Gründungsmitglied bleibt NICHT im Header-Special-Bereich

`founding_member` wurde in Phase 126 bewusst als:

```text

```

innerhalb der Membership Stage belassen.

Es darf deshalb nicht zusätzlich im Header auftauchen.

Keine Doppelung.

# 7. Rollen ohne Badge-System bleiben getrennt

Nicht als Special behandeln:

* `fansub_lead`
* `techadmin`
* `gfxler`

Das sind Rollen beziehungsweise Rollencodes, keine eigenständigen Special Achievements.

Nicht in den Header-Special-Bereich aufnehmen.

# 8. Keine große Card-Darstellung

Der Header darf nicht mit mehreren großen Achievement-Karten überladen werden.

Nicht:

```text
[ große Historical-Leader-Card ]
[ große Allrounder-Card ]
```

Bevorzugt kompakte Elemente.

Beispiel Desktop:

```text
Besondere Auszeichnungen

[Artwork 40px] Historische Leitung     [Icon 40px] Allrounder
```

oder als kompakte Chips/Cards:

```text
[ ◉ Historische Leitung ] [ ⬡ Allrounder ]
```

Die konkrete Gestaltung soll sich an den bestehenden Header-Oberflächen orientieren.

# 10. Mobile

Auf Mobile muss der Header weiterhin übersichtlich bleiben.

Kein horizontaler Scrolltrack für nur ein oder zwei Specials.

Bevorzugt:

```text
Besondere Auszeichnungen

[ Historische Leitung ]
[ Allrounder ]
```

oder zwei kompakte Elemente nebeneinander, wenn die Breite reicht.

Anforderungen:

* sauberer Umbruch
* kein Seitenoverflow
* keine sichtbare Scrollbar
* keine überlangen Chips
* Header bleibt lesbar
* Navigation wird nicht verdrängt

---

# 11. Tablet

Bei 768/1024 px:

* Specials dürfen nebeneinander stehen, wenn ausreichend Platz vorhanden ist
* ansonsten sauber umbrechen
* Banner, Avatar, Name und zentrale Profilinfos bleiben dominant

---

# 12. Normalisierter Artwork-/Icon-Slot

Historische Leitung verwendet ein PNG.

Allrounder verwendet ein Icon.

Beide sollen trotz unterschiedlicher Quelle visuell gleichwertig erscheinen.

Daher einen stabilen kompakten Slot verwenden.

Beispielrichtung:

```text
32–48 px visuelle Fläche
```

abhängig vom aktuellen Headerlayout.

Nicht als harter Wert erzwingen, wenn bestehende Größenvariablen besser passen.

Anforderungen:

* PNG proportional
* `object-fit: contain`
* Icon sauber zentriert
* keine Verzerrung
* kein Layout Shift
* Historical Leader nicht riesig neben Allrounder
* Allrounder nicht winzig neben Historical Leader

---

# 13. Historische Leitung – Artwork

Das vorhandene hochwertige Artwork soll sichtbar genutzt werden.

Aber nicht als Hero.

Beispiel:

```text
[ kleines Historical-Leader-Artwork ]
Historische Leitung
```

Wenn die aktuelle Badge-Preview-Infrastruktur ohne neue Komplexität wiederverwendet werden kann, darf das verdiente Badge optional anklickbar sein und größer betrachtet werden.

Aber:

Keine neue Modal-/Drawer-/Carousel-Engine nur dafür bauen.

Wenn kein bestehender einfacher Preview-Pfad passt, bleibt die kompakte Darstellung nicht interaktiv.

---

# 14. Allrounder

Allrounder soll eine vergleichbar hochwertige kompakte Darstellung erhalten.

Beispiel:

```text
[ Hexagon-Icon ]
Allrounder
```

Optional kurze Zusatzinformation nur wenn sie ohne Überladung passt:

```text
3+ unterschiedliche Rollen
```

Keine großen erklärenden Texte im Header.

---

* nächste Stufe
* Schwellenwerte

# Leitprinzip Phase 127

Der bestehende Member-Header ist bereits informationsreich und visuell stark.

Besondere Auszeichnungen sollen ihn deshalb **ergänzen und nicht übernehmen**.

Ziel ist:

**eine kompakte zusätzliche Identitätsebene direkt im Profilkopf – Historical Leader und Allrounder sichtbar, Verified nicht doppelt, keine weitere große Badge-Sektion.**

```
```
