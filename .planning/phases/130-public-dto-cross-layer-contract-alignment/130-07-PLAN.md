# 130-07 — Lock the contract: forbidden-field asserts + OpenAPI schema parity test (Wave 4)

**Requirement:** PMCT-02, PMCT-03 (assurance for the whole phase). **Depends on:** 130-01..130-06 (final aligned contract).
**Goal:** A Go handler-level contract test serializes a real public member response and (a) asserts BY NAME that forbidden fields are ABSENT, and (b) validates the response against the OpenAPI `PublicMemberProfileData` schema — proving field-absence (PMCT-02) AND cross-layer parity (PMCT-03) automatically, naming the leaking field on failure. A parity check keeps the four enums identical across Go/OpenAPI/TS.

**Read first:** `130-CONTEXT.md` D-08 (negative list + schema-validation requirement; helper choice is Claude's discretion), the final `PublicMemberProfile` (post-130-02), `shared/contracts/openapi.yaml` `PublicMemberProfileData` + `PublicMemberMembership` + `PublicMemberProfileBackgroundImage` (post-130-01), existing contract tests e.g. `backend/internal/handlers/public_member_access_matrix_test.go`, and `frontend/src/types/profile.ts` (post-130-04) for the enum-parity source.

**Files**
- NEW `backend/internal/handlers/public_member_profile_contract_test.go` (forbidden-field + schema-parity test). No DB required — build a fully-populated `PublicMemberProfile` literal, marshal, assert.
- Optionally NEW `frontend/src/types/__tests__/publicMemberEnums.contract.test.ts` OR a small Go/CI check that diffs the enum sets across the three layers (choose the lighter option; document it).

**Steps**
1. **Forbidden-field negative list (D-08).** In the Go test, marshal a fully-populated `PublicMemberProfile` (memberships with roles, a background image, badges incl. a platinum-capable one, projects, contributions) to JSON, walk the object graph, and assert NONE of these keys appear anywhere: `email`, `keycloak_subject`, `app_user_id`, `legacy_user_id`, `app_member_status`, `app_member_roles`, `historical_member_status`, `source_original_url`, `storage_path`, plus any `can_*` capability field and any internal status/permission field. On failure, report the exact JSON path of the leak. Keep this negative list co-located with the test as the authoritative forbidden set.
2. **OpenAPI schema validation (D-08).** `backend/go.mod` has NO OpenAPI validator dependency (confirmed — no `kin-openapi`/`libopenapi`), so do NOT add a heavy dependency. Chosen approach: parse `shared/contracts/openapi.yaml`, collect the declared property names + enum members for `PublicMemberProfileData` and its public sub-schemas (`PublicMemberMembership`, `PublicMemberProfileBackgroundImage`, `PublicMemberBadge`, `PublicMemberBadgeProgress`, `PublicMemberCurrentProject`, `PublicMemberLatestContribution`, `PublicMemberPreviousContribution`, `PublicMemberRole`), and assert (a) every serialized key is a declared property (no undocumented field) and (b) every emitted enum value is within the declared enum. If the team later adds a real validator dep, this test may be upgraded — document the current approach in the test header. (Parse the YAML with whatever YAML lib is already in the module graph — check `go list -m all` for `gopkg.in/yaml.v3`; do not add a new direct dep just for this.)
3. **Enum parity across layers (D-05/D-06).** Add a check that the four closed public enums — badge `current_tier`/`next_tier` (incl. `platinum` in next_tier), `profile_status`, latest-contribution `type`, `contribution_status` — are byte-identical sets in OpenAPI and TS (and are the accepted runtime values in Go). A small script/test that reads both files and diffs the sets is sufficient; fail on any divergence.
4. Wire both into the standard test run so CI executes them (no manual-only gate).

**Verification**
- `go test ./backend/internal/handlers/ -run Contract` green; deliberately injecting a forbidden field into the fixture makes it FAIL with the field named (prove the guard bites, then revert).
- The enum-parity check passes and fails if platinum is removed from one layer only.
- Full phase gate: `go build ./...`, `go test ./backend/...`, `npm run -w frontend typecheck && npm run -w frontend test` all green.
