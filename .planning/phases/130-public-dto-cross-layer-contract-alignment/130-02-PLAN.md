# 130-02 — Fork the Go public DTO structs, decoupled from the edit structs (Wave 2)

**Requirement:** PMCT-01, PMCT-02. **Depends on:** 130-01 (canonical schema names/shape).
**Goal:** `PublicMemberProfile` stops embedding internal/edit shapes — introduce `PublicMemberMembership` and a public background-image struct carrying ONLY allow-listed fields, add the internal→public mapping at the assembly site, and drop `app_member_status` / `app_member_roles` / `historical_member_status` / `source_original_url` (and any internal id/storage) from the public serialization. The internal `MemberProfile` edit struct stays unchanged. Every touched production file stays ≤450 lines.

**Read first:** `130-01-PLAN.md` (final OpenAPI shapes to mirror), `backend/internal/models/member_profile.go` (`PublicMemberProfile` L281, `MemberProfileMembership` L22, `MemberProfileBgImage` L166, `MarshalJSON` L316), `docs/engineering/implementation-contract.md` (reuse-first; no parallel projections), and the public profile loader in `backend/internal/repository/member_profile_repository.go` (the code assembling `PublicMemberProfile.Memberships` and `.BackgroundImage`).

**Files**
- MODIFY `backend/internal/models/member_profile.go` — add public structs; retype `PublicMemberProfile` fields. If adding the structs pushes the file over 450 lines, SPLIT the public DTO (all `PublicMember*` types + `MarshalJSON`) into NEW `backend/internal/models/public_member_profile.go` (same package) — this also better expresses the decoupling.
- MODIFY `backend/internal/repository/member_profile_repository.go` — the public-profile assembly emits the new public shapes and STOPS populating the dropped internal fields.

**Steps**
1. Add `PublicMemberMembership` struct = allow-list only: `FansubGroupID`, `FansubGroupName`, `FansubGroupSlug`, `LogoURL *string`, `GroupStatus`, `JoinedYear *int32`, `LeftYear *int32`, `IsCurrent bool`, `Roles []PublicMemberRole` (json `roles`, non-null), `HasHistoricalLink bool`. JSON tags MUST byte-match `PublicMemberMembership` in OpenAPI (130-01). Explicitly NO `AppMemberStatus` / `AppMemberRoles` / `HistoricalMemberStatus`.
2. Add a public background struct (e.g. `PublicMemberProfileBackgroundImage struct { PublicURL string \`json:"public_url"\` }`) with NO `SourceOriginalURL` / `StoragePath` / `ID`. Retype `PublicMemberProfile.BackgroundImage` → `*PublicMemberProfileBackgroundImage`.
3. Retype `PublicMemberProfile.Memberships` → `[]PublicMemberMembership`.
4. In the public loader (`member_profile_repository.go`), build `[]PublicMemberMembership` and the public background struct directly. DELETE the assignments that set `app_member_status` / `app_member_roles` / `historical_member_status` / `source_original_url` on the public path (they no longer have a home on the public struct). Keep the internal edit loader (which builds `MemberProfile` with the rich `MemberProfileMembership` / `MemberProfileBgImage`) untouched.
5. Preserve the nil-slice→`[]` guarantee: ensure `Memberships`, `Roles`, `PublicBadges`, `BadgeProgress`, `CurrentProjects`, `LatestContributions`, `PreviousContributions` still serialize as `[]` not `null` (extend `MarshalJSON` guard if the retype changes behavior).
6. Confirm no other consumer references the removed public fields (grep `PublicMemberProfile` usages across handlers/tests); update any that do.

- `go test ./backend/internal/repository/... ./backend/internal/handlers/... ./backend/internal/models/...` green (run in the `golang:1.25-alpine` container on `team4s_default` with the phase test DSN, per project convention).
- `grep -n "AppMemberStatus\|AppMemberRoles\|HistoricalMemberStatus" backend/internal/models/*.go` shows them ONLY on the internal `MemberProfileMembership`, never on `PublicMemberMembership`.
- The public background struct has no `SourceOriginalURL`.
- Every touched production `.go` file is ≤450 lines (`wc -l`).
