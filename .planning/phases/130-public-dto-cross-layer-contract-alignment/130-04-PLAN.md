# 130-04 — TypeScript public types mirror the OpenAPI contract (Wave 2)

**Requirement:** PMCT-01, PMCT-02, PMCT-05. **Depends on:** 130-01 (canonical OpenAPI shapes/enums). Runs parallel to 130-02 (disjoint stack).
**Goal:** `frontend/src/types/profile.ts` public types match the 130-01 OpenAPI contract exactly — a dedicated `PublicMemberMembership` TS type (no internal permission/status fields), a dedicated public background type (no `source_original_url`), completed enum unions (`next_tier` incl. `platinum`, D-06), and the single shared error-envelope type. The internal `MemberProfileData` edit type stays unchanged.

**Read first:** `130-01-PLAN.md` (final OpenAPI shapes), `frontend/src/types/profile.ts` (`MemberProfileMembership` L13, `PublicMemberBadge.next_tier` L156, `PublicMemberBadgeProgress.next_tier` L164, `PublicMemberProfileData` L226 incl. `background_image` L248 + `memberships` L250, `PublicMemberProfileResponse` L280, `MemberProfileStatus` L146, `PublicMemberLatestContributionType` L198).

**Files**
- MODIFY `frontend/src/types/profile.ts` only.

**Steps**
1. Add `export interface PublicMemberMembership` = allow-list only: `fansub_group_id`, `fansub_group_name`, `fansub_group_slug`, `logo_url?`, `group_status`, `joined_year?`, `left_year?`, `is_current`, `roles: PublicMemberRole[]`, `has_historical_link`. NO `app_member_status` / `app_member_roles` / `historical_member_status`. Retype `PublicMemberProfileData.memberships` → `PublicMemberMembership[]`. Leave the internal `MemberProfileMembership` interface (used by `MemberProfileData`) untouched.
2. Add a dedicated public background type (e.g. `PublicMemberProfileBackgroundImage { public_url: string }`) with NO `source_original_url`; retype `PublicMemberProfileData.background_image` (currently an inline object exposing `source_original_url` at L248) → `PublicMemberProfileBackgroundImage | null`.
3. Enums (D-06): extend `PublicMemberBadge.next_tier` → `'bronze' | 'silver' | 'gold' | 'platinum' | null`. For consistency, close `PublicMemberBadgeProgress.next_tier` (currently `string | null`) to the same tier union if the runtime values are that closed set; otherwise leave a comment noting the intentional openness. Verify `MemberProfileStatus` (`active|historical|memorial`), `PublicMemberLatestContributionType` (`text|media`), and `PublicMemberCurrentProject.contribution_status` union match OpenAPI 1:1.
4. Add/verify one shared error-envelope type mirroring `ErrorResponse`: `export interface ApiErrorEnvelope { error: { message: string; code?: string; details?: string } }`. Reuse it (do not invent per-call error shapes); 130-05 wires it into the helper parse. If an equivalent already exists in the codebase, reuse that one and note it.
5. Do NOT remove `MemberProfileRecentMedia` / `MemberProfileRecentContribution` — still referenced by the internal `MemberProfileData` (L119/L120). Orphan handling is 130-06.

- `PublicMemberProfileData.background_image` type has no `source_original_url`.
- `PublicMemberBadge.next_tier` includes `'platinum'`.
