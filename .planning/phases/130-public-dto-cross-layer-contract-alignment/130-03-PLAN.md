# 130-03 — Go handler: lock the four status branches, one envelope, and enum-value emission (Wave 3)

**Requirement:** PMCT-03, PMCT-04, PMCT-05. **Depends on:** 130-02 (forked public structs).
**Goal:** The public profile/projects handlers emit exactly the documented contract — visible→200 `{data, viewer}`, hidden AND missing→byte-identical neutral 404 `{error:{message}}`, failure→500 `{error:{message, code?, details?}}` — using the ONE shared envelope, and the runtime enum-string emission (tiers, `profile_status`, contribution `type`/`status`) matches the 130-01 OpenAPI enums. No body discriminator is introduced (128 non-distinguishability lock).

**Read first:** `130-01-PLAN.md` (documented branch semantics), `backend/internal/handlers/app_public_profile.go` (`GetPublicMemberProfile` L31, 200 body L59; `GetPublicMemberProjects` L74–99), `backend/internal/handlers/public_member_access.go` (`writePublicMemberUnavailable` L76 → neutral 404 `"Profil nicht verfügbar"`), `backend/internal/handlers/error_responses.go` (`writeInternalErrorResponse` L13 → 500 `{error:{message, code?, details?}}`), and the tier/status emission sites: `backend/internal/repository/member_profile_contribution_badges_repository.go`, `backend/internal/repository/member_profile_progress_repository.go`.

**Files**
- MODIFY `backend/internal/handlers/app_public_profile.go` (and, only if needed for the neutral-404 wiring, `public_member_access.go`).
- Read-only verify (change only if a value diverges from OpenAPI) the tier/status emission repositories above.

**Steps**
1. **Confirm the 200 envelope is `{data, viewer}`.** `GetPublicMemberProfile` sets `profile.IsOwner/IsPrivatePreview` then serializes — verify the 200 body includes BOTH `data` (the profile) and `viewer` (`{is_owner, is_private_preview}`) to satisfy `PublicMemberProfileEnvelope`. If `viewer` is currently missing/derived elsewhere, add it explicitly. Projects 200 stays `{data: page}` per `PublicMemberProjectsEnvelope`.
2. **Neutral 404 stays byte-identical (128 lock).** Both the hidden branch and the missing/`ErrorNotFound` branch route through `writePublicMemberUnavailable` → `{error:{message:"Profil nicht verfügbar"}}` with NO `code`/`details`. Verify no code path emits a different 404 body or leaks existence (e.g. distinct messages for hidden vs missing). Add a focused handler test asserting the two branches produce identical bytes.
3. **500 via the one envelope.** All internal-error branches use `writeInternalErrorResponse` (`{error:{message, code?, details?}}`). Remove/replace any ad-hoc `gin.H{"error": gin.H{"message": ...}}` 500 literals (e.g. the nil-loader guards at L37/L74) with `writeInternalErrorResponse` so 500s share one shape. Keep `message` operator-facing German with correct umlauts.
4. **Enum-value emission parity (D-05/D-06).** Verify the strings emitted for badge `current_tier`/`next_tier`, `profile_status`, `PublicMemberLatestContribution.type`, and `PublicMemberCurrentProject.contribution_status` are all within the closed OpenAPI enums from 130-01. Go uses `*string` (no compile-time enum), so this is a runtime-value check: no emitted value may fall outside the enum. If any does, fix the emission site to match OpenAPI (OpenAPI is canonical — never widen the enum to fit a stray value without a decision).
5. Ensure handlers compile against the 130-02 forked structs (no references to the dropped `app_member_status` etc.).

**Verification**
- `go build ./...` clean; `go test ./backend/internal/handlers/...` green (alpine container + phase test DSN).
- New/updated handler test proves: hidden 404 body == missing 404 body (byte-identical); a 500 path returns `{error:{message,...}}`; a visible 200 returns `{data, viewer}`.
- `grep -n "gin.H{\"error\"" backend/internal/handlers/app_public_profile.go` shows no ad-hoc 500 error literals remain (all go through `writeInternalErrorResponse`).
