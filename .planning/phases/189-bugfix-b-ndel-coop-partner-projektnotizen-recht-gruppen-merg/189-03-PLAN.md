<objective>
Fix the live crash on `/anime/2/group/26/releases`: `Invalid src prop
(/api/v1/media/files/logo_1789627959614_...png) on next/image does not match
images.localPatterns`. Root cause (confirmed via direct code read, not guessed): this page
imports raw `next/image` and uses it directly for `group.fansub.logo_url`
(header, lines 325-331) and `otherGroup.logo_url` (the "Weitere Gruppen zu diesem Anime" chip,
lines 427-433) -- both legacy `/api/v1/media/files/<filename>` URLs are outside
`publicImagePatterns.mjs`'s `LOCAL_IMAGE_PATTERNS`, and Next validates local `src` values against
exactly that list before the page can render at all.

This exact failure mode already has a solved, documented pattern elsewhere in this same route:
`HeroSection.tsx` already uses `ResponsiveImage` for the identical `group.fansub.logo_url` field
and is therefore already safe. Per D-07, the fix is to migrate `releases/page.tsx` to the same
sanctioned component -- NOT to add `/api/v1/media/files/**` to the allowlist (deliberately
treated as unmigrated legacy data elsewhere) and NOT to wrap `next/image` in a local try/catch.

`releases/page.tsx` is already 556 lines (over the 450-line limit, before this plan's edit) --
per CLAUDE.md, touching its content forces a pure-refactor split FIRST, in its own commit, before
the behavior-changing image fix.

Purpose: stop the hard crash for any group whose logo predates Phase 173's media-URL backfill,
using the already-proven app-wide mechanism.
Output: `releases/page.tsx` split into itself plus three small presentational components, two of
which now safely render legacy logo URLs via `ResponsiveImage`.
</objective>
