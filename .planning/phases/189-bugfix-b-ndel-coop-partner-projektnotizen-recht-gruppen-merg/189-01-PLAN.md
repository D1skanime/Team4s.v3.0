<objective>
Add a `coop_groups` field to the Seek-Cursor release list response (`GetGroupReleasesCursor`,
the endpoint the public project page actually calls via `GetGroupReleaseListCursor` /
`group_contributors_handler.go:241`), containing only fansub groups that share at least one
`release_version` with the current group on this anime -- as opposed to the existing
`other_groups` field, which includes every group with ANY release on the anime, overlapping or
not. This is the backend half of the Coop-Partner bugfix (D-04/D-02): today the project page
mislabels every other active group on the anime as a "Coop-Partner" even without a shared
release.

Per D-04, this field is added ONLY to the Cursor endpoint (`GetGroupReleasesCursor`) -- the
Offset endpoint `GetGroupReleases` (used by other handlers, not the project page) is
deliberately left untouched.

Purpose: Give the frontend (Plan 189-02) a backend-computed, correctly-scoped list of real
coop partners to render in the project page's header metric and expandable partner list.
Output: `coop_groups` on `GroupReleasesCursorPage`, a new `getCoopGroups` repository function
with a real-Postgres proof, and an OpenAPI contract fix that also closes a pre-existing
documentation drift (`other_groups` was already shipped on this response shape but never
documented).
</objective>

		SELECT DISTINCT fg.id, fg.slug, fg.name, fg.logo_url

		JOIN release_versions rev ON rev.id = rvg.release_version_id
