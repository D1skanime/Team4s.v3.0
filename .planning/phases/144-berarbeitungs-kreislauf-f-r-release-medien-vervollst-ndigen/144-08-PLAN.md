<objective>
Close three findings from 144-VERIFICATION.md and 144-REVIEW.md against the already-shipped Phase
144 backend, without touching any of the phase's other already-verified behavior:

1. (VERIFICATION.md blocking gap) `PatchReleaseVersionMedia` and `ReplaceReleaseVersionMediaFile`
   both only check `PREVIEW_NOT_ALLOWED_FOR_CATEGORY` against the REQUEST body's
   `is_preview_candidate` field, never the row's actual current DB value. When an admin fixes only
   the category on a row that is already `is_preview_candidate=true` (the frontend omits the field
   from the payload whenever the admin doesn't touch that control), the guard is skipped, the write
   hits the DB's `chk_rvm_preview_category` CHECK constraint, and the admin sees a generic 500
   instead of the documented 422.
2. (REVIEW.md WR-01) Five call sites in the same two handler files spell "groß" as "gross" and
   "geprüft" as "geprueft" in user-facing response strings, violating CLAUDE.md's Sprachqualität rule.
3. (REVIEW.md WR-03) `MediaRepository.GetRVMCategory` is dead code — no production caller remains
   (both handlers read `Category` off `GetReleaseVersionMediaRelation`'s result instead); only a
   compile-time existence-check test line references it.

All three gaps are scoped to the same small cluster of files (the category-guard fix and the
Sprachqualität fix land in the exact same two handler files; the dead-code removal and the guard
fix both touch the same repository file), so they are closed together in one plan to avoid two
plans editing the same lines in overlapping waves.

Purpose: PREVIEW_NOT_ALLOWED_FOR_CATEGORY becomes airtight regardless of what the request payload
does or doesn't include, closing 144-VERIFICATION.md's single blocking gap; the backend's own
Sprachqualität and dead-code debt from this phase's own review is cleaned up in the same pass.
Output: A single shared `rvmPreviewGuardBlocked` decision function used identically by both the
PATCH and the PUT replace endpoint; `release_version_media.is_preview_candidate`'s current value is
now part of the already-loaded `relationMeta`; five corrected German strings; one dead method removed.
