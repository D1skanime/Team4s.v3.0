<objective>
Unblock category changes on the existing metadata PATCH endpoint for release-version media
(`PATCH /admin/release-versions/:versionId/media/:relationId`). Today this endpoint explicitly
rejects any `category` field in the request body with a 422 `CATEGORY_CHANGE_NOT_ALLOWED` error
(`admin_content_release_version_media.go:854-860`). CONTEXT.md's Zielbild 2 requires this removed:
"falsche Kategorie" is a plausible rejection reason and a pure metadata change on the same row, so
the submitter must be able to fix it in the same form as the caption/preview edit, without a new
upload.

Purpose: closes the second of four Zielbild goals in 144-CONTEXT.md — this plan is backend-only
and touches the EXISTING PATCH path; the NEW file-replace endpoint (Zielbild 1) is a separate plan
(144-02/144-04) and does not depend on this one functionally, only shares the same repository
struct.
Output: `PatchReleaseVersionMedia` accepts and validates `category`; `PatchReleaseVersionMedia`
(repository) persists it; the existing preview-candidate-vs-category guard is preserved for BOTH
the pre-existing and the newly-changed category; OpenAPI + frontend types describe the new field;
the pre-existing test asserting the OLD (now-wrong) behavior is rewritten to assert the NEW one.
</objective>
