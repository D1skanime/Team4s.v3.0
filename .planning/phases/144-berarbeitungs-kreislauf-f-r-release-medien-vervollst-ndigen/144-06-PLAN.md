<objective>
Build the submitter-facing half of Zielbild 1 and 2: inside the existing "Medium bearbeiten" drawer,
a rejected item's submitter can now change the category, stage a replacement file, and submit both
(plus the existing caption field) in one action — closing CONTEXT.md's "Der Kreislauf fordert nach
einer Ablehnung eine Überarbeitung und verweigert dann genau die Änderung, die den Ablehnungsgrund
beheben würde" problem statement end to end on the submitter side.

Purpose: this is the UI consumer of 144-04's new PUT endpoint and 144-05's `replaceItem`
API-client wrapper; per 144-UI-SPEC.md's Interaction Contract, every new element extends the
already-shipped drawer rather than introducing a second visual language. This plan also keeps
`ReleaseVersionMediaSection.tsx` (already 671 lines pre-phase, over CLAUDE.md's 450-line cap
before this phase even starts) from growing more than necessary: the category field — which uses
only `@/components/ui` primitives and carries no native-element lint risk — moves into a new
sibling component, `ReleaseVersionMediaReplaceControls.tsx`. The file-replace drop-zone's native
`<input type="file">` CANNOT make the same move: `frontend/eslint.config.mjs`'s
`LEGACY_NO_RESTRICTED_SYNTAX_FILES` list is an explicit, git-committed RATCHET ("darf nur
SCHRUMPFEN, nie wachsen" / may only shrink, never grow) — `ReleaseVersionMediaSection.tsx` is
already on that list at `warn` severity with 3 pre-existing native-`<input>` findings, but a BRAND
NEW file is never eligible for that exemption, so a native file input newly written into
`ReleaseVersionMediaReplaceControls.tsx` would be flagged at the base `error` severity and break
the lint gate. The drop-zone therefore stays inline in `ReleaseVersionMediaSection.tsx`, where it
mirrors the existing upload drop-zone's already-tolerated pattern (per CLAUDE.md: native
`<input type="checkbox">`/`<input type="file">` are tolerated only because no UI-kit primitive
exists for them yet).
Output: a working `replaceItem` hook action; a category `Select` (new component) + file-replace
drop-zone (inline) rendered only for rejected, editable items; a three-state primary button label;
tests proving the gating and the wiring.
</objective>
