# Phase 138 — UI Design Contract

> Visual and interaction contract for Phase 138 (Effective-Rights Administration & Impact UX).
> Generated by gsd-ui-researcher from 138-CONTEXT.md (D-01…D-35, locked) and 138-RESEARCH.md
> (R-01…R-12). Verified by gsd-ui-checker. Consumed by gsd-planner and gsd-executor.
>
> This phase extends an **existing, proprietary, CLAUDE.md-mandated component library**
> (`@/components/ui`), not shadcn. No new visual language is introduced — this contract pins
> exactly which existing tokens/primitives new Phase-138 screens must reuse, and specifies the
> interaction/copy contracts (guided revoke, impact preview, activation status) that do not yet
> exist anywhere in the codebase.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is not used and must not be introduced. `components.json` does not exist and CLAUDE.md explicitly mandates the proprietary `frontend/src/components/ui/` library for all user-facing UI (reference/showcase: `/dev/ui-system`). |
| Preset | not applicable |
| Component library | Proprietary, hand-rolled (`frontend/src/components/ui/`) — no Radix/base-ui underneath. 29 primitives exported from `frontend/src/components/ui/index.ts`. |
| Icon library | `lucide-react` (already a pinned dependency; used today in `Modal.tsx`, `Drawer.tsx`, `EmptyState.tsx`, `ErrorState.tsx`) |
| Font | `Inter, "Segoe UI", system-ui, sans-serif` (`--font-sans`, `frontend/src/styles/globals.css`) |

**Binding constraint (D-35, CLAUDE.md):** every user-facing element in Phase 138 must be built from
`@/components/ui` primitives. Hand-built native `<select>/<input>/<textarea>/<button>` or bespoke
markup duplicating an existing primitive is forbidden, even where "local file consistency" might
seem to justify it. This is a hard UI-checker gate.

## Spacing Scale

Phase 138 reuses the **existing, already-locked** spacing scale from `globals.css` — no new tokens
are introduced (D-35 forbids inventing CSS variable names):

| Token | Value | Usage in Phase 138 |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-label gaps in badges/chips (e.g. role badge + link) |
| `--space-2` | 8px | Compact inline spacing (button groups, filter chip rows) |
| `--space-3` | 12px | Table cell internal padding, form control internal gaps |
| `--space-4` | 16px | Default panel/card padding, tab content padding |
| `--space-5` | 24px | Section padding inside detail panels (capability catalog sections, impact preview body) |
| `--space-6` | 32px | Gaps between major page regions (split-view master/detail gutter) |
| `--space-7` | 48px | Page-level top/bottom padding on new top-level nav routes (`/admin/changes`, `/admin/claims` if new) |
| `--space-8` | 64px | Reserved — not expected to be needed by any Phase 138 screen; do not invent a new large value if a layout seems to need more than 64px, re-examine the layout instead. |

Exceptions: `--control-height-sm/md/lg` (36/44/52px) remain the only non-4px-multiple-adjacent
control-height tokens already in use for interactive elements (Button, Switch, Select) — reuse them
verbatim for any new button/toggle sizing in this phase; do not invent a new touch-target size.

## Typography

Phase 138 introduces **no new custom text styling outside existing primitives** wherever a primitive
already renders text (Card title/description, Badge, Table header/cell, EmptyState/ErrorState
title/description, Modal/Drawer title/description all keep their existing built-in typography —
do not override with inline `style` font-size/weight). The table below is the contract for the
**genuinely new prose** this phase introduces: guided-revoke explanation text, impact-preview body
copy, activation-status labels, and translated "Änderungen" sentences.

| Role | Size | Weight | Line Height | Where used |
|------|------|--------|-------------|------------|
| Body | 14px | 400 | 1.5 | Guided-revoke explanation paragraphs, impact-preview lead paragraph, "Änderungen" translated sentence body, claim-decision impact paragraph |
| Label / Caption | 12px | 700 | 1.3 | Activation-status pill text, capability-state chips ("erlaubt" / "nicht erlaubt" / "persönlich entzogen" / "persönlich zusätzlich erlaubt" / "non-deniable"), impact-preview count labels ("Rolleninhaber", "verlieren", "gewinnen") |
| Heading | 16px | 700 | 1.3 | Modal/Drawer section sub-headings inside a body (e.g. "Dieses Recht wird aktuell gewährt durch:"), split-view panel headers that are not already a `Card`/`SectionHeader` title |
| Display | 20px | 700 | 1.2 | User-detail and group-detail header name (only where not already covered by `PageHeader`) |

Exactly 2 weights used by new Phase 138 prose: **400 (regular)** and **700 (bold)**. Existing
primitives internally use additional weights (600/800/900 appear in `ui.module.css`) — those stay
untouched inside their own components; new Phase-138-authored text never introduces a third weight.

## Color

Phase 138 reuses the **existing** design tokens verbatim (CLAUDE.md/D-35 binding: `--surface-canvas/
-card/-sunken`, `--text-primary/-muted`, `--color-border`, `--accent-primary/-deep`, `--shadow-*`).
No new color tokens are introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface-canvas` (`#f6f4ef`) | Page background for all new admin routes (`/admin/changes`, any new `/admin/claims` top-level page) |
| Secondary (30%) | `--surface-card` (`#ffffff`) plus `--surface-sunken` (`#f0ece5`) | Cards, tables, modal/drawer panels (`--surface-card`); nested/inset areas inside a panel, e.g. the collapsed capability-catalog sections and the impact-preview detail table's zebra/nested rows (`--surface-sunken`) |
| Accent (10%) | `--accent-primary` (`#5f84dd`), hover/active state `--accent-deep` (`#185fa5`) | Reserved for: primary CTA buttons (`Button variant="primary"`), the active tab indicator in `Tabs`, the selected row/item in every split-view master list (Rollen split-view left panel, and any new Benutzer/Gruppen/Capability list-with-detail view), inline text links that cross-navigate between perspectives (D-02 bidirectional navigation links, e.g. "Was darf diese Rolle?"), and the focused/current step in the guided-revoke flow. **Not** used for status badges (those use `Badge`'s own semantic variants) and never used as a large background fill. |
| Destructive | `--color-error` (`#dc3545`) for text/icons; `--button-danger-start/-mid/-end` gradient for the `Button variant="danger"` background | Reserved for: the `Recht entziehen` / `Capability entziehen` confirmation button, the "verliert das Recht" row state in the impact-preview detail table, the `fehlgeschlagen` activation-status pill, non-deniable warning icon/text (D-17) |

Accent reserved for (explicit, non-exhaustive list is forbidden by the checker — this list is exhaustive
for this phase): primary buttons, active tab underline, selected split-view row, cross-navigation
links, guided-revoke current-step indicator. Everything else uses neutral surface/border/text tokens
or `Badge`'s existing semantic palette (`success`/`warning`/`danger`/`info`/`muted`/`neutral`).

## Copywriting Contract

D-33 locks the German business-action vocabulary; the table below is that vocabulary plus the new
empty/error/destructive copy this phase's new screens need. All copy uses correct umlauts (ä/ö/ü/
Ä/Ö/Ü/ß) — no ASCII substitutes anywhere in JSX text, labels, aria-labels, or toasts (CLAUDE.md,
binding, no exceptions).

| Element | Copy |
|---------|------|
| Primary CTA (this phase's headline flow, CAP-08) | **„Recht entziehen"** — opens the guided revoke flow from any capability row in the Benutzer-in-Gruppe-Editor |
| Secondary CTA (CAP-08 counterpart) | **„Recht zusätzlich erlauben"** — opens the equivalent guided grant flow |
| Existing-override CTA (D-16) | **„Abweichung entfernen"** — reverts a `persönlich entzogen`/`persönlich zusätzlich erlaubt` row back to the resolver default |
| Role-assignment CTAs (D-22) | **„Rolle zuweisen"** / **„Rolle entfernen"** |
| Account-status CTAs (D-31) | **„Benutzer deaktivieren"** / **„Benutzer reaktivieren"** |
| Empty state — no group rights yet | Title: „Keine Rechte in dieser Gruppe." Body: „Dieser Benutzer hat aktuell keine Rolle und keine persönliche Abweichung in dieser Gruppe. Rolle zuweisen, um Rechte zu vergeben." |
| Empty state — no open claims | Title: „Keine offenen Claims." Body: „Für diesen Filter liegen aktuell keine zu entscheidenden Claims vor." |
| Empty state — no changes/audit entries for this filter | Title: „Keine Änderungen gefunden." Body: „Für die gewählten Filter liegen keine administrativen Änderungen vor. Zeitraum oder Filter anpassen." |
| Error state — generic load failure | Title: „Fehler beim Laden." Body: „Die Daten konnten nicht geladen werden. {api error message if available, otherwise:} Erneut versuchen." (matches `getErrorStateCopy`'s existing fallback pattern — reuse it, do not invent new error copy helpers) |
| Error state — impact preview computation failed | Title: „Auswirkungs-Vorschau nicht verfügbar." Body: „Die Auswirkungen konnten nicht berechnet werden. Ohne Vorschau wird keine Änderung übernommen." (blocking — the confirm action stays disabled, per D-18/D-20: no mutation may proceed without a computed preview) |
| Guided revoke — sources explanation (D-16, locked example, reuse verbatim as the template) | „Dieses Recht wird aktuell gewährt durch: {Liste der Rollen/Quellen}. Das Entfernen nur einer dieser Rollen würde das Recht nicht vollständig entziehen. Empfohlen: Persönliche Abweichung für diesen Benutzer in {Gruppe} setzen." |
| Non-deniable explanation (D-17) | „Dieses Recht kann für {Benutzer} nicht persönlich entzogen werden. Es wird direkt durch {Quelle} gewährt und ist nicht überschreibbar." — shown inline where the `Recht entziehen` action would otherwise appear; the action itself is not rendered as a disabled ghost button (that invites a surprise-at-click), it is replaced entirely by this explanatory text. |
| Impact preview — header counts (D-19, locked example) | „{N} Rolleninhaber" · „{N} verlieren das Recht" · „{N} gewinnen das Recht" · „{N} behalten es über eine andere Rolle" · „{N} behalten es über eine persönliche Abweichung" |
| Impact preview — confirm button | „Änderung übernehmen" (primary, only enabled once the preview has finished computing) |
| Impact preview — cancel button | „Abbrechen" (secondary) |
| Activation status — role-matrix mutation, cache reload succeeded (the normal case, both DB write and cache reload are synchronous, see Activation Status Contract below) | „Gespeichert und aktiv." |
| Activation status — role-matrix mutation, cache reload failed (new, requires the minimal backend field from Pitfall 3) | „Gespeichert, aber nicht aktiv: Der Rechte-Cache konnte nicht aktualisiert werden. Erneut versuchen oder Administrator informieren." + retry action |
| Activation status — personal override mutation, normal success | „Gespeichert und sofort aktiv." (per R-05: `ResolveGroupRights` reads overrides live from Postgres on every call — there is no cache and therefore no genuine delay; never show a spinner implying one) |
| Activation status — personal override mutation, post-commit re-resolve enrichment failed (existing GAP-01 edge case) | „Gespeichert. Status wird geprüft — bitte Seite neu laden, um den aktuellen Stand zu sehen." (`ausstehend`, the one legitimate case where "pending" is honest for this path) |
| Destructive confirmation — Recht entziehen | „Recht entziehen: {Capability-Label} wird {Benutzer} in {Gruppe} entzogen. Fortfahren?" — confirm button label „Recht entziehen" (`Button variant="danger"`), reused via `Modal`, never `window.confirm()` (established precedent: Phase 135-10 replaced all `window.confirm()` calls with `Modal` for this exact reason) |
| Destructive confirmation — Capability entziehen (role-matrix path) | Existing `RevokeCapabilityModal.tsx` copy must be corrected as part of this phase: replace „Die Änderung wird nach dem nächsten Cache-Reload der Rechte-Prüfung wirksam." (implies a delayed future reload that does not exist, per R-05/Pitfall 3) with „Die Änderung wird sofort im Rechte-Cache aktualisiert." plus the new fail-path copy above if the reload fails. |
| Claim decision impact (D-24) | Approve: „Genehmigen erzeugt: {Zuordnung/Rolle}. Effektive Rechte danach: {Zusammenfassung}." Reject: „Ablehnen: Es entsteht keine neue Zuordnung. {Benutzer} bleibt im aktuellen Zustand." If the specific action being decided (`VerifyClaim` vs. `ActivateClaimedMember`, see 138-RESEARCH.md Pitfall 4/Open Question 1) turns out to cause no rights-relevant change at all, the honest copy is „Diese Entscheidung ändert keine effektiven Rechte." — never show a fabricated diff. |
| Änderungen entry (D-25, locked example, reuse verbatim as the template) | „{Admin} hat {Benutzer} in {Gruppe} die Rolle {Rolle} entzogen. Vorher: {Rolle} — {Capability} erlaubt. Nachher: keine {Rolle} — {Capability} nicht mehr erlaubt." Where before/after cannot be honestly reconstructed from `audit_logs` (R-07), omit the Vorher/Nachher lines entirely rather than guessing — never render a placeholder like "unbekannt" in their place. |

## Phase 138 Additional Contract

*(Supplementary to the standard template sections above — required because Phase 138 is an
information-architecture-heavy admin phase with several genuinely new interaction patterns.
Planner and executor should treat this section as equally binding.)*

### A. Information Architecture (locked by D-01…D-10, D-32 — visual contract only, IA itself is not this agent's decision to make)

```text
Hauptnavigation:  Benutzer | Gruppen | Rollen | Capabilities | Claims | Änderungen

Benutzer-Detail:  Übersicht | Rollen & Rechte | Beiträge | Claims | Streaming | Änderungen
Gruppen-Detail:    Benutzer | Rollen | Claims | Änderungen
Capabilities:      Split-view (Rollenliste links, Capability-Matrix rechts) — REUSE, do not rebuild
                    (`frontend/src/app/admin/role-capabilities/RoleCapabilityClient.tsx` already
                    implements this exact shape; only the Impact Preview modal is new, plus fixing
                    the stale `CATEGORY_ORDER`/`CATEGORY_LABEL_MAP` to cover all 7 real categories:
                    `gruppe`, `gruppenmedien`, `gruppenseite`, `projekt`, `rechteverwaltung`,
                    `release`, `review`)
```

Every list surface (Benutzer, Gruppen, Rollen, Capability-Detail's "wer besitzt das effektiv")
renders user/group/role names as clickable navigation targets using `Button variant="ghost"` or an
inline text link styled with `--accent-primary` — never a raw `<a>` or unstyled clickable `<div>`.

### B. Component Inventory (what to reuse, what is genuinely new)

| Screen/Flow | Primitives to reuse (do not rebuild) | New component needed |
|---|---|---|
| Capabilities split-view (D-08) | `RoleMasterList`, `RoleCapabilityDetail`, `Drawer` (mobile), `Card`, `Badge`, `Accordion` | `RoleCapabilityImpactPreviewModal` (new, CAP-09) |
| Benutzer-in-Gruppe-Editor (D-09, UADM-01, evolves `UserGroupRightsTab.tsx`) | `Table`/`TableRow`/`TableCell`, `Accordion` (per-category sections, D-12), `Badge` (capability state chips), `Button`, `EmptyState`, `ErrorState`, `LoadingState`, `SectionHeader` | `GuidedRevokeFlow` (new, CAP-08), `GuidedGrantFlow` (new, symmetric), `CapabilityHistoryPanel` (new, D-13b) |
| Rollen view "wer besitzt diese Rolle" (D-07) | `Table`, `Badge`, `Button` (links) | `RoleHoldersTable` (new — depends on new backend role-holder query, see 138-RESEARCH.md R-03) |
| Claims (D-23/D-24) | `Table`, `Badge`, `Modal`, filter row (`FormField` + `Select`) | `ClaimDecisionImpactPanel` (new, inside a `Modal`) |
| Änderungen (D-25/D-26/D-27) | `Table`, filter row, `Card` (per-entry expandable detail) | `ChangeEntryTranslator` (new, pure function mapping `audit_logs.event_type` → German sentence; mirrors the existing `capabilityCategories.ts` label-mapping pattern) |
| Activation status (CAP-10) | `Badge` (status pill), `Modal` (stays-open pattern, D-21) | `ActivationStatusIndicator` (new — small, reusable across both role-matrix and override mutation flows, but must render the two paths' honest vocabulary differently, see Section C) |

**Explicitly forbidden per D-15:** a bare `Switch` toggling a capability's allow/deny state directly.
`Switch` remains available in `@/components/ui` for other unrelated on/off settings, but the
guided-revoke/guided-grant business actions (`Recht entziehen`, `Recht zusätzlich erlauben`,
`Abweichung entfernen`) must be `Button`-triggered flows, never a switch with an implicit save.

**Missing primitive, do not invent locally (R-10):** there is no Toast/Snackbar component in
`@/components/ui`. Do not build one ad hoc for this phase. The `D-21` modal-stays-open pattern (the
Impact Preview / mutation-confirmation `Modal` remains open and updates its own body to show the
activation status) does not require a toast — use it instead of inventing transient notification UI.

### C. Activation Status Contract (CAP-10 — the two honest paths, do not conflate)

| Path | Mechanism (from 138-RESEARCH.md R-05) | Honest states this phase may show | States this phase must NOT show |
|---|---|---|---|
| Role→Capability matrix mutation (`GrantCapability`/`RevokeCapability`) | Synchronous Postgres write, then synchronous in-process `permissions.Service.ReloadCache` before the HTTP response returns. Single backend container — no cross-replica staleness. | `Gespeichert und aktiv` (normal case) · `Gespeichert, aber nicht aktiv` (cache reload failed — requires the minimal response-field contract extension flagged in R-05/Pitfall 3) | A `wird aktiviert` / spinner / polling state implying an async window — none exists for this path today. |
| Personal user-override mutation (`MutateOverride`) | No cache at all — `ResolveGroupRights` reads overrides live from Postgres on every call. Always immediately consistent on commit. | `Gespeichert und sofort aktiv` (normal case) · `Status wird geprüft` (only the existing GAP-01 post-commit re-resolve-enrichment failure edge case; the mutation itself already succeeded) | A `fehlgeschlagen` status after a 200 response — a genuine failure on this path returns 4xx/5xx before any `ActivationStatus` is constructed at all; render the request-level error instead, not an activation-status pill. |

Both flows keep their confirming `Modal` open after the user confirms, and update the same modal's
body in place to show the resulting activation status (D-21) — do not close the modal on submit and
show a separate success screen/toast.

### D. Responsive Contract (D-32)

- **Breakpoint:** reuse the existing `760px` split-view breakpoint verbatim (`RoleCapabilityClient.tsx`'s
  `window.matchMedia('(max-width: 759px)')`) for every new split-view this phase introduces. Do not
  invent a second breakpoint value.
- **Desktop (≥760px):** split-views are side-by-side (master list left, detail right); large tables
  render as full `Table`.
- **Tablet/Mobile (<760px):** master list first, full-width; detail opens in
  `Drawer variant="responsiveSheet"` (matches the existing pattern exactly — reuse, do not
  reimplement). Large tables collapse to `Card`-based rows/lists (a pattern already used elsewhere
  in the admin area for narrow viewports — confirm the exact existing card-row component at plan
  time rather than inventing a new one).
- **Never:** a horizontally-scrolled desktop matrix squeezed onto a small screen (D-32 explicit
  prohibition) — the capability matrix, impact-preview detail table, and any new Rollen/Capability
  matrix must have a genuinely different narrow-viewport layout, not a shrunk clone.

### E. Guided Revoke Flow — screen-by-screen (CAP-08, D-16, D-17)

1. **Trigger:** `Button variant="secondary"` labeled „Recht entziehen" on a capability row inside the
   Benutzer-in-Gruppe-Editor (only rendered if the capability is currently effective for this user).
2. **Step 1 — Source explanation (`Modal`, size `md`):** title „Recht entziehen: {Capability-Label}".
   Body: the locked D-16 explanation copy (see Copywriting Contract) listing every granting source
   from `EffectiveRightState.granting_roles[]`/`specialized_grants[]`. If `EffectiveRightState.decisive_source`
   indicates a non-deniable/Contribution-Role-only grant (per 138-RESEARCH.md Pitfall 5), the source
   list must explicitly flag that source as "kann durch eine persönliche Abweichung nicht entzogen
   werden" inline next to that specific source — never let the general D-16 narrative imply a scoped
   deny always fully works.
3. **Step 2 — Recommendation + confirm:** the same modal (do not navigate away) shows the
   recommendation sentence and a preview of the resulting state ("Nachher: {Capability} nicht mehr
   erlaubt" or, if another source remains, the honest "Nachher: {Capability} weiterhin erlaubt durch
   {andere Quelle}" — CAP-08 explicitly requires this partial-effect case to be shown, not hidden).
   Confirm button: `Button variant="danger"` labeled „Recht entziehen".
4. **Step 3 — Activation status:** modal body updates in place per Section C's contract for the
   override-mutation path.
5. **Non-deniable case (D-17):** step 1 replaces the entire recommendation/confirm block with the
   locked non-deniable explanation copy; no confirm button is rendered at all (not a disabled one).

### F. Impact Preview — screen-by-screen (CAP-09, D-19, D-20, D-22)

1. **Trigger:** any role↔capability matrix toggle in the Capabilities split-view detail, and any
   `Rolle zuweisen`/`Rolle entfernen` action on a user (D-22 — same preview pattern for both).
2. **Modal (size `lg`, over the matrix, per D-19):** title „Auswirkungs-Vorschau: {Capability-Label}
   für {Rolle}" (or „…für Rollenzuweisung {Benutzer}" for the D-22 case).
3. **Header counts row:** the five locked D-19 counts (Rolleninhaber / verlieren / gewinnen /
   behalten über andere Rolle / behalten über persönliche Abweichung), rendered as compact
   label+number pairs (Label/Caption typography, 12px/700), not large statistic tiles (D-05's
   "no giant stat tiles" principle extends here by analogy — these are inline counts inside a modal,
   not page-level KPI cards).
4. **Expandable detail table (`Accordion` wrapping a `Table`, or a paginated `Table` directly —
   planner's call per the open pagination question in 138-CONTEXT.md §6):** columns exactly
   `Benutzer | Gruppe | vorher | nachher | Grund`, matching the locked D-19 example table verbatim.
   Apply a hard cap + pagination for large role-holder counts (138-RESEARCH.md flags this as
   unbounded in principle — Claude's Discretion per CONTEXT.md §6, recommend: page size 25, sorted
   by "verliert das Recht" rows first since those are the highest-risk/most-actionable rows).
5. **Confirm/cancel:** per the Copywriting Contract row above; confirm stays disabled until the
   preview computation has finished (loading state inside the modal uses `LoadingState`, not a
   blocking full-page loader).
6. **Compute failure:** per the Copywriting Contract's "impact preview computation failed" error
   row — blocking, no mutation may proceed (D-18/D-20).

### G. Claims decision impact (D-24)

Reuse the same `Modal`-based impact-preview pattern (Section F) for `VerifyClaim`/
`ActivateClaimedMember` decisions, scaled down (no role-holder batch, single-user before/after).
Per 138-RESEARCH.md Pitfall 4/Open Question 1, confirm at plan/execution time which of the two
actions actually mutates rights-relevant state before wiring the preview to a specific endpoint —
the UI contract itself is action-agnostic (attach the same modal pattern to whichever action is the
real mutation point), but the copy must never fabricate a diff for an action that provably has no
rights effect (see the Copywriting Contract's honest fallback line).

### H. Änderungen (Audit) translation contract (D-25, D-26, D-27)

- One entry = one `Card variant="flat"` (or `TableRow` in the central list view) showing the locked
  D-25 sentence template: `wer → was → in welchem Kontext → vorher → nachher`.
- Vorher/Nachher lines render only when reconstructable from `audit_logs` (R-07); omit cleanly
  (no placeholder text) when not — this is a copy/data contract, not a visual one, but the layout
  must gracefully collapse (no empty label with blank value) when those two lines are absent.
- "Aktivität" (what a user did) and "Änderungen" (what an admin changed about identity/rights) never
  share one list or one filter set (D-26) — if both appear in the same user-detail tab area, they
  are visually and structurally separate sections, not interleaved rows.

### I. Beiträge display-bug fix (D-29 — narrow, visual-only scope)

`UserContributionsTab.tsx`'s `<Badge variant="info">Version {item.release_version_id}</Badge>` is
replaced with the real business label once the backend adds `release_versions.version` +
episode number to the projection (138-RESEARCH.md R-08): render as
`{Anime-Titel} · Episode {episode_number} · Version {version}` — reuse the existing `Badge`
component and existing tab layout; this is a data/copy fix, not a new visual pattern. Do not expand
this into grouping/range-collapse work (explicitly Phase 139 scope, D-29 binding).
