<objective>
Close 138-RESEARCH.md Pitfall 3 / CAP-10's only real backend gap: today `GrantCapability`/`RevokeCapability`
log a `ReloadCache` failure but never surface it in the HTTP response, so the frontend has no way to
honestly distinguish "gespeichert und aktiv" from "gespeichert, aber Cache-Reload fehlgeschlagen". This
plan adds the minimal, honest response-field extension (no new async status machine — none exists for
this path per R-05) and builds the shared `ActivationStatusIndicator` primitive both this mutation path
and the personal-override mutation path (wired by later plans) will render through.

Purpose: CAP-10 requires the UI to "never report stale enforcement as final success" — this is the one
place in the whole phase where that claim can currently be dishonest.
Output: an extended Grant/RevokeCapability response contract (full D-35 chain) plus a new, reusable
`@/components/ui` status-pill component.
</objective>
