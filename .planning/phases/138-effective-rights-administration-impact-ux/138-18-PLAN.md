<objective>
Close GAP-02: at 394px viewport width, `RoleCapabilityImpactPreviewModal` — the CAP-09/D-18/D-19
safety gate shown before every role-to-capability mutation — clips one of its five impact metrics
out of the visible area, forces horizontal scrolling to reach the decision-relevant "NACHHER" and
"GRUND" columns of the per-user impact table, and (per the plan-checker's blocker on the prior
revision of this plan) only fills the top quarter of the viewport height, leaving a large empty
gap below the content.

Purpose: An admin must never confirm a global role-capability change without seeing every metric
and every user's before/after impact, and the dialog must not look broken/unfinished on the exact
device widths D-32 requires supporting. Blind confirmation or a half-empty safety dialog on narrow
viewports both defeat the point of the impact-preview gate (D-18).

Root cause of the height symptom (confirmed by plan-checker review): `frontend/src/components/ui/ui.module.css`
forces `.modalPanel { height: 100dvh; max-height: 100dvh; }` inside its `@media (max-width: 767px)`
block (~line 1912), independent of how much content the modal actually has. This shared rule
applies to every modal in the app and must not be changed or weakened globally — instead, this
plan gives `RoleCapabilityImpactPreviewModal` an opt-in, component-scoped override via a new
optional `Modal` prop (`panelClassName`) that every other `<Modal>` call site simply never passes,
so their rendered output is byte-identical to before.

Output: A responsive metrics row that stacks to guarantee all 5 counts are visible, a narrow-width
per-user Card list (replacing the horizontally-scrolling table only below 759px, matching the
existing `RoleHoldersTable.tsx` responsive pattern) that surfaces vorher/nachher/Grund without
scrolling, and a component-scoped height override so the dialog sizes to its content instead of
forcing full-viewport height with dead space below. Desktop rendering and every other modal in the
app are byte-for-byte unchanged.
</objective>

```typescript
function useIsMobile(): boolean {
  const [isMobile, setIsMobile] = useState(false)
  useEffect(() => {
    if (typeof window === 'undefined') return
    const media = window.matchMedia('(max-width: 759px)')
    const onChange = () => setIsMobile(media.matches)
    onChange()
    media.addEventListener('change', onChange)
    return () => media.removeEventListener('change', onChange)
  }, [])
  return isMobile
}
```
