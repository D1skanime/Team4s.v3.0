<objective>
Wire the public member profile (`/members/[slug]`) avatar and background to the display-preferring
source added in 173-10, without regressing the EXISTING animated-avatar preservation behavior
(D-07) that `MemberProfileHero.tsx` already implements for GIF/animated-WebP avatars.

`MemberProfileHero.tsx` is a SHARED component used by BOTH the own-profile editor (`/me/profile`,
`isPublicView=false`, per D-04 explicitly out of this phase's scope) and the public profile
(`/members/[slug]`, `isPublicView=true`, this plan's actual target). Its existing animated-avatar
detection (`isGifAvatarURL`/`isAnimatedWebpSource`) inspects whatever URL is passed as `avatarURL`
by its file extension — if this plan simply swapped `avatarURL` itself to the display variant
(always a static `.jpg` per 173-05/173-10, even for an animated source), that detection would
silently stop firing and an animated avatar would regress to a static frame. Instead, this plan
adds two NEW, purely additive, optional props (`avatarDisplayURL`, `backgroundDisplayURL`) that
default to the existing `avatarURL`/`backgroundImageURL` when absent — meaning the `/me/profile`
caller, which this plan does not touch and will never pass the new props, renders byte-for-byte
identically before and after this plan. Only `MemberProfileContent.tsx` (the public-page caller)
passes the new props, computed from `profile.avatar?.display_url`/`profile.background_image?.display_url`
with a fallback to the unchanged `public_url`.

Purpose: completes D-02's component wiring for the LAST of the ten public surfaces named in
`173-CONTEXT.md`'s `<findings>` — "Member-Avatare und Profil-Hintergründe" — while keeping D-07's
animated-avatar guarantee intact by construction, not by convention.

Output: `types/profile.ts`'s `PublicMemberProfileData.avatar`/`.background_image` gain `display_url`;
`MemberProfileContent.tsx` passes the new display-preferring props; `MemberProfileHero.tsx` renders
the non-animated avatar branch and the background backdrop from the display-preferring source,
leaving the animated-avatar branch and the `/me/profile` caller byte-for-byte unchanged.
</objective>
