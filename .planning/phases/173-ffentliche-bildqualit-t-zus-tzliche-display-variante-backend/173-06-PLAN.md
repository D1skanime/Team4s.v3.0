<objective>
Resolve the D-15/D-06 contradiction found during research: `UploadOwnProfileStoryImage`
(`app_profile_story_image.go:148-157`) currently resizes to max 1600px and stores ONLY that single
file as `media_assets.file_path`, calling it "original" — there is no true 1:1 original anywhere.
Going forward, new uploads must store a TRUE 1:1 original (EXIF/GPS stripped, no resize) as a
`media_files` `variant='original'` row, while `media_assets.file_path` keeps pointing at a
long-edge-capped `display` file (same role the 1600px file played before — the TipTap story editor
embeds `media_assets.file_path` directly as the rendered `<img src>`, so this must not change
shape).

Purpose: write path #6c, the last of the three profile-upload sub-flows and the only one with a
genuine behavior change (not just an additive variant) — existing story images intentionally keep
their current 1600px file as their only asset; D-15 explicitly says "ein echtes Original existiert
für sie nicht mehr" (no true original exists for old rows), so this plan must NOT attempt to
retroactively invent one for pre-existing rows.

Output: new story-image uploads get both a true original (`media_files` row) and a display file
(`media_assets.file_path`); old rows are unchanged until 173-07's backfill adds a `display` row
for them (reusing their existing file, no new file written).
</objective>

func (r *MemberProfileRepository) InsertStoryImageAsset(ctx context.Context, input models.StoryImageUploadInput) (int64, error) {
	var id int64
	err := r.db.QueryRow(ctx, `
		INSERT INTO media_assets (file_path, mime_type, format, status, owner_member_id, created_at)
		VALUES ($1, $2, 'image', 'ready', $3, NOW())
		RETURNING id
	`, input.FilePath, input.MimeType, input.OwnerMemberID).Scan(&id)
	return id, nil
}
