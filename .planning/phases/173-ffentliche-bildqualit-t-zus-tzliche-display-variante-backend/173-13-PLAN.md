<objective>
Switch the three release-gallery/hero public components named in `173-CONTEXT.md`'s `<findings>`
to consume the display-preferring source via the global `ResponsiveImage` primitive (D-02), while
preserving D-03 (click-to-original, already correctly implemented via the existing
`FansubMediaLightbox`) and the one documented, intentional exception where `ResponsiveImage` cannot
be used (`HeroSection.tsx`'s Jellyfin/API-proxy branch, which needs conditional `unoptimized` that
the primitive does not expose).

- `ReleaseGallery.tsx`: the grid thumbnail (`renderImage`) currently sources
  `image.thumbnail_url ?? image.original_url` through a raw `next/image` `<Image unoptimized>` —
  switch the priority to `image.display_url ?? image.thumbnail_url ?? image.original_url` and
  swap to `ResponsiveImage`. The Kara preview (`renderKara`) already receives a display-preferring
  `preview_url` from 173-09's backend fix — only the component swap (raw `Image unoptimized` ->
  `ResponsiveImage`) is needed there, no src-priority change. The lightbox
  (`FansubMediaLightbox`/`toLightboxItem`) is UNTOUCHED — it already uses
  `original_url ?? thumbnail_url` and already implements D-03 correctly; this plan does not touch
  that logic, only verifies it via the must_haves grep.
- `projectPageData.releasePreview.ts`: `buildPublicReleasePreview`'s `imagePreviews` mapping
  currently picks `image.thumbnail_url ?? image.original_url` — add `display_url` as the first
  priority. This feeds `PublicReleaseBlock.tsx`'s `FeaturedRelease` (heroImage + preview tiles),
  which gets the matching `ResponsiveImage` swap (no click-to-original needed there — these tiles
  are not currently an "open" affordance, consistent with D-03 only applying where a click already
  does something today).
- `HeroSection.tsx`: the self-hosted banner/poster branch already conditionally sets
  `unoptimized={heroImageUrl.includes("/api/")}` — since `ResponsiveImage` hard-codes
  `unoptimized={false}` with no override, this plan splits the JSX into two branches: when
  `!heroImageUrl.includes("/api/")`, render `ResponsiveImage`; when it DOES include `/api/`
  (Jellyfin-sourced), keep the EXACT existing raw `next/image` `<Image unoptimized>` call,
  unchanged. `heroImageUrl`'s underlying backend source (`anime.banner_url`) is already
  display-preferring via 173-09.

Purpose: these are the three public release-surface components explicitly named in
`173-CONTEXT.md`'s `<findings>` whose backend sources are now display-preferring (173-08/173-09);
this plan is the component-level half of D-02 for the release/gallery/hero surface.

Output: `ReleaseGallery.tsx`, `projectPageData.releasePreview.ts`, `PublicReleaseBlock.tsx`,
`HeroSection.tsx` all consume the display-preferring source via `ResponsiveImage` (quality 85)
wherever `ResponsiveImage` can express the needed behavior; the one documented exception
(`HeroSection.tsx`'s Jellyfin branch) keeps raw `next/image unoptimized`, unchanged.
