<objective>
Add a `display` media-file variant (long edge <= 1920px, never upscaled, JPEG quality >= 88 for
static images; animated WebP for animated GIFs) to the global uploader's `processImage` function
in `backend/internal/handlers/media_upload_image.go`. Because `StoreGeneratedAnimeImage`
(`media_upload_segment_preview.go:119`) and the planned Phase 173 backfill CLI both call
`processImage` internally, this single change covers 3 of the 6 write paths named in
`173-RESEARCH.md`: the global uploader itself (all `asset_type` values including
`segment_preview`), the Kara segment auto-preview path (Phase 172), and (transitively, once
173-07 lands) the backfill tool.

Purpose: `processImage` is the shared insertion point PATTERNS.md and RESEARCH.md identify as the
highest-leverage write path — fixing it here automatically fixes the segment-preview/Kara-fallback
blurriness that triggered this phase (per `173-CONTEXT.md`'s "Live-Befund" line).

Output: `processImage` writes `original` + `thumb` + `display` (static images) or `original` +
`thumb` + `display` (animated WebP, for animated GIF sources) media_files rows. An exported
`GenerateAnimatedWebPDisplay` helper is added for the Phase 173 backfill CLI (173-07) to reuse.
</objective>
