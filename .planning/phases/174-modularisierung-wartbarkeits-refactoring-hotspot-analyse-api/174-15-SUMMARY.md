## Decisions Made
- Reused the project's existing Phase-117 real-Postgres fixture and `repository_test` external-package pattern (already proven by `admin_content_anime_theme_segments_hydration_integration_test.go` and `theme_segment_playback_resolution_integration_test.go`) rather than building a new harness — consistent with the plan's explicit guidance to read a sibling real-Postgres test file for the exact DB-setup/teardown protocol.
- Scoped Segment-cluster coverage to the plan's hard acceptance criteria (4 core CRUD methods) plus two natural, low-cost extensions (`GetAnimeSegmentByID`, the two library-read methods' fallback path) instead of attempting full coverage of all ~15 segment-library/playback-source/preview-image helper methods — those require schema not present in the shared fixture (`segment_library_definitions`/`segment_library_assets`/`segment_library_assignments`, `anime_source_links`) and the already-covered Phase-117 hydration integration test exercises the multi-release-version playback-source path these helpers feed.
- Patched `themes.id` to an identity column locally inside the test (isolated to this test's own schema) because the shared fixture defines it as a plain `BIGINT` — every prior fixture consumer supplied explicit IDs, so this is the first test to exercise `CreateAdminAnimeTheme`'s reliance on the real migration's `BIGSERIAL` auto-increment.
