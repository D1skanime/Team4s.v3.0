<objective>
Resolve RESEARCH.md's explicitly-flagged hardest Welle-2 decision point: the 30-function "media/assets" bucket spans admin-anime asset uploads, release-version media, segment asset uploads, and own-profile avatar/background/story uploads — RESEARCH.md's own analysis concludes this is evidence the target shape's single `media` module is too coarse, and recommends splitting media functions into their *consuming* domain modules rather than one shared `media.ts`, keeping only truly-shared upload mechanics centralized. This plan does that triage and places `replaceReleaseCrew` (the 1-function release-version-media/notes/crew bucket) into `releases.ts`.

Purpose: Avoid creating a second god-module (`media.ts`) that just recreates `api.ts`'s coupling problem under a new name — the whole point of D-08's domain split is reduced coupling, not relabeled coupling.
Output: `releases.ts` (new, release-version media/notes/crew + release-consuming media functions), `media.ts` (new, only genuinely shared mechanics, if any), existing `admin/anime.ts` and `members.ts` (from 174-03/174-04) gain the admin-anime-consuming and profile-consuming media functions respectively.
</objective>
