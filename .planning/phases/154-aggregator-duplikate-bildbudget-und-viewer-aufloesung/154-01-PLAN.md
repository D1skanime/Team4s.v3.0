<objective>
Remove the four duplicate query pairs in the public-member-profile aggregator (RCA-05 / P154-01..04)
by hoisting the four raw-count loader calls to run exactly once per request in
`GetPublicMemberProfileByID`, changing only the three consumer functions
(`loadRoleVolumeBadges`, `loadContributionBadges`, `loadBadgeProgress`) to accept pre-loaded counts
instead of re-querying. `GetOwnDashboard`'s independent use of the same four raw-count loaders must
keep compiling and behaving identically. No SQL changes, no blind parallelization, no join, no index
migration (all explicitly forbidden by CONTEXT.md A3).

Purpose: Structural query-count reduction (20 -> 16 without a project, per REPORT.md/RESEARCH.md) —
explicitly NOT a page-load speed claim (HTTP medians already 4-6ms; do not describe this as a
performance win).
Output: Aggregator issues each of the four duplicated facts once; badges/progress derivation stays
functionally separate; a Go regression test locks the new query count as a guard, not a benchmark.
</objective>
