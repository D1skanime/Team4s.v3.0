<objective>
Harden the shared `FocalCarousel` primitive (`frontend/src/components/ui`) for two concrete,
directly-observed a11y gaps (RESEARCH.md Pitfalls 4 and 5, confirmed by direct read of the current
485-line file): (1) expanding to grid view unmounts the just-clicked button and leaves focus
nowhere (the collapse direction already handles this correctly via `restoreFocusRef`, this plan
adds the missing expand-direction counterpart); (2) every carousel slide stays mounted and none of
the inactive ones are marked `inert`, so a keyboard user tabs through every slide's interactive
descendants in DOM order, not just the visible one (WAI-ARIA APG's documented carousel anti-pattern).
Because `FocalCarousel` is a single shared `@/components/ui` primitive used by every badge-chain
carousel, both fixes propagate everywhere in one change. Add `jest-axe` coverage (this plan is the
first consumer of Plan 133-01's setup) proving zero violations in each render state.

Purpose: PMA11Y-02 (full keyboard operability), PMA11Y-03 (correct name/state/status), PMA11Y-04
(DOM order matches visual/interactive reachability + automated evidence).
Output: `inert`-gated inactive slides, expand-direction focus management, axe-covered test suite.
</objective>

<interfaces>
Existing collapse-direction focus restoration to mirror (`FocalCarousel.tsx`, KEEP unchanged,
verified current lines 100-108 and 379-385):
```typescript
useEffect(() => {
  if (!expanded && restoreFocusRef.current) {
    restoreFocusRef.current = false
    const toggle = document.getElementById(toggleId)
    if (toggle) toggle.focus()
    else trackRef.current?.focus()
  }
}, [expanded, toggleId])
```
and the "Weniger anzeigen" button already sets `restoreFocusRef.current = true` before
`setExpanded(false)`.

Missing expand-direction counterpart: `setExpanded(true)` is called from two sites with no focus
follow-up — inside `renderItem`'s `showAll: () => setExpanded(true)` callback (passed to every
rendered item so any item can trigger expand) and the `showAllLabel` toggle `Button`'s own
`onClick={() => setExpanded(true)}`. Add an `expandFocusRef` (same `useRef(false)` shape as
`restoreFocusRef`), set it to `true` at both `setExpanded(true)` call sites, and add a new
`useEffect` keyed on `expanded === true` that focuses the "Weniger anzeigen" button. That button
currently has no stable `id` — give it one (e.g. `` `${gridId}-collapse` ``, mirroring
`toggleId = \`${gridId}-toggle\`` already declared) so the new effect can `document.getElementById(...)`
it, consistent with how the collapse effect locates `toggleId`.

Missing inert on inactive slides (`FocalCarousel.tsx`, current `itemWindow` map, lines ~429-458):
```typescript
<div
  key={getItemKey(item)}
  data-focal-item
  role={listLabel ? 'listitem' : undefined}
  className={classNames(styles.itemWindow, itemClassName, isActive && styles.itemWindowActive, isActive && activeItemClassName)}
  aria-current={isActive ? 'true' : undefined}
  ...
>
```
`isActive` is already computed in the render body (`const isActive = index === safeIndex`) — add
`inert={!isActive}` directly to this JSX (React 18.3 forwards the `inert` DOM attribute on host
elements); no new effect needed since it re-evaluates on every render already driven by
`activeIndex`/`safeIndex` changes.
</interfaces>
