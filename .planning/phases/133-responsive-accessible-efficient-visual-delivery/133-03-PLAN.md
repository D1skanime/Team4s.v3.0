<objective>
Convert `profile.module.css`'s hero-panel responsive rules from device-width `@media` to
`@container` queries, per CONTEXT.md D-01/D-03 and UI-SPEC.md's "Responsive strategy" contract:
"every reusable component uses @container exclusively for its own internal responsive behavior."
`profile.module.css` currently has 5 `@media` blocks and 0 `@container` blocks (RESEARCH.md's
`@media`/`@container` count table) — it is the one reusable-component CSS module in this phase's
scope that has NOT started the container-query migration `FocalCarousel.module.css` already
completed. This plan updates the existing hard-coded CSS-locking regression test in
`MemberProfileHero.test.tsx` (lines ~136-150) in the same change, since it currently asserts the
exact `@media (max-width: 1099px)`/`@media (max-width: 760px)` text that this conversion removes.

Purpose: satisfy PMUI-03 for the hero component specifically (the largest visible reusable block on
the profile page) and keep it correct when the hero renders inside a narrower column than the full
viewport (e.g. the two-column `.profilePair` layout `page.module.css` already provides).
Output: container-query-driven `.heroPanel`/`.heroAvatar` rules; updated locking test.
</objective>
