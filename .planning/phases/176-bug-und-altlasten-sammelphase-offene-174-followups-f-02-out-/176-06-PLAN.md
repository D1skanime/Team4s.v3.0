<objective>
Close Permission-Matrix rows 6.1/6.2 (176-CONTEXT.md D-18): the Notizen tab's visibility gate
(`fansubEditAccess.ts:46`) is an OR of `can_edit_notes || can_edit_founding_history`, but `NotesTab`
itself has zero permission gating on its add/edit/delete group-note controls -- a user let in solely
via `can_edit_founding_history` (who should only be able to edit the group's founding-history entry,
per the already-live `GroupHistorySection`'s `foundingOnly` flag) currently gets full, unrestricted
group-note CRUD rights they were never granted.

Purpose: founding-history-only editors are a real, already-used capability tier in this codebase
(`FansubEditSecondaryTabs.tsx` already computes a `foundingOnly` boolean for `GroupHistorySection`
right next to `NotesTab` in the same tab) -- this plan brings `NotesTab` up to the same standard
rather than leaving it as the one ungated surface in an otherwise-capability-aware tab.
Output: `NotesTab` accepts a `canEditNotes` prop that hides/disables all group-note mutation
controls when false; `FansubEditSecondaryTabs` computes and passes it using the same
capability-derivation pattern already used for `GroupHistorySection`'s `foundingOnly`.
</objective>
