   `.planning/phases/134-fixture-backed-verification-rollout/evidence/screenshots/{slug}-{viewport}.png`
   (full-page screenshot, `fullPage: true`).
3. Keyboard-focus check: press `Tab` up to 15 times, and after each press capture
   `document.activeElement`'s tag name + whether it has a visible focus outline (`getComputedStyle
   (document.activeElement).outlineStyle !== 'none'` OR a custom focus-visible class per this
   codebase's established focus-ring convention — check `frontend/src/components/ui/FocalCarousel.tsx`'s
   existing focus-visible pattern if uncertain). Record the sequence of focused element
   tag+role/aria-label pairs to a JSON file
   `.planning/phases/134-fixture-backed-verification-rollout/evidence/{slug}-{viewport}-keyboard.json`;
   fail (throw, non-zero exit) if ANY of the first 15 Tab stops lands on an element with no visible
   focus indicator.
4. Print a summary line per profile+viewport: screenshot path, keyboard-check pass/fail, page title.

The script must fail loudly and exit non-zero if any profile+viewport combination fails to reach
`networkidle` within a reasonable timeout (30s) or if the keyboard-focus check finds an unfocusable
control — do not silently skip a broken combination.
