<objective>
Build the two presentation-only upload primitives (`UploadDropzone`, `UploadFileRow`) that D-13 requires
every one of the eight upload surfaces to eventually render through, and register them in the
`/dev/ui-system` showcase per the project's global-UI-system rule (CLAUDE.md). These primitives contain

separate plan (180-02) and lives under `frontend/src/hooks/`, never under `components/ui`
(180-RESEARCH.md Pitfall 1; `/dev/ui-system/page.tsx:140` states "Keine Team4s-Fachlogik in
`src/components/ui`" as an active rule).

Purpose: Give every later plan in this phase (Weg 1/2 functional migration, Weg 3-8 presentational
adoption) a single, already-built, already-tested component to import instead of re-implementing
dropzone/file-row markup six more times.
Output: `UploadDropzone.tsx`, `UploadFileRow.tsx` (+ CSS modules + tests), barrel-exported, shown in
`/dev/ui-system`.

**Note (D-17, 2026-10-11):** `allowDrop` keeps its generic `false` branch and test coverage here —
it is still a legitimate, documented part of the primitive's public API (default `true`). After
D-17, no per-way adoption plan (180-05/07/08/09/10/11) passes `allowDrop={false}` anymore; this
plan does not need to remove anything now, but the final full-gate plan (180-12) greps for
`allowDrop={false}`/`allowDrop: false` across the codebase and, if the false branch is confirmed
to have zero live callers, removes the now-dead `allowDrop === false` handling path from
`UploadDropzone.tsx` instead of leaving it unexercised. Keep the branch testable and working in
this plan regardless — the removal decision happens later, with full visibility into every way's
final prop values.
