# Phase 180 — UI Design Contract

> Visual and interaction contract for the shared `UploadDropzone` + `UploadFileRow` presentation
> primitives (D-13) and their functional integration into Weg 1 (Release-Medien) and Weg 2
> (Gruppenmedien, D-01). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **No shadcn gate applies.** This project does not use shadcn (no `components.json` found) and
> is not meant to adopt it: `CLAUDE.md` mandates a project-owned, already-established global
> primitive library under `frontend/src/components/ui` (`Button`, `Input`, `Textarea`, `FormField`,
> `Badge`, `Card`, `Drawer`, `SectionHeader`, `EmptyState`, `ErrorState`, …), showcased at
> `/dev/ui-system`. D-02 (locked, 180-CONTEXT.md) explicitly requires the new upload baustein to
> reuse exactly this library, not a new system. Asking to initialize shadcn here would contradict
> an explicit, binding project rule — so this contract documents the existing internal system
> instead of running the shadcn gate.
>
> **Korrektur (D-17, 2026-10-11):** Die Per-Way Adaptation Matrix hatte `allowDrop=false` für
> Weg 3/5/6/7/8 gesetzt, obwohl dort dieselbe ablege-einladende `UploadDropzone` erscheint — das
> hätte das Missverständnis erzeugt, das D-16 vermeiden soll. Korrigiert: `allowDrop=true` auf
> allen acht Wegen, Abläufe/Rechte bleiben unverändert getrennt. Siehe D-17 in `180-CONTEXT.md`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — project-owned internal design system |
| Preset | not applicable |
| Component library | custom internal library at `frontend/src/components/ui` (showcased at `/dev/ui-system`) |

**Binding rule carried over from CLAUDE.md:** every user-facing element in the two new primitives
and in all 8 adapted upload surfaces MUST be built from `@/components/ui` (`Button`, `Input`,
`Textarea`, `FormField`, `Badge`). No hand-rolled native `<input>`/`<button>`/`<select>` for
anything these primitives already cover — this is a hard gate, not a style preference. (Note for
the planner/executor: `AnimeJellyfinAssetUploadControls.tsx`, Weg 4's current implementation,
already violates this rule today with raw `<button className={styles.button}>` markup sourced
from `AdminStudio.module.css` instead of the global `Button` component — adopting `UploadDropzone`/
`UploadFileRow` there is the opportunity to fix this pre-existing debt as a side effect, not an
additional in-scope task on its own.)

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg-primary)` (#f9f9f9) | Page/drawer background the dropzone sits on |
| Secondary (30%) | `var(--bg-card)` / `var(--surface-card)` (#ffffff) | `UploadFileRow` card surface, idle dropzone fill base |
| Accent (10%) | `var(--accent-primary)` (#5f84dd) | Dropzone dashed border + background tint **only while dragging/hovering/focused**; primary "Upload starten" button; `<progress>` `accent-color` |
| Destructive | `var(--color-error)` (#dc3545) | Failed-status text/background only; error message text under a failed row |

Accent (`--accent-primary`) reserved for: the dropzone's active-drag border/background tint, the
`UploadDropzone`'s click-focus ring (inherits global `:focus-visible` token, not a new one), and
the primary "Upload starten" `Button`. It is explicitly **not** used for idle borders, body text,
or the status chips below — those are semantic, not accent.

**Status feedback colors (informational, non-interactive — reuse the existing `Badge` component,
do not reinvent CSS classes):**

| Upload status | `Badge` variant | Label |
|---|---|---|
| `idle` (queued, not yet started) | `muted` | „Wartet" |
| `uploading` | `warning` | „Lädt hoch …" |
| `processing` | `warning` | „Wird verarbeitet …" |
| `ready` | `success` | „Hochgeladen" |
| `failed` | `danger` | „Fehlgeschlagen" |

This replaces the bespoke `.idle`/`.uploading`/`.processing`/`.ready`/`.failed` CSS classes
currently hand-rolled in `ReleaseVersionMediaSection.module.css:492-511` with the shared `Badge`
primitive — a direct application of D-02's "use global primitives/tokens instead of
hand-rolled markup" rule to a case the original Weg-1 implementation missed.

## Component Inventory

Two presentation-only primitives (D-13, no `@/lib/api` imports, no Team4s business logic — the
`/dev/ui-system` page itself states "Keine Team4s-Fachlogik in `src/components/ui`" as an active
rule, see `frontend/src/app/dev/ui-system/page.tsx:140`) plus one orchestration hook that stays
**outside** `components/ui`.

### `UploadDropzone` (new, `frontend/src/components/ui/UploadDropzone.tsx`)

| Prop | Type | Default | Purpose |
|------|------|---------|---------|
| `onFilesSelected` | `(files: File[]) => void` | required | Fires on click-picked or dropped files |
| `accept` | `string` | `'image/*'` | Native `<input accept>`, browser-level hint only — never the sole validation |
| `multiple` | `boolean` | `true` | `false` for every single-slot way (3/4/5/7) |
| `allowDrop` | `boolean` | `true` | `false` disables the drag&drop surface and falls back to click-only. **Correction (D-17, 2026-10-11): no way sets this to `false` anymore** — all eight ways use the default `true`, so every rendered dropzone that invites dropping actually accepts a drop. The prop remains part of the primitive's API for future use; if plan 180-01 finds the `false` branch has zero remaining callers after this correction, remove the dead branch rather than keep it unexercised (see 180-CONTEXT.md D-17) |
| `disabled` | `boolean` | `false` | Mirrors each way's existing capability/busy gate |
| `density` | `'roomy' \| 'compact'` | `'roomy'` | Controls padding/icon/typography only — never a fixed pixel width/height. The parent page's existing layout (e.g. Weg 4's `assetPreviewFrame`/`assetStateEmpty` slot, `aspect-ratio: 2/3` or `16/9`) still owns the outer box size; the dropzone fills `100%`/`100%` of whatever container it is given. This is what lets Weg 3–8 reuse the same component without a layout rewrite. |
| `promptLabel` | `string` | „Dateien hier hineinziehen oder zum Auswählen klicken." | Override for single-slot/video contexts if the default sentence doesn't fit |
| `dropHintLabel` | `string` | — | Context line under the prompt (category, "nur ein Bild", etc.) |
| `multiFileOnSingleSlotWarning` | `string` | D-16's locked sentence | Shown when `multiple=false` and more than one file is dropped; only the first file is forwarded to `onFilesSelected` |

States: `idle`, `hover/focus` (click-affordance), `dragging` (accent border+tint, only reachable
when `allowDrop`), `disabled` (opacity ~0.62, `cursor: not-allowed`, matches existing
`.dropZoneDisabled`). Keyboard: `role="button" tabIndex={0}`, `Enter`/`Space` opens the native file
picker — same contract as the existing Weg‑1/Weg‑2 dropzones, just consolidated into one component
instead of two near-identical implementations.

## Interaction & State Contract

- **Primary visual anchor (Checker Dimension 2 follow-up):** Before any file is queued, the idle
  `UploadDropzone` prompt is the primary visual anchor on the upload screen. Once at least one
  file is queued, the anchor shifts to the „Upload starten"-Button (primary accent CTA) — the
  dropzone recedes to a secondary "add more files" affordance beneath the queue.
- **D-09 (Drag&Drop):** One `UploadDropzone` implementation replaces the two near-identical
  `onDrop`/`onDragOver` handlers in `ReleaseVersionMediaSection.tsx:283-306` and
  `GroupMediaReviewUploadPanel.tsx:87-95`. Click-to-pick always works regardless of `allowDrop`.
- **D-10 (explicit trigger):** No file ever uploads on selection/drop alone. Files sit in the
  `UploadFileRow` list in `idle` status until „Upload starten" is clicked.
- **D-11 (optional fields):** `UploadFileRow`'s `title`/`caption` `FormField`s never render a
  required-asterisk and never block submission when empty.
- **D-12 (single retry):** Only the failed row's own `onRetry` re-runs; sibling `ready` rows never
  re-upload. The hook branches exactly like the existing
  `useReleaseVersionMedia.ts:250-269` `resultId === null` check — re-upload the file if no result ID
  exists yet, otherwise only re-patch metadata.
- **D-16/D-17 (multi-drop-on-single-slot, generalized to every single-slot way):** If more than
  one file lands on a `multiple={false}` dropzone, only `files[0]` is forwarded to
  `onFilesSelected`; the dropzone immediately renders `multiFileOnSingleSlotWarning`'s locked text
  inline. This guard is built generically into `UploadDropzone` itself (keyed off `multiple`, not
  off which way is calling it) — originally scoped to Weg 4 under D-16, it now applies equally to
  Weg 3/5/7 once D-17 sets `allowDrop=true` there too. Reuse each way's existing inline
  error/status text slot — e.g. Weg 4's existing `onError` callback path — do not introduce a new
  toast/snackbar mechanism for this.
- **D-17 (Drag&Drop on all eight ways):** `allowDrop` is `true` for every way (see Per-Way
  Adaptation Matrix) — no way renders a drop-inviting prompt that then silently ignores a drop.
  File-type validation stays each way's own existing check (e.g. Weg 5 still only accepts video
  files; a wrong-type drop surfaces that way's existing error message, unchanged by this phase).
  Rights/visibility are untouched (Phase 179 remains authoritative, e.g. Weg 4's
  `isPlatformAdmin` gate).
- **Review-status neutrality (Pitfall 5):** Neither primitive nor `useUploadQueue` knows about
  `review_status`. That remains a per-way adapter concern (Weg 2 passes `reviewStatusCode:
  'in_review'`, Weg 1 passes nothing) — this is a hook/adapter contract note, not a visual one, but
  stated here so the executor doesn't accidentally surface a review-status prop on the shared
  primitives.

## Accessibility Contract

- `UploadDropzone`: `role="button"`, `tabIndex={0}` when enabled (`-1` when disabled),
  `aria-disabled` mirrors `disabled`, `Enter`/`Space` triggers the same action as click. Visible
  focus uses the existing global `:focus-visible` token (`globals.css:227-230`) — no new focus
  style.
  Visually hidden `<input type="file">` keeps `aria-label="Dateien"` (or a per-way override, e.g.
  "Bild" for single-slot contexts) so screen readers announce the real control, not just a `div`.
- `UploadFileRow`: status chip lives inside an `aria-live="polite"` region (matches existing
  `ReleaseVersionMediaUploadQueue.tsx:87`) so status transitions are announced without re-reading
  the whole row. The `<progress>` element gets `aria-label={'Übertragung: ' + file.name}`.
- Both primitives are keyboard-reachable without a mouse; drag&drop is an **enhancement**, not the
  only path to select a file, in every one of the 8 ways.
