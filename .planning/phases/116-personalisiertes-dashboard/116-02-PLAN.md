<objective>
Add the one, small, read-only backend aggregation that Phase 116's D-03 (5 Kennzahlen) and D-04
(Fortschritt je Kategorie) need but which does not exist anywhere in the codebase today: a
dedicated `GET /api/v1/me/dashboard` endpoint bundling total points, a real badge count, a new
"Projekte (Anzahl)" aggregate, images/contributions counts, per-role volume counts, and per-family
next-threshold progress for the three Phase-113 contribution badge families.

Purpose: `GetOwnProfile` never loads points or live-derived badges (they only exist inside
`GetPublicMemberProfile`), and the three Phase-113 tier functions
(`highestContribProjectsTier`/`highestContribChronicleTier`/`highestContribArchivistTier`) and the
Phase-112 `highestRoleVolumeTier` function all discard the raw count after deriving a tier string —
exactly the raw count the dashboard needs for "noch X bis nächste Stufe" is thrown away today. This
plan extracts that raw count without touching the public profile's existing output, then bundles it
behind one new authenticated GET so the frontend never needs a 5-6-request fan-out.

Output: refactored raw-count extraction in the two existing Phase-112/113 repository files (behavior-
preserving), a new `member_profile_dashboard_repository.go`, a new `dashboard_me_handler.go` using
the mandatory `resolveVerifiedMemberIDForAppUser` ownership gate, the new route wired in `main.go`,
and the additive OpenAPI contract entry.
</objective>
