## Page Composition & Section Contracts

Reihenfolge (Claude's Discretion laut CONTEXT.md, Mockup v2 abgestimmt — **verbindlich für diesen Plan**, nicht mehr offen):

```
PageHeader ("Mein Bereich" · "Dashboard")
  └─ 1. AttentionSection        (D-02, prominent direkt unter PageHeader)
  └─ 2. DashboardMetrics        (D-03, 5 HeroMetrics-Kacheln)
  └─ 3. CategoryProgressTable   (D-04, Table)
  └─ 4. MyGroupsSection         (D-05, reuse MembershipsSection)
  └─ 5. QuickLinksSection       (D-06, Card-Grid mit Buttons/Links)
```

Empfohlene Dateistruktur (450-Zeilen-Limit; `page.tsx` bleibt reine Promise.all-Orchestrierung analog `frontend/src/app/me/profile/page.tsx`):

```
frontend/src/app/me/dashboard/
├── page.tsx
├── page.module.css                 (nur Grid/Section-Spacing, keine neuen Farbwerte)
└── components/
    ├── AttentionSection.tsx        (D-02)
    ├── DashboardMetrics.tsx        (D-03)
    ├── CategoryProgressTable.tsx   (D-04)
    ├── MyGroupsSection.tsx         (D-05, dünner Wrapper um MembershipsSection + Empty-State-Gate)
    └── QuickLinksSection.tsx       (D-06)
```

### 1. „Braucht deine Aufmerksamkeit" (D-02)

- **Primitive:** `SectionHeader` (title wie oben) + Liste aus `Card variant="interactive"` (identisches Muster zu `MembershipsSection.tsx` — anklickbare Card mit `Link`).
- **Zeileninhalt je Eintrag:** Anime-/Release-Titel (fett), Rollen-/Gruppenkontext (Sekundärtext), `Badge variant="info"` „Neu" wenn `isRecentlyAssigned(created_at, windowDays=14)` true, rechtsbündig ein Chevron/Pfeil-Icon (`ArrowRight` aus `lucide-react`, analog `MembershipsSection`-Zeile 81) als reines Dekor (`aria-hidden`).
- **Sortierung:** absteigend nach `created_at`/`confirmed_at` (neueste zuerst) — kein Server-Sort nötig, Client-seitig.
- **Link-Ziel je Zeile:** `release_version_id` vorhanden → `/me/releases/${release_version_id}/workspace`; sonst → `/me/projects/${anime_id}/group/${fansub_group_id}` (Pattern 2 aus RESEARCH.md, wörtlich übernehmen).
- **Empty State:** `EmptyState` Primitive (kein eigenes `<p>`), Copy siehe Copywriting-Tabelle, `variant="compact"` (kurze, unaufdringliche Darstellung, da dies eine „gute Nachricht"-Leere ist, kein Fehlerzustand).
- **Kein Datum-Rohtext anzeigen** (kein „vor 3 Tagen"-Zusatztext gefordert) — die „Neu"-Badge allein reicht als D-02-Signal; kein neues Zeit-Format-Utility einführen.

### 2. Deine Zahlen — 5 Kennzahlen (D-03)

- **Primitive:** exakt `HeroMetrics` mit `items` = 5 Einträge in fester Reihenfolge: Punkte, Badges, Projekte, Hochgeladene Bilder, Geschriebene Beiträge.
- **Kein eigenes Grid bauen** — `HeroMetrics` ist bereits responsiv (Media Query `ui.module.css:269-278` verkleinert Schriftgröße < 640px, Grid stackt automatisch); keine Anpassung nötig.
- **Datenquelle:** neuer `GET /api/v1/me/dashboard`-Endpunkt (Backend-Aggregation, D-08) — **nicht** `getMyBadges()` (zählt nur persistierte Badges, s. RESEARCH Pitfall 1) und **nicht** `previous_contributions_count` (zählt abgeschlossene Projekte, s. Pitfall 2).
- **Zahlenformat:** reine Ganzzahl ohne Nachkommastellen, keine Tausendertrennzeichen-Bibliothek nötig bei erwarteten Wertebereichen (`toLocaleString('de-DE')` reicht falls Punkte > 999).
- **Kein Empty State nötig** — alle 5 Werte haben immer einen sinnvollen Default (0), auch für brandneue User.
- **Umrahmung:** `SectionHeader title="Deine Zahlen"` direkt über der `HeroMetrics`-Instanz, keine zusätzliche `Card` außenrum (HeroMetrics hat bereits eigenes Kachel-Styling).

### 3. Fortschritt je Kategorie (D-04)

- **Primitive:** `Table`/`TableHead`/`TableBody`/`TableRow`/`TableHeaderCell`/`TableCell`, `variant="compact"`.
- **Spalten:** „Kategorie" | „Aktuelle Stufe" | „Fortschritt".
- **Zeilen (feste Reihenfolge, eine Zeile je Familie):** Punkte-Meilenstein → Rollen-Volumen **je aktiver Rolle des Members** (kann 0–N Zeilen sein, je nachdem in wie vielen Rollen der User aktiv war) → Bildarchivar → Chronist → dokumentierte Projekte (Phase 113).
- **„Aktuelle Stufe"-Zelle:** wiederverwendetes Badge-Presentation-Muster (`getMemberBadgePresentation`/`resolveRoleVolumePresentation` aus `memberBadgeLabels.ts`) — rendert als `Badge` mit passendem `variant`/Label, NICHT als reiner Text, damit die Farbcodierung (Bronze/Silber/Gold/Platin etc.) konsistent mit den bestehenden Profil-/Public-Ansichten bleibt.
- **„Fortschritt"-Zelle:** Text „noch {next_threshold - current_count} bis {next_tier_label}", z. B. „noch 38 bis Silber"; wenn keine höhere Stufe existiert: „Höchste Stufe erreicht" (kein Fortschrittsbalken/Progress-Bar-Komponente einführen — reiner Text reicht, da kein solches Primitive im System existiert und ein neues Balken-Element eine neue Designsprache wäre).
- **Schwellen:** ausschließlich aus bestehenden, bereits im Projekt gepflegten Konstanten konsumieren (`POINT_MILESTONES`, `ROLE_VOLUME_TIER_THRESHOLDS` aus `memberBadgeLabels.ts`; Contribution-Familien-Schwellen aus Phase 113 Backend-Konstanten) — **niemals neue Schwellenwerte in dieser Phase definieren** (harter Konstraint aus D-04/RESEARCH Anti-Pattern).
- **Responsive:** Tabelle nutzt das bestehende `styles.tableWrap`-Scroll-Verhalten (horizontales Scrollen bei schmalen Viewports) — kein Kartenformat-Fallback für Mobile nötig, da `Table` dieses Verhalten bereits global für das Projekt definiert.
- **Empty State:** `TableEmptyState` (Primitive-Bestandteil von `Table`) mit `colSpan={3}`, Copy siehe Copywriting-Tabelle, nur wenn der User **gar keine** Kategorie-Aktivität hat (kein Member-Profil oder keine einzige Contribution/Rolle) — nicht pro einzelne Zeile.

### 4. Meine Gruppen (D-05)

- **Primitive:** **direktes Reuse** von `frontend/src/components/profile/MembershipsSection.tsx` — keine neue Komponente für die Kartendarstellung bauen. Diese Komponente verlinkt bereits korrekt auf `/fansubs/${fansub_group_slug}` (öffentliches Gruppenprofil), **nicht** auf `/admin/fansubs/${id}/edit` — exakt die in D-05/Pitfall 5 geforderte Korrektur ist hier bereits vorhanden.
- **Wrapper-Kontrakt (`MyGroupsSection.tsx`):** Prop `title` explizit auf „Meine Gruppen" setzen (Komponentendefault ist „Fansub-Gruppen" — für den Dashboard-Kontext überschreiben).
- **D-09-Empty-State-Override (verbindlich):** `MembershipsSection` selbst zeigt bei leeren `memberships` nur einen schlichten `<p>`-Text ohne Sprungziel (`styles.emptyText`, kein `@/components/ui`-Primitive, kein Call-to-Action). Das **erfüllt D-09 nicht** (friendly EmptyState **mit Absprung** ist gefordert). Deshalb: Der Wrapper `MyGroupsSection.tsx` MUSS bei `memberships.length === 0` **statt** `MembershipsSection` zu rendern, direkt `EmptyState` (title/body/action gemäß Copywriting-Tabelle, `action` = `Button` „Fansub-Gruppen entdecken" → `/fansubs`) rendern. Nur bei `memberships.length > 0` wird `MembershipsSection` wie gehabt eingebettet.
- **Kein zweiter Link auf die Admin-Edit-Route** — bewusst weggelassen (Claude's Discretion, siehe RESEARCH Pitfall 5): das Dashboard ist read-only Cockpit, ein optionaler Zweitlink nur für Leader wäre zusätzliche Komplexität ohne D-05-Anforderung.

### 5. Schnellzugriffe (D-06)

- **Primitive:** `SectionHeader title="Schnellzugriffe"` + Grid aus `Card variant="interactive"` (analog Sektion 1/4) ODER direkt `Button`-Reihe — **Entscheidung:** `Card`-Kacheln (Icon + Label), da 5 gleichrangige Sprungziele besser als Kachel-Grid lesbar sind als eine reine Button-Leiste; erster Eintrag zusätzlich mit `variant="primary"`-Akzent (siehe Color-Kontrakt).
- **Reihenfolge (verbindlich, D-06):** Anime entdecken (`/anime`, `Compass`-Icon) → Rangliste (`/members/ranking`, `Trophy`-Icon) → Fansub-Gruppen (`/fansubs`, `Users`-Icon) → Suche (`/suche` bzw. defensiv deaktiviert, `Search`-Icon) → Mein Profil (`/me/profile`, `UserCircle`-Icon). Icons identisch zu den bereits in `AppShell.tsx` für dieselben Ziele verwendeten `lucide-react`-Icons (Konsistenz Nav ↔ Dashboard).
- **Suche-Route-Gate (Pitfall 3, verbindlich):** Vor dem Rendern MUSS geprüft werden, ob `/suche` zum Ausführungszeitpunkt existiert (z. B. über ein statisches Feature-Flag/Prüfung analog dem bestehenden AppShell-Muster `disabled: true, badge: 'bald'`). Existiert die Route: normale anklickbare Card. Existiert sie nicht: Card in deaktiviertem visuellem Zustand (reduzierte Opazität, `aria-disabled="true"`, kein `<Link>`, sondern ein nicht-interaktives Element) mit `Badge variant="muted"` „bald" statt Klickziel — **niemals** auf eine 404-Route verlinken.
- **Kein eigenes Such-UI** — reiner Sprungpunkt, exakt wie D-06 fordert.

## Accessibility & Responsive Contract

- **Semantische Struktur:** `PageHeader` rendert `<header>`/`<h1>`, jede Sektion nutzt `SectionHeader` (`<h2>`) — keine eigene Heading-Hierarchie erfinden.
- **Icon-only Links/Buttons:** jedes rein-dekorative Icon (Chevron/Pfeil in Aufmerksamkeits-/Gruppen-Zeilen, Quick-Access-Icons neben Text-Label) erhält `aria-hidden="true"` (bestehendes Muster, siehe `MembershipsSection.tsx:71/81`). Falls ein Icon *ohne* begleitendes Textlabel verwendet würde (kommt in dieser Phase nicht vor, da jede Kachel ein Label führt), wäre `aria-label` Pflicht.
- **Tastaturnavigation:** alle Sprungziele sind reguläre `<a>`/`Link`- oder `Button`-Elemente (via `Card variant="interactive"` + `Link`-Wrapper, identisch zu `MembershipsSection`) — kein `onClick`-only `<div>`. Deaktivierte „Suche"-Kachel ist kein fokussierbares interaktives Element (kein `tabIndex`, kein `href`), da sie keine Aktion anbietet.
- **Responsive Breakpoints:** keine neuen Breakpoints definieren — alle verwendeten Primitives (`HeroMetrics`, `Table`, `Card`) haben bereits projektweite Responsive-Regeln (`ui.module.css`). Sektionen stapeln automatisch vertikal in einem einspaltigen Flow (Standard-Block-Layout, kein CSS-Grid mit fixen Spalten außerhalb der Primitives nötig).
- **Farbkontrast:** keine neuen Farbwerte eingeführt (siehe Color-Kontrakt) — bestehende Primitive-Kontraste gelten unverändert als geprüft.
- **`aria-live` für Zustandswechsel:** nicht erforderlich — Datenladen erfolgt einmalig beim Seitenaufruf (`Promise.all`), kein Streaming/Polling-Update, das eine Live-Region bräuchte.
