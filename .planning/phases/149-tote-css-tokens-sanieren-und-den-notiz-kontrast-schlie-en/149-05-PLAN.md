<objective>
Build the permanent regression guard that ROADMAP Phase 149 calls for: an automated test, running
in the regular `vitest` suite, that fails — naming token, file, and line — the moment a new
fallback-free reference to an undefined CSS custom property is introduced anywhere under
`frontend/src`. This closes the defect class Plans 149-01/02/03 just fixed by hand, so it cannot
silently reappear.

Purpose: the 39 occurrences fixed by Block A were invisible to every existing test — `var()`
references to undefined properties are not TypeScript errors, not ESLint errors, and not runtime
errors; they just silently degrade to the inherited/initial color. Without a dedicated scanner,
the next similarly-named typo or copy-paste from a removed token reintroduces the same class of
bug with zero test signal.

Output: `frontend/src/lib/cssCustomProperties.ts` (pure scanner logic, no file I/O) and
`frontend/src/lib/cssCustomProperties.guard.test.ts` (synthetic-fixture unit tests proving the
scanner's detection rules, plus a real-tree integration test run against the actual, now-fixed
`frontend/src`).
</objective>

  file: string
  line: number
  name: string          // e.g. "--color-text-muted"
  hasFallback: boolean
  fallbackVarName?: string  // set only when the fallback argument is itself a var(--x) reference
}

export function extractDefinedProperties(fileContents: Map<string, string>): Set<string>
// Scans declaration-position custom properties only (e.g. "--x:" inside a rule body or inline
// style object key), across ALL provided files — both top-level (:root, .foo { --x: ... }) and
// TSX inline-style object literal keys (style={{ '--x': value }}).

export function extractVarUsages(fileContents: Map<string, string>): CustomPropertyUsage[]
// Scans every var(--name) / var(--name, fallback) occurrence, per file, with 1-based line number.

export function findDeadReferences(
  defined: Set<string>,
  usages: CustomPropertyUsage[],
): CustomPropertyUsage[]
// A usage is dead if: (a) no fallback and name not in defined, OR (b) has a fallback whose
// fallbackVarName is itself set and not in defined (one-level nested var() fallback check — the
// Breadcrumbs.module.css class of bug). A usage with a literal (non-var) fallback, or a fallback
// var() that IS in defined, is never dead.
