<objective>
Fix Live-UAT-Befund 20: `ReleasePreviewRow`'s data lines (`techLine`/`extrasLine`/`dateLine`)
currently start at the left edge of `.content` (a single-column grid), which is the SAME edge as the
avatar column, instead of being indented to align with `groupName`/`releaseName`'s text column. This
plan restructures the row so ALL text content (group name, release name, and the three data lines)
lives in ONE vertical `Stack`, placed beside the avatar(s) via `Cluster` with wrapping disabled —
per `192-CONTEXT.md`'s Befund-20 decision, which explicitly permits either `SplitLayout` or `Cluster`
("je nachdem, was dem bestehenden Avatar+Text-Aufbau am nächsten liegt").

Purpose: `SplitLayout` is deliberately NOT used here (a documented, CONTEXT.md-permitted deviation
from `192-UI-SPEC.md`'s illustrative consumption-map suggestion): `SplitLayout`'s container-query
threshold (768px/1024px) would stack the avatar ABOVE the text at the mandated 390px mobile
screenshot width, which the current `.identity` flex row never does at any width — a real visual
regression the zero-pixel-diff contract forbids. `Cluster` with `wrap={false}` has no stacking
threshold at all, exactly reproducing today's always-side-by-side layout.
Output: `ReleasePreviewRow.tsx`/`.module.css` restructured; new `ReleasePreviewRow.test.tsx` proving
column alignment across all three mandated story variants plus the defensive zero-avatar case.
</objective>
