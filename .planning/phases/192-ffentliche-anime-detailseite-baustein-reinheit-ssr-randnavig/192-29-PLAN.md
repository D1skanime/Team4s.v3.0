<objective>
Extend three independent Grundbausteine (`Avatar`, `Button`, `ResponsiveImage`) with small,
genuinely reusable capabilities needed to close three of this round's guard-widening violations, per
`192-CONTEXT.md`'s `<addendum_2026-11-05b>`. None of these three components share files with each
other or with Plan 192-28 (Card) beyond `docs/FRONTEND_ARCHITEKTUR.md`; they are grouped into one
plan because each is individually too small to justify a dedicated plan (1-2 files of real logic
change each).

1. **`Avatar`**: a new `'xs'` (20px) size tier plus a `bordered` capability, shared by
   `FansubGroupPicker`'s 20px circular chip logo (currently a raw `<Image>` with local
   `width:20px;height:20px;border-radius:50%;object-fit:cover`) and `ReleasePreviewRow`'s already-Avatar-based
   `.logo` (which currently adds a local `border: 1px solid var(--border-on-media)` on top of Avatar) --
   the addendum explicitly asks for the SAME mechanism for both "round/framed small group/identity
   image" cases.
2. **`Button`**: `chipGlass` variant currently relies on a local, now-to-be-removed `.chip { gap:
   var(--space-1); }` override in `FansubGroupPicker.module.css` to get its 4px icon/label gap --
   Button's own default `--button-gap` (10px) does NOT match. This plan measures the discrepancy and
   fixes it at the `chipGlass` variant level, so switching the call site to `leftIcon` (Plan 192-33)
   is Zero-Pixel-Diff.
3. **`ResponsiveImage`**: a new rounding capability reproducing `AnimeEdgeNavigation.module.css`'s
   `.previewCover { border-radius: var(--radius-sm); }` without the composite file declaring
   `border-radius` itself.

Purpose: per `192-CONTEXT.md`'s `<addendum_2026-11-05b>`, items 4 and 6 ("Entscheidung — konkrete
Umsetzung").
Output: three independently reusable Grundbaustein capabilities, none wired into any composite file
yet (wiring happens in Plans 192-32/192-33).
</objective>

that specific instance today -- NOT the Button default. Measure this precisely (render both in a
disposable comparison or read the compiled CSS order/computed style) before deciding: if `chipGlass`

`grep -rn 'variant="chipGlass"' frontend/src`) would visually change, note it; if `chipGlass` is only
ever used by `FansubGroupPicker` today (confirm via the same grep), setting
`.buttonChipGlass { --button-gap: var(--space-1); }` is a safe, Zero-Pixel-Diff-preserving fix at the
Grundbaustein level with no other consumer affected. Add a German comment documenting why chipGlass
specifically needs a tighter gap than the 10px default (a small inline logo next to a short chip
label, not a padded primary action). Update `Button.stories.tsx` with a `chipGlass` + `leftIcon`
story state if one does not already exist (the existing chipGlass stories at lines ~66-67 currently
have no icon).

`ResponsiveImage.module.css`'s current contents, if any, before adding one):** Add a new,

raw token name (`'sm'` alone would be a size-name, not a purpose-name) -- consider wording like "a
