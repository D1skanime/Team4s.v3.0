Größenstufen") by converting `Card.padding` from a raw Space-scale literal (`'1'..'9'|'none'`) to a
named purpose enum (`'content' | 'nestedBlock' | 'dividedSection' | 'none'`), following the exact
`GAP_PURPOSE_TOKENS` pattern already established by `Stack`/`Cluster`/`SplitLayout`. This is a
breaking rename of an API already in production use at exactly 3 call sites (confirmed via repo-wide
grep) -- this plan updates those 3 call sites' padding VALUE only (a one-line string swap each, no
other change), so the build stays green at the end of this plan; the composite files' OWN further
Befund-Review1 work on those same files happens in later plans (192-24/192-25/192-26).

Also builds Extension D's second capability (Rand-bis-Rand / `bleedBelowMd`): a new boolean prop that
collapses Card's horizontal padding to zero and centers its grid children below a breakpoint, for
`AnimeDetailHero.module.css`'s `.posterMetaCard` case (wired in Plan 192-25, not here).

Purpose: per `192-CONTEXT.md`'s `<addendum_2026-11-05a>` section D -- "Card.padding wird... auf eine

**`bleedBelowMd` (Rand-bis-Rand-Modus, Extension D's second capability)** -- NOT wired into any call
site in this plan (Plan 192-25 wires it into `AnimeDetailHero.module.css`'s `.posterMetaCard`). Read
that file's CURRENT mobile override to confirm the exact values this must reproduce:
```
@media (max-width: 767px) {
  .posterMetaCard { margin-left: calc(-1 * var(--space-4)); margin-right: calc(-1 * var(--space-4)); justify-items: center; }
}
```
New boolean prop (exact name at this plan's discretion, propose `bleedBelowMd?: boolean`): when
`true`, below 767px, Card's own horizontal padding component collapses to 0 (vertical unchanged) AND
the Card's own CSS-grid `justify-items` switches from its implicit default (`stretch`, i.e. unset) to
`center` for direct grid children -- implement via the SAME override-hook mechanism as
`--card-padding-override`/`--card-radius-override` (a new, Card-owned CSS custom property set only
when the prop is `true`), with the actual `@media (max-width: 767px)` rule living in
`Card.module.css` itself, scoped to only activate when that hook is set. This REPLACES
`.posterMetaCard`'s local `margin-left`/`margin-right`/`justify-items` mobile override -- but do not
delete that CSS yet, it is still in active use until Plan 192-25 migrates the call site.

`gapPurposeNaming.guard.test.ts` currently guards against raw `gap="[1-9]"`/free
`firstColumnWidth` strings at 6 call-site files. Extend `forbiddenRawValuePatterns` with a pattern
matching Card's old raw padding literal (`padding="[1-9]"`) and extend the positive counter-example
string with the new purpose values, so a future regression back to a raw Card padding literal at any
of the already-guarded files is caught the same way.
