<objective>
Fix Live-UAT-Befund 19: today `AnimeEdgeNavigation` resolves its prev/next neighbors entirely
client-side, so the edge-navigation buttons are absent from the server-rendered HTML and only appear
after hydration + a client fetch. This plan extracts the existing neighbor-finding algorithm
(index/page-boundary logic) out of `AnimeEdgeNavigation.tsx` into a shared, server-safe function in
`lib/animeGridContext.ts`, calls it from `page.tsx`'s `AnimeDetailContent` Server Component, and
narrows `AnimeEdgeNavigation` to accept `previous`/`next` as props for the navigation links
themselves — while keeping its own client-side `getAnimeList` fetch ONLY for the hover-preview card.

Purpose: eliminates the one deliberate behavioral gap this phase targets outside Befund 21/20 —
the edge-nav buttons must exist in the server HTML, not appear after the fact.
Output: `resolveAnimeNeighbors()` in `lib/animeGridContext.ts`, reused by both the new server call
site and the narrowed client call site; a new SSR-oriented test in `page.test.tsx` proving the
`href`s are present without any mock fetch or hydration step.
</objective>
