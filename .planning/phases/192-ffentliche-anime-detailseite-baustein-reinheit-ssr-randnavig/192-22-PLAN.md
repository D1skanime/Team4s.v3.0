<objective>
Extend the `Cluster` Grundbaustein with the two Cluster-owned capabilities specified in
`192-CONTEXT.md`'s `<addendum_2026-11-05a>`:

- **Extension B (Haltepunkt-Umkehr):** a `collapseBelow`/`gapCollapsed` pair that reverses Cluster
  from a horizontal row to a stacked column below a configurable breakpoint, with its own gap purpose
  for the stacked state. Replaces two composite files' local `.titleRow`/`.row` breakpoint-reversal
  CSS (applied in Plans 192-24/192-26, not here).
- **Extension C (Schwebe-Overlay-Modus):** a `float` prop that makes Cluster `position:absolute`
  (floating band, no flex) above a breakpoint and a normal in-flow flex row below it, with
  `pointer-events:none` on the container and `pointer-events:auto` on each direct child baked into
  Cluster itself. Replaces `AnimeDetailHero.module.css`'s `.edgeNavigationOverlay` local CSS (applied
  in Plan 192-25, not here).

Both capabilities share the same container-query wrapper mechanism (copy the pattern already
established in `SplitLayout.module.css`), so they are built together in this one plan even though they
serve two different composite-file cases -- B and C both touch `Cluster.tsx`/`Cluster.module.css`
directly, and splitting them into two "parallel" plans would make the second one depend on the first
anyway (same files).

This is interface-first Grundbaustein work: neither capability is wired into any composite file yet.
No existing Cluster caller is touched.

Purpose: per the independent review's blocking finding (`compositeLayoutPurity.guard.test.ts`'s
undocumented-exception-list problem) -- Fall 3 (`AnimeDetailHero.module.css` `.titleRow`) and Fall 10
(`ReleasePreviewRow.module.css` `.row`) share one root cause (B); Fall 9
(`.edgeNavigationOverlay`) is a categorically different capability (C). Both get a real, reusable
Grundbaustein extension instead of remaining documented exceptions.
Output: `Cluster.tsx` supports `collapseBelow`/`gapCollapsed` and `float`; two new `layout.css`
tokens; Storybook/tests cover both; `docs/FRONTEND_ARCHITEKTUR.md` documents both.

must render: at/above 48rem/768px, a normal horizontal flex row (today's existing behavior, `gap`

if `gapCollapsed` is omitted). `48rem` is the SAME breakpoint `SplitLayout` already uses (confirmed:
`SplitLayout.module.css`'s `@container split-layout (min-width: 48rem)`) -- `collapseBelow`'s only
member is `'md'` for now (no second breakpoint value has a real call site; do not add one
speculatively).

**Extension C exact required behavior** (reproduces the CURRENT `.edgeNavigationOverlay` desktop/mobile
split, read `AnimeDetailHero.module.css` for the literal values being replaced): a `float` prop (name
is this plan's discretion, propose `float?: 'controlBand'` unless implementation reveals a better
name) that, when set: above 48rem/768px makes Cluster `position:absolute` with `top:
var(--overlay-offset-control-band)` and `height: var(--overlay-height-control-band)` (new tokens,
mapped unchanged to the CURRENT values `var(--space-3)` and `var(--control-height-md)` -- confirm
these are the exact values in `AnimeDetailHero.module.css`'s current `.edgeNavigationOverlay` rule
before hardcoding), `left:0; right:0;`, `pointer-events:none` on the Cluster root and
`pointer-events:auto` on each direct child (bake `& > *` into `Cluster.module.css` itself as a
legitimate part of this mode -- this REPLACES the current foreign-caller pattern in
`AnimeDetailHero.module.css`'s `.edgeNavigationOverlay > * { pointer-events: auto; }`, which Plan
192-25 will delete). Below 48rem/768px: a normal in-flow Cluster row using the caller's own
`gap`/`justify`/`align` (today's mobile override is `display:flex; justify-content:center; gap:
var(--space-4);` -- the caller passes `gap="contentPair"` and `justify="center"` to reproduce this;
the mobile-only `margin-top`/`padding` seen in the CURRENT `.edgeNavigationOverlay` mobile rule is
OUT OF SCOPE for Cluster itself -- that is external spacing relative to a sibling element, which Plan
192-25 will resolve with a Stack wrapper, not with Cluster).

**Shared two-level wrapper mechanism** (needed by BOTH B and C, since both require `@container`
awareness): when `collapseBelow` or `float` is set, render an outer `<Component>` carrying ONLY
`container: cluster / inline-size; min-width:0;` (a container cannot also be re-laid-out by its own
`@container` query -- same CSS-spec constraint `SplitLayout.module.css`'s top comment already
documents) and an inner `<div>` carrying the actual flex/positioning classes and the `--cluster-*`
custom properties. When NEITHER `collapseBelow` nor `float` is set, render exactly as today (single
element, no wrapper) -- this is the ONLY way to guarantee zero DOM/behavior change for every existing
caller (confirmed via `Cluster.test.tsx`'s `container.firstElementChild` assertions, which must keep
passing unmodified).
