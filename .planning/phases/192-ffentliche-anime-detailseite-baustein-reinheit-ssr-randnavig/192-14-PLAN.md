**ReleasePreviewRow** (`ReleasePreviewRow.tsx`/`.module.css`) — confirmed during planning:
`.row { display:flex; flex-direction:column; gap: var(--space-3); padding: var(--space-3); }`
sits on a `<div className={styles.row}>` directly inside `<Card variant="glassStrong">` (the
Card's ENTIRE content — one wrapper, no sibling). At `>=768px` it flips to
`flex-direction:row; justify-content:space-between; align-items:center;`. IMPORTANT finding from
planning: this responsive flip is NOT the same shape as `SplitLayout` (SplitLayout always makes its
SECOND column `minmax(0,1fr)`/flexible and its FIRST column fixed/auto — but here the FIRST
visual child (`.body`, group name + text) must be the flexible one and the SECOND (`.action`,
the button) must stay auto-width/right-aligned, the opposite ratio) — do not reach for `SplitLayout`
here without re-verifying this. `.action { display:flex; justify-content:flex-end; }` wraps a
SINGLE child (one button) — check whether this wrapper's flex is even doing anything visible once
`.row` itself is a flex container with `justify-content:space-between` (a direct flex item is
already pushed to the row's end without needing its own internal flex) before deciding how to
replace it.

**EpisodeGlassCard** (`EpisodeGlassCard.tsx`/`.module.css`) — confirmed during planning:
`.headerTitleRow { display:flex; align-items:center; justify-content:space-between; gap:
var(--space-3); width:100%; }` wraps two `<span>`s inside `DisclosureTrigger`'s `title` prop (NOT a
`<div>` — `Cluster`/`Stack` both accept an `as` prop, use `as="span"` to keep valid markup here).
`.headerText { min-width:0; display:flex; flex-direction:column; }` has NO explicit `gap` (relies on
browser default `gap:normal`≈`0` between its `display:block` children — using `Stack` here would
ADD an unwanted non-zero gap unless `Stack` is given an explicit zero-gap purpose value; simplest
compliant fix: since the children are already `display:block` spans, `.headerText` likely needs
only `display:block; min-width:0;` with NO flex/Stack at all — block children already stack
vertically with zero gap by default; verify this renders identically before committing to it).
`.versionList { border-top:...; padding: var(--space-3) var(--space-4) var(--space-4); display:grid;
gap: var(--space-3); }` — the padding is ASYMMETRIC (top/sides/bottom all differ), not expressible
by Card's new padding prop (which sets uniform padding) — treat this one as a documented,
non-generalizable exception (same pattern as 192-13's `.infoCardBody`) UNLESS a clean fix is found;
its `display:grid; gap: var(--space-3);` arranging the `ReleasePreviewRow` children CAN become
`Stack gap="<the ReleasePreviewRow-grouping purpose>"` (a single uniform gap, no padding concern).

**AnimeEdgeNavigation** (`AnimeEdgeNavigation.tsx`/`.module.css`) — confirmed during planning:
`<Card variant="glassStrong" className={\`${styles.previewCard} ...\`}>` — the className is on
CARD'S OWN ROOT, not a wrapper div. `.previewCard`'s `position/top/z-index/width` rules are

`ResponsiveImage` + the text `<div>` as Card's children.
