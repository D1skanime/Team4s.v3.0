Extend the `Stack` Grundbaustein with the "Rhythmus-Modus" (Extension A) specified in
`192-CONTEXT.md`'s `<addendum_2026-11-05a>`: `gap` accepts either a single `StackGapPurpose` (today's

`AnimeDetailHero`'s `.infoCardBody`) can express it entirely through Stack instead of its own local

into any composite file yet (that happens in Plans 192-24/192-26, which depend on this plan). No
existing Stack caller is touched.

Current `Stack.tsx` (read it in full before editing -- this is the exact current state, not a
summary):
```
export type StackGapPurpose = 'independentBlocks' | 'relatedContent'
const GAP_PURPOSE_TOKENS: Record<StackGapPurpose, string> = {
  independentBlocks: 'var(--space-independent-blocks)',
  relatedContent: 'var(--space-related-content)',
}
export interface StackProps extends HTMLAttributes<HTMLElement> {
  gap?: StackGapPurpose
  align?: 'start' | 'center' | 'end' | 'stretch'
  as?: ElementType
  className?: string
  children: ReactNode
}
export function Stack({ gap = 'independentBlocks', align = 'stretch', as: Component = 'div', className, children, style, ...props }: StackProps) {
  return (
    <Component {...props} style={{ ...style, '--stack-gap': GAP_PURPOSE_TOKENS[gap], '--stack-align': align }} className={classNames(styles.stack, className)}>
      {children}
    </Component>
  )
}
```
`Stack.module.css`'s `.stack` rule: `display:flex; flex-direction:column; gap:var(--stack-gap,
var(--space-3)); align-items:var(--stack-align, stretch); min-width:0;`. When `--stack-gap` is unset
(never happens today since the component always sets it), the fallback is `var(--space-3)` --
irrelevant for array mode since array mode will explicitly set `--stack-gap` to the literal `0`.

Array-gap mechanism (binding behavior from `192-CONTEXT.md`'s addendum, section A): when `gap` is an
array, `array.length` MUST equal `Children.count(children) - 1` (one purpose per GAP between
consecutive children, not one per child). Implementation approach (the addendum calls this "analog
zum bestehenden `--stack-gap`-Override-Hook-Muster"): set the Stack's own `--stack-gap` to the literal
`'0'` (so the native CSS `flex` `gap` contributes nothing), then render every child except the first
wrapped in a minimal spacer element carrying ONLY an inline `marginTop` set to
`GAP_PURPOSE_TOKENS[gapArray[childIndex - 1]]` -- no className, no other style, so it introduces zero
new surface/color/radius (consistent with Stack's own "no Fläche/Farbe/Rundung" rule). Single-value
`gap` (the overwhelming majority of today's callers) MUST take the exact same code path as today --
do not introduce a second rendering branch for the single-value case; only add a NEW branch for the
array case, gated by `Array.isArray(gap)`.

Fail fast (consistent with this project's "Env validation is defensive and mostly fail-fast"
convention) if `Array.isArray(gap) && gap.length !== Children.count(children) - 1` -- throw a German
error message naming the expected vs actual count, so a future composite file that edits
`.infoCardBody`'s children without updating the gap array fails loudly in development rather than
silently misaligning spacing.

New purpose + token: `'captionLines'` -> `var(--space-caption-lines)`, with
`--space-caption-lines: var(--space-1);` (4px) added to `frontend/src/styles/tokens/layout.css`,
directly below the existing `--space-related-content` entry, with the same inline-comment style
(German, names the owning Grundbaustein and the concrete use case: "Stack: zwei Textzeilen, die
gemeinsam eine einzige Bildunterschrift/Beschriftung bilden"). This purpose will be consumed later by
`AnimeEdgeNavigation.tsx`'s preview-card title/type pairing (Plan 192-26) -- do not wire it there in
this plan.

`docs/FRONTEND_ARCHITEKTUR.md`'s Stack/Cluster/SplitLayout paragraph (search for "sind drei
token-only Layout-Grundbausteine") needs one new sentence describing the array-gap rhythm capability
and the `'captionLines'` purpose, in the same descriptive style as the existing paragraph (no new
section, just extend the existing one).
