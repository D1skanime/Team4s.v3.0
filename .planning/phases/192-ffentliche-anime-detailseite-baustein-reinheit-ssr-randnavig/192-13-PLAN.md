Current `AnimeDetailHero.module.css` structure needing cleanup (read the full file — this is a
pointer, confirmed during planning, not a guarantee line numbers haven't shifted post-192-12):
- `.posterColumn { display:flex; flex-direction:column; position:relative; }` — the
  `display:flex;flex-direction:column` part is REDUNDANT with `Card variant="publicPoster"`'s own
  `.cardPublicPoster` rule (already `display:flex;flex-direction:column;gap:0;padding:0`) — this
  Card variant IS the flex container; `.posterColumn`'s own flex declaration does nothing but
  duplicate it. Keep only `position: relative;` here (needed for the badge/overlay positioning
  context) or remove the selector entirely if `position:relative` turns out not to be needed
  either — verify against the rendered DOM before deleting.
- `.posterMeta { padding: var(--space-4); flex: 1; }` — applied via className to a `<Stack
  gap="section" className={styles.posterMeta}>` sibling of `.posterWrapper` (the poster image)
  inside the SAME `Card variant="publicPoster"`. Since only the META portion (not the poster image)
  needs padding, Card's new `padding` prop cannot apply directly to the outer `publicPoster` Card
  (it would also pad the image, breaking the full-bleed poster look) — wrap the meta content (the
  `WatchlistAddButton` + `Divider` + genres `Stack`) in its OWN nested `Card` (a transparent variant
  that adds no visible border/background — `variant="nested"` is the closest existing candidate,
  confirmed transparent by reading `Card.module.css`'s `.cardNested` rule during planning) with
  `padding="4"`, so the padding genuinely comes from Card's mechanism, not local CSS. `flex: 1`
  (a flex-ITEM sizing hint, not a container declaration) may remain if the nested-Card restructure
  still needs it to preserve the image-vs-meta height ratio — verify visually.
- `.posterDivider`/`.divider` — both become `<Divider tone="..." spacing="..." />` (see Task 1).
- `.infoCardBody { display:flex; flex-direction:column; padding: var(--space-6); }` plus several
  children's individual `margin-bottom`/`margin` values (`.titleRow` margin-bottom 16,
  `.badges` margin-bottom 24, `.description`/`.tagsSection` margin 0 0 24, `.statsRow` border-top +
  padding-top 16, `.relatedSection` margin-top 24 + padding-top 16 + border-top) — this is a
  BESPOKE, non-uniform per-child spacing rhythm (explicitly flagged during planning, see Task 2),
  not a single repeatable gap value. The `padding: var(--space-6)` on the OUTER `.infoCardBody`
  wrapper is the generalizable part (route it through Card's new `padding` prop — this wrapper div
  sits directly inside `Card variant="publicHeroInfo"`, so the padding prop CAN apply to that outer
  Card directly, no nesting needed here, unlike `.posterMeta`). The individual children's
  `display:flex;flex-direction:column` plus their bespoke margins is the HARD case — see Task 2.
