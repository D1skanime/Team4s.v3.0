<objective>
Close Permission-Matrix row 1.2 (Weg 2, Gruppenmedien-Upload): remove the second,
parallel custom-permission-fallback rights layer in `UploadFansubMedia` (D-10) so group-media
upload is authorized by exactly one capability-registry check, matching Weg 1's (release-media
upload) single-layer shape — while leaving the structurally identical delete-side fallback
(`DeleteFansubMedia`) completely untouched, since D-10 explicitly keeps it.

Purpose: This collapses two parallel rights-check paths for the same action into one authoritative
check (D-02's binding frame: rights are data-driven via `action_definitions`/`role_capabilities`
only). The live-DB fact-check in `179-CONTEXT.md` confirms this fallback is already structurally
unreachable for upload (0 custom-permission records exist; every active role already has the
baseline `fansub_group_media.upload` capability) — removing it changes nothing for any real user
today, but a regression test proving that is still required per D-05.
Output: `fansub_media_upload.go`'s upload path is single-layer; a new real-Postgres regression
test proves the removed fallback no longer grants access even when seeded with `can_upload=true`.
</objective>
