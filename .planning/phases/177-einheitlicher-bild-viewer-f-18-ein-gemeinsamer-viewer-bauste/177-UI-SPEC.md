## Scope Reminder (binding, from 177-CONTEXT.md)

- **In scope (viewer surfaces):** `ReleaseGallery`/`FansubMediaLightbox` (public release gallery),
  `FansubGroupMediaBlock` (fansub group profile), `ScreenshotGallery` (episode page, repointed to
  `getGroupReleaseImages`), `ProjectMemberMediaViewer`'s consumer position inside
  `ProjectMemberMediaGallery`, `GroupAssetsExperience`'s **image lightbox only**.
- **Out of scope (do not touch):** Admin drawer #6 (`ReleaseVersionMediaSection` "Medium
  bearbeiten") and admin drawer #8 (`GroupMediaReviewDetailDrawer.tsx`) — D-17, confirmed
  permanently excluded, not even their display logic. `VideoPlayerModal` and all video playback —
  D-18/D-05, images and videos stay structurally separate; no mixed navigation order, no visual
  unification of the two modals in this phase. `ReleaseVersionMediaDetailPanel.tsx` is dead code,
  deleted outright (D-06), not part of the visual contract.
- **Hard rule (D-19):** media with non-public visibility/non-approved review status must never
  reach the viewer's props at all — this is a server-side/data-layer contract, not a UI
  affordance; the UI-SPEC below assumes the data it receives is already filtered. **Entschieden
  (D-20):** dieser harte Filter gilt nur für die 4 datenbankgestützten Flächen
  (`ReleaseGallery`/`FansubMediaLightbox`, `FansubGroupMediaBlock`, `ScreenshotGallery`,
  `ProjectMemberMediaViewer`). `GroupAssetsExperience` (Jellyfin-Ordner-Scan, kein
  `media_assets`-Bezug) bleibt zugriffsseitig unverändert — keine neue Zugriffskontrolle in dieser
  Phase.

## Pflicht-Constraint: Primitives und Tokens (bindend für Planner und Executor)

1. Ausschließlich globale Primitives aus `@/components/ui` (Referenz-Showcase `/dev/ui-system`,
   z. B. `Modal`, `Button`, `Badge`, `EmptyState`, `ErrorState`) und globale Design-Tokens
   (`--surface-*`, `--text-*`, `--accent-*`, `--shadow-*`, `--space-*`, `--border-*`, `--z-*`,
   `--control-height-*`) dürfen für den Viewer verwendet werden. Dieses Projekt nutzt kein shadcn
   (kein `components.json` gefunden) — das primäre Design-System ist das hausgebaute
   `frontend/src/components/ui/`-System; dessen Primitive-Pflicht gilt unverändert.
2. Fehlende Viewer-Bedienelemente werden **nicht** lokal im Viewer hand-gebaut, sondern als
   additive Erweiterung bestehender globaler Primitives spezifiziert (siehe Abschnitt
   „Primitive-Erweiterungen" unten) — in diesem Phasen-Scope reichen zwei additive Erweiterungen
   (`Modal`-Variante, `Button`-Variante) plus **ein** neuer globaler Token (`--surface-stage`); kein
   komplett neues Standalone-Primitive ist nötig.
3. Lokale Datei-Konsistenz mit den vier abzulösenden Viewer-Implementierungen
   (`ScreenshotGallery`, `ProjectMemberMediaViewer`, `GroupAssetsExperience`-Lightbox-Anteil)
   rechtfertigt **kein** Abweichen von diesem Vertrag — alle vier haben unabhängig voneinander
   `role="dialog"`-Backdrops, native `<img>`/`<button>` oder uneinheitliche
   Navigations-Grenzverhalten hand-gebaut; genau das wird in dieser Phase beseitigt (D-10, D-11).
4. Echte deutsche Umlaute (ä, ö, ü, Ä, Ö, Ü, ß) in jedem user-facing String des Viewers — siehe
   Copywriting-Vertrag unten für die konkreten Texte (D-12).

## Spacing Scale

Projekt-eigene Token-Skala (`frontend/src/styles/globals.css`), nicht die generische
Template-Skala — alle Werte Vielfache von 4:

| Token | Value | Usage im Viewer |
|-------|-------|-------|
| `--space-1` | 4px | Icon-Innenabstand in Badge/Counter |
| `--space-2` | 8px | Abstand zwischen Metadaten-Zeilen; Abstand Bild↔Metadaten-Block (kompakt, mobile) |
| `--space-4` | 16px | Standardabstand Metadaten-Panel-Innenpadding |
| `--space-5` | 24px | Innenpadding Stage (Desktop), Abstand Close-Button zum Panelrand |
| `--space-6` | 32px | **Swipe-Schwellenwert** (siehe Interaktionsvertrag) — bewusst ein deklarierter Spacing-Wert, kein Magic Number |
| `--space-7` | 48px | Große Layout-Lücken (z. B. Grid-Gap in den Galerie-Grids, unverändert) |

**Exceptions:**
- **Touch-Targets:** alle interaktiven Viewer-Controls (Close, Zoom-Toggle, Prev/Next) sind
  mindestens `--control-height-md` (44px) in Breite **und** Höhe — bereits bestehender Projekt-Token,
  keine neue Ausnahme, nur explizit für Mobile reaffirmiert.
- **Swipe-Schwellenwert:** 32px horizontaler Delta (`--space-6`) **und** horizontaler Delta >
  vertikaler Delta, bevor `onNavigate` ausgelöst wird (verhindert Konflikt mit vertikalem Scrollen
  auf Touch-Geräten).

## Color

**Primärer Fokuspunkt:** Das Bild auf der dunklen Bühne ist der visuelle Hauptanker des Viewers;
das Metadaten-Panel ist bewusst sekundär (hellere Fläche, kleinere Typografie-Rollen) und liegt
unterhalb der Bühne (siehe „Metadaten-Panel" unten).

Der Viewer führt **eine bewusste, lokal begrenzte Ausnahme** vom 60/30/10-Verhältnis ein: die
Bild-Bühne (`stage`) ist dunkel, exakt wie in Sketch 010 gefordert ("dunkle Bühne, kein weißer
Rand"). Diese Ausnahme gilt **ausschließlich** für die Bildfläche selbst, nicht für das
Metadaten-Panel oder die Modal-Hülle.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--surface-canvas)` `#f6f4ef` | Seitenhintergrund außerhalb des Viewers (Galerie-Grids, Seiten-Chrome) — unverändert |
| Secondary (30%) | `var(--surface-card)` `#ffffff` | Modal-Panel-Hülle (Card-Schatten, abgerundete Ecken — unverändert ggü. heutigem `Modal`), Metadaten-Panel-Hintergrund |
| Accent (10%) | `var(--accent-primary)` `#5f84dd` | **Ausschließlich**: Fokus-Ring auf allen interaktiven Viewer-Controls (bereits global via `:focus-visible`), Linkfarbe des „Release öffnen →"-CTA |
| Destructive | `var(--color-error)` `#dc3545` | nicht verwendet — keine destruktiven Aktionen in diesem Phasen-Scope (rein lesende Darstellung, D-19/177-CONTEXT.md „Risiko: Mittel ... rein lesende Darstellung ohne Datenmutation") |
| **Neu (scoped exception):** `--surface-stage` | `#10141c` (Wert aus Sketch 010 übernommen) | Ursprünglicher Flächenfarbe-Token — seit D-33 (Live-UAT Runde 2) nicht mehr für die Viewer-Chrome-Hintergründe verwendet, siehe `--surface-stage-veil` unten |
| **Neu (D-33, Live-UAT Runde 2):** `--surface-stage-veil` | halbtransparenter, warmer Dunkelton, aus `--text-strong` (`#171513`) abgeleitet (z. B. `color-mix(in srgb, var(--text-strong) 86%, transparent)`) | Ersetzt `--surface-stage` als Hintergrund der gesamten Viewer-Chrome (`Modal`s `modalPanelStage`, `MediaViewerStage`s `.stage`, `MediaViewerCaption`s `.caption`/`.panel`, `ThumbnailStrip`s `.strip`) — kombiniert mit `backdrop-filter: blur(var(--surface-stage-veil-blur))`, sodass die Team4s-Seite dahinter abgedunkelt/weichgezeichnet durchscheint. Das `<img>`-Element selbst bleibt unbeeinflusst (`backdrop-filter` wirkt nur auf das, was hinter dem Element liegt). Fallback ohne `backdrop-filter`-Unterstützung: nahezu deckende Opazität desselben Farbtons. |
| **Neu (D-33):** `--surface-stage-veil-blur` | z. B. `20px` | Blur-Radius für den Veil-Hintergrund, siehe oben |

Accent reserved for: Fokus-Ring (global, unverändert) + „Release öffnen →"-Link-Text/-Icon. Keine
weitere Verwendung (keine Akzentfarbe auf Kategorie-Badges — die nutzen den bestehenden
`Badge variant="info"`-Farbsatz, nicht Accent).

## Primitive-Erweiterungen (statt neuer Standalone-Komponenten)

Beide Erweiterungen sind **additiv** — bestehende Aufrufer (`ReleaseGallery`,
`FansubGroupMediaBlock`, jeder andere `Modal`/`Button`-Konsument im Projekt) kompilieren und
rendern unverändert, da jeweils ein neuer optionaler Enum-Wert ergänzt wird (D-07-kompatibel).

### 1. `Modal` — neuer Wert `variant?: 'default' | 'stage'` (Default bleibt `'default'`)

| Prop/Verhalten | `variant="default"` (unverändert) | `variant="stage"` (neu) |
|---|---|---|
| `dialogHeader` (Titelzeile + Beschreibung) | gerendert wie heute | **nicht gerendert** — `title` wird stattdessen über eine `.visually-hidden`-Span mit `id={titleID}` weiterhin für `aria-labelledby` bereitgestellt (Screenreader-Zugänglichkeit bleibt erhalten, visuell nichts sichtbar) |
| `dialogFooter` (Default-„Schließen"-Button oder `footer`-Prop) | gerendert wie heute | **nicht gerendert**, auch wenn `footer`-Prop übergeben würde — Stage-Variante ignoriert `footer` bewusst (nur ein Schließ-Weg, Sketch-Vorgabe „nur X schließt") |
| Close-Button-Position | inline in `dialogHeader` | **absolut positioniert**, oben rechts über dem gesamten Panel (`position: absolute; top: var(--space-5); right: var(--space-5)`), visuell identisch zum bestehenden `.closeButton`-Rezept (helle Kreisfläche, `var(--text-soft)`-Icon) — **kein neuer visueller Stil nötig**, nur Repositionierung |
| `.overlayClose` (unsichtbarer Vollflächen-Button, Klick auf Backdrop schließt) | gerendert wie heute | **nicht gerendert** — Backdrop-Klick schließt in Stage-Variante nicht (Sketch-Vorgabe „nur X schließt", sonst würde ein Klick neben das Bild versehentlich schließen) |
| `modalBody`-Padding/Gap | `padding: 18px 22px 20px; gap: 16px` | `padding: 0; gap: 0` — der Viewer kontrolliert sein eigenes Innenlayout (Stage + Metadaten-Panel) vollständig selbst |
| `modalPanel`-Hintergrund | helle Gradient-Fläche (unverändert) | **D-25 (Live-UAT Runde 1):** die gesamte `modalPanel`-Fläche nutzt `--surface-stage` und füllt den gesamten Viewport (Breite + Höhe) — kein heller Rahmen, kein Fenster-Look, kein großer Innenabstand. Ersetzt die ursprüngliche Zeile dieser Tabelle (die galt nur bis Live-UAT Runde 1); gilt weiterhin unverändert für `variant="default"`. |

### 2. `Button` — neuer Wert `variant?: ... | 'floating'`

Für den Zoom-Toggle auf der dunklen Bühne (bestehendes `variant="ghost"` hat zu wenig Kontrast auf
dunklem Grund, da es für helle Flächen entworfen ist). **Seit Live-UAT Runde 1 (D-26) gilt
`floating` nur noch für den Zoom-Toggle — die Navigationspfeile verwenden stattdessen `NavArrow`
(siehe Primitive 3 unten), nicht `Button variant="floating"`.**

| Property | Value |
|---|---|
| Visuelles Rezept | identisch zum bestehenden `.closeButton`-Stil: helle Kreisfläche (`color-mix(in srgb, var(--surface-card) 96%, transparent)`), `var(--text-soft)`-Icon, `box-shadow: inset 0 1px 0 rgba(255,255,255,.7)` — **kein neuer Farbwert**, nur ein neuer Variant-Name für ein bereits existierendes Aussehen |
| Größe | `iconOnly`, mindestens 44×44px (`--control-height-md`) |
| States | `default` (wie oben), `:hover` (leicht dunklere Variante, analog `.closeButton:hover` falls vorhanden, sonst `background: var(--surface-card)` voll opak), `:focus-visible` (Standard-Fokusring, global), `:disabled` (nicht genutzt im Viewer — Navigation ist immer Wrap-around, nie disabled) |
| Verwendung im Viewer | **nur noch** Zoom-Auslöser — **seit D-38 (Live-UAT Runde 2) in der oberen Leiste neben dem Schließen-X**, nicht mehr auf der Bühne selbst; Icon/aria-label wechseln zwischen `ZoomIn`/„Bild vergrößern" (eingepasst) und `ZoomOut`/„Zoom zurücksetzen" (jede gezoomte Stufe, D-37) |

## Viewer-Interaktionsvertrag — Desktop und Mobile

### Zoom (D-37, Live-UAT Runde 2 — ersetzt den ursprünglichen binären 100%-Toggle unten)

**Mehrstufiger Zyklus, jede Stufe relativ zur aktuell angezeigten (eingepassten) Größe:**

| Stufe | Darstellung | Auslöser (nächste Stufe) |
|---|---|---|
| eingepasst (Default) | Bild passt in Bühne (`object-fit: contain`), zentriert | — |
| 2× | doppelte Größe der eingepassten Darstellung | Klick auf Lupe-Button (D-38) oder Doppelklick auf das Bild |
| 4× | vierfache Größe der eingepassten Darstellung | erneuter Klick/Doppelklick |
| zurück zu eingepasst | wie Default | erneuter Klick/Doppelklick (Zyklus schließt sich) |

- **Pan (2×/4×):** Ziehen mit gedrückter Maus (Desktop) oder Ein-Finger-Ziehen (Touch) verschiebt
  den sichtbaren Ausschnitt; geclampt, sodass nie ein leerer Rand neben dem Bild sichtbar wird.
- **Pinch-Zoom (Touch):** kontinuierliches Zoomen innerhalb der Zyklus-Grenzen (Minimum
  eingepasst, Maximum 4×), unabhängig von den festen Klick-Stufen.
- **Mausrad im gezoomten Zustand:** zoomt um den aktuellen Mauszeiger-Punkt herum (der Punkt unter
  dem Cursor bleibt fixiert) — statt Bild-Navigation auszulösen (siehe Navigationstabelle unten).
- **Touch-Swipe im gezoomten Zustand:** pannt den Ausschnitt statt zu navigieren.
- **Bildwechsel** setzt Zoomstufe und Pan-Position bedingungslos zurück auf eingepasst/Null.
- Lupe-Button (D-38): jetzt in der oberen Leiste neben dem Schließen-X (nicht mehr auf der Bühne),
  `aria-label` „Bild vergrößern" (eingepasst) / „Zoom zurücksetzen" (jede gezoomte Stufe).
- Jede Entscheidungslogik hier (Zyklus, Pan-Clamp, Zoom-um-Cursorpunkt, Wheel-/Swipe-Weiche,
  Reset-Wert) ist als reine Funktion zu implementieren (D-13).

#### Ursprünglicher Zoom-Abschnitt (vor Live-UAT Runde 2, nur noch als Herkunftsreferenz)

### Navigation (Pfeile/Tastatur/Wischen/Mausrad — Wrap-around)

| Eingabe | Verhalten |

### Progressive Load (Display → Original)

1. Initiales `src` = `display_url ?? original_url ?? thumbnail_url` (angezeigt sofort, fit-to-stage).
2. Im Hintergrund wird `original_url` per `new Image()` vorgeladen (kein UI-Block).
3. Nach erfolgreichem Laden: nahtloser `src`-Swap auf `original_url`, kein Layout-Sprung
   (`object-fit: contain` verhindert Sprung bei abweichendem Seitenverhältnis).
4. Während des Ladens: dezenter Pill unten links auf der Bühne, Text „Originalbild wird geladen …“,
   blendet per Opacity-Transition aus, sobald der Swap abgeschlossen ist oder bei Fehler (stiller
   Fallback auf die bereits sichtbare Display-/Original-URL, **kein** `ErrorState` für diesen Fall —
   der Nutzer sieht ohnehin schon ein valides Bild).
5. Prefetch der Nachbarbilder (`index − 1`, `index + 1`) mit derselben `new Image().src = url`-Technik,
   verbatim aus `ProjectMemberMediaViewer` portiert (D-02), parametrisiert auf `original_url` statt
   `preview_url`.

### Metadaten-Anordnung (Live-UAT Runde 1+2, D-30/D-31/D-34/D-35 — ersetzt den ursprünglichen Abschnitt unten)

**Überschreibt D-21 teilweise.** Das Metadaten-Panel ist kein einzelner gestapelter Block mehr
unterhalb des Bildes, sondern zwei getrennte Bereiche auf der Vollbild-Bühne (D-25):

   „Heading" (20px/700) — nur gerendert, wenn vorhanden

3. Folge (`Label`-Typografie, Wert aus `episode_label`) — Teil derselben Zusatzzeile
4. Release-Version (`Label`-Typografie, Wert aus `release_version_label`) — Teil derselben
   Zusatzzeile

keine Platzhalter. Ist weder Titel noch Kategorie/Folge/Release-Version vorhanden, entfällt der
Kopfbereich komplett (z. B. `GroupAssetsExperience`, das laut Component Inventory nur Titel hat —
dort bleibt der Kopfbereich ggf. auf den Titel allein reduziert).

mehrzeiliger Fließtext ist schlechter lesbar als linksbündiger Text in einem zentrierten Block
(der Zeilenanfang bleibt an einer festen vertikalen Position, statt bei jeder Zeile zu wandern);
das ist Standard-Typografie-Praxis für Lesbarkeit bei begrenzter Zeilenlänge, keine willkürliche
Wahl.

5. Bildunterschrift (`Body`-Typografie, Wert aus `caption`) — nur gerendert, wenn vorhanden
   (Graceful Omission, D-22); ist kein `caption`-Wert vorhanden, entfällt der Caption-Bereich
   komplett.
6. „Release öffnen →"-CTA (nur `ProjectMemberMediaViewer`-Konsument, siehe Copywriting-Vertrag) —
   bleibt im Caption-Bereich, unterhalb der Bildunterschrift.

**Lange Bildunterschrift — Variante 1 (entschieden, D-31):** Die Bildunterschrift wird bis ca.
3–4 Zeilen vollständig angezeigt. Ist sie länger: die letzte sichtbare Zeile läuft weich aus

Mausrad **innerhalb** des offenen Panels scrollt den Text, löst **keine** Bild-Navigation aus.

Mobile: identische Kopf-/Caption-Aufteilung wie Desktop (keine Formfaktor-Verzweigung nötig außer
der bereits genannten größeren Panel-Höhe für „Weiterlesen").
