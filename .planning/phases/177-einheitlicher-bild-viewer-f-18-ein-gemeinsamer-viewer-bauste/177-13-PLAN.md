    - `clampZoomLevel(level)` bounds any value into `[1, 4]`. Tests: `clampZoomLevel(0.3)` -> `1`;

    - `cycleZoomLevel(current)` advances to the next step strictly greater than `current + 0.05`
      (a small tolerance so clicking right at/near a step advances PAST it, not back to it),
      wrapping to `ZOOM_STEPS[0]` once at or past the top. This lets a continuous pinch/wheel value
      between two fixed steps keep escalating toward the next one instead of snapping backwards.
      Tests: `cycleZoomLevel(1)` -> `2`; `cycleZoomLevel(2)` -> `4`; `cycleZoomLevel(4)` -> `1`;
      `cycleZoomLevel(2.7)` -> `4` (continues up); `cycleZoomLevel(3.97)` -> `1` (within tolerance
      of the max step, treated as already there, wraps).
    - `resetZoomLevel()` always returns `1` -- mirrors `resetCaptionPanelOpen()`'s pattern
      (`mediaViewerCaptionPanel.ts`), called by the viewer shell's item-change effect (Plan 177-14).

    - `computeContainedSize({ containerWidth, containerHeight, naturalWidth, naturalHeight })`
      reproduces the browser's own `object-fit: contain` box-fit math -- exactly one axis fills the
      container, the other scales down proportionally. Tests: container 1000x600, natural
      1200x800 (image aspect 1.5 < container aspect 1.667) -> height-constrained, `{ width: 900,
      height: 600 }`; container 1000x600, natural 2000x500 (image aspect 4 > container aspect
      1.667) -> width-constrained, `{ width: 1000, height: 250 }`.
    - `clampPanOffset({ containerWidth, containerHeight, contentWidth, contentHeight, offsetX,
      offsetY })` clamps a requested pan offset so the (centered-then-offset) content box always
      fully covers the container on both axes -- max travel per axis is half that axis's overflow;
      an axis with no overflow allows zero pan. Tests: `containerWidth: 1000, contentWidth: 800`
      (content smaller/equal, no overflow) with `offsetX: 500` requested -> `x: 0` (not 500);
      `containerWidth: 1000, contentWidth: 1600` (300px max travel each side) with `offsetX: 500`
      requested -> `x: 300` (the boundary value, NOT the requested 500); same setup with
      `offsetX: -500` -> `x: -300`; `offsetX: 150` (within bounds) -> `x: 150` (passthrough,
      unclamped). Mirror at least one case on the Y axis.
    - `computeZoomAroundPointOffset({ pointerOffsetFromCenter, previousOffset, previousLevel,
      nextLevel })` solves, per axis, for the new (pre-clamp) pan offset such that the content
      point currently under the pointer stays at the same screen position across the level change:
      `pointerOffsetFromCenter * (1 - nextLevel / previousLevel) + previousOffset * (nextLevel /
      previousLevel)`. Tests: `{ pointerOffsetFromCenter: 0, previousOffset: 0, previousLevel: 1,
      nextLevel: 2 }` -> `0` (zooming exactly at center never pans); `{ pointerOffsetFromCenter:
      100, previousOffset: 0, previousLevel: 1, nextLevel: 2 }` -> `-100`; `{
      pointerOffsetFromCenter: 100, previousOffset: -100, previousLevel: 2, nextLevel: 1 }` -> `0`
      (zooming back to fit always trends back toward centered); `{ pointerOffsetFromCenter: 50,
      previousOffset: 20, previousLevel: 2, nextLevel: 4 }` -> `-10`.
    - `computeWheelZoomLevel(currentLevel, deltaY, sensitivity)` returns
      `clampZoomLevel(currentLevel - deltaY * sensitivity)` -- `deltaY < 0` (scroll up) zooms in,
      `deltaY > 0` (scroll down) zooms out. Tests: `computeWheelZoomLevel(1, -100, 0.01)` -> `2`;
      `computeWheelZoomLevel(2, 100, 0.01)` -> `1`; `computeWheelZoomLevel(1, 100, 0.01)` -> `1`
      (clamped, can't go below fit); `computeWheelZoomLevel(4, -1000, 0.01)` -> `4` (clamped, can't
      exceed max).
    - `resolvePinchZoomLevel(startLevel, startDistance, currentDistance)` returns
      `clampZoomLevel(startLevel * (currentDistance / startDistance))`, anchored to the gesture's
      START distance/level (not the previous tick) so repeated recalculation across a long pinch
      never compounds rounding drift; returns `clampZoomLevel(startLevel)` if `startDistance <= 0`
      (defensive, avoids a divide-by-zero before two touches have both reported a position). Tests:
      `resolvePinchZoomLevel(1, 100, 200)` -> `2`; `resolvePinchZoomLevel(2, 100, 50)` -> `1`;
      `resolvePinchZoomLevel(1, 100, 1000)` -> `4` (clamped); `resolvePinchZoomLevel(2, 100, 10)` ->
      `1` (clamped); `resolvePinchZoomLevel(1, 0, 50)` -> `1` (defensive branch).
    - `distanceBetweenPoints(a, b)` / `midpointBetweenPoints(a, b)` operate on plain `{x,y}` points
      (not touch events) so the pinch gesture's span/anchor math is itself directly testable without
      any DOM/TouchEvent involvement. Tests: `distanceBetweenPoints({x:0,y:0},{x:3,y:4})` -> `5`;
      `midpointBetweenPoints({x:0,y:0},{x:10,y:20})` -> `{x:5,y:10}`.
